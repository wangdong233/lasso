# 01 方案 —— 架构与路线裁决

> 本文是整套管线的「为什么」。裁决数据来自 419 章实战（2026-08-19/20 全量交付），源文档：
> 本书实战期的架构裁决书已并入本目录（关键结论直接摘录于下），原始问题档案见 [档案/问题集/](档案/问题集/README.md)。

## 1. 三选一裁决：混合（引擎 = 确定性脚本，skill = 薄壳）

| 候选 | 形态 | 每章 token | 每章时延 | 确定性 |
|---|---|---|---|---|
| a) 确定性批量脚本 | 单进程 Node + lasso MCP（stdio）+ 直连 CDP print | **0** | **12-20s**（实测） | 100%（同一份 JS 片段逐章执行，QC 机械化） |
| b) Claude skill 驱动 agent | agent 读 skill → 逐章发工具调用 | ≥50k-150k input tokens/章 | 60-180s/章 | 低-中（指令遵循有漂移面） |
| c) **混合（裁决采用）** | 引擎=方案 a；skill=环境纪律+适配指南+QC 宪法的薄壳 | 本课程 0；新课一次性适配 | 15-20s/章 | 引擎侧 100%；适配侧受控 |

**裁决 c，否决纯 b 与纯 a 独占**：

- 否决纯 b：质量门禁与修复配方是**已验证代码**，让 agent 每章重新理解执行 = 把已编译的东西解释执行——更慢、更贵、更不可复现，且违反「文字绝对不可丢」红线的工程化要求（红线必须机械化，不能依赖指令遵循）。419 章 × agent 形态 ≈ 20-60M input tokens 线性爆炸。
- 否决纯 a 的独占性：换课程时变的只有三样——站点 URL、DOM 选择器组、宣传图指纹。把课程参数抽成 `config.mjs` 唯一入口 + 薄 skill 承载「适配流程 + QC 宪法 + 静默纪律」，跨课程复用成本最低。
- **边界**：skill 壳禁止重新实现引擎逻辑；引擎禁止内嵌 LLM 调用（保持零 token）。

## 4. 终局成书裁决：路线 b′（MD 正典 + 分片渲染 + 合并）

### 4.1 三条路线对照（三章白盒实测）

| 维度 | 路线 a（逐章 PDF 拼接） | 路线 b（MD 整本单渲染） | **路线 b′（分片渲染，裁决）** |
|---|---|---|---|
| 页数/体积 | 25 页 = 分章之和，无资源去重 | 14 页（版式密度收益） | 分片各渲 + pypdf 合并 |
| 章界 | 每章末页原样携带（实测 ≈0.78 页/章 浪费，419 章≈327 页≈全书 13%） | 章起新页/智能续排 | **连续流式**：章级零强制分页 |
| 导航 | 无 TOC 无页码 | 统一封面+目录+页码 | **统一 TOC（两遍回填）+ 页码盖章 + 两级书签** |
| 文字零丢失 | 继承分章门禁 | CJK 多重集 missing=0 | 同左（G1 全集对照，见 06） |
| 可重排版 | 否（版式冻结） | 是 | **是**（改一次 CSS 重渲该片） |
| 风险 | 合并零风险 | ~2400-2800 页一次 printToPDF，内存/布局稳定性超线性，**不押注** | **单次渲染钉死在 ~170 页/片；片失败只重渲该片** |

### 4.2 裁决原文语义

> **终局一个 PDF = 路线 b′（MD 正典 + 按模块分片渲染 + pypdf 合并 + TOC 页码两遍回填）。路线 a 降级为：① 全量过程中的单章预览（本来就在产）② 终局渲染故障时的成品保底 ③ 增量先读分发。**

四条依据：

1. 「一个 PDF」的刚需是**书性**——统一目录、全书页码、统一版式。路线 a 结构上给不了（拼接不改页内）；路线 b 由构造给出。
2. **正典已经是 MD**：每章 MD+images 落地，终局工步不新增存储格式，只加一个渲染器。
3. **红线可机械化移植**：CJK 零丢失门禁装进了合并渲染器，不因换渲染路径放松。
4. **风险有界**：分片把单次渲染规模钉死在 ~170 页；章级洞治理换成 CSS 原生约束 + 分片闭环复核。

### 4.3 连续流式版式（2026-08-20 改版）

章级零强制分页——上一章正文结束后**同页紧接**下一章章头；每片（模块）首页加模块题头块（通栏粗线+大标题），不整页分隔；封面/目录独立分页。G2 相应收紧为「除结构性边界（前言页/各模块末页/模块界首页的前一页——自动豁免集）外，任何页尾墨迹空白 ≥40% 失败」。

## 5. K=2 并发裁决（取代「全程单 producer」旧红线）

- **单进程多 tab 死刑**：lasso 会 `ensureOwnPageSelected` 把选中页拨回，多 tab 互踩。
- **K 进程各自上游实例可行**：每 worker 独立 lasso server + 独立 tab 归因（id-diff）。
- **两道栅栏**：
  1. **错峰 20s**：worker0 即起、worker1 错峰——并发建 tab 的 id-diff 归因不撞（否则可能互选对方 tab）。
  2. **存活栅栏**：任一 worker 先完工**不得先 transport.close**——lasso shutdown 的 TabSession.restore 会关掉他人工作 tab。由 run-k2.mjs 统一等待双方退出收尾。
- 分片语义：两 worker 按 manifest.idx 奇偶分片（`--only` 时 round-robin 均分）；跨进程熔断经 `BREAKER.trip` 文件协同。
- 实测收益 ≈2× 速度（419 章均值 14.8s/章 n=418）；红线仍守：单 Chrome、≤2 worker、0 个并发 merge 渲染（merge 与 produce 不并行）。

## 6. 状态与幂等（长跑的骨架）

- 台账 `.engine/state.json` 每章**原子写**（tmp+rename）：`done|failed|pending` + attempts + fatal + sha256 + QC 摘要。
- 断点续跑：done 跳过；failed attempts<3 自动重试；`--retry` 无视 3 次上限；`--force` 全部重跑（禁用）。
- 失败隔离：整章 try/catch，记 fatal 后继续下一章——单章失败不阻断批。
- **幂等的代价与守卫**：「跳过已存在」类优化必须对照计划校验内容完整性（P31/P32：陈旧分片被「已存在」信任 → 成书缺 105 章。render/assemble 双守卫 = 片 meta 章数必须 == 当轮 plan 章数，详见 06）。
