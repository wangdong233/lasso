### 1.5 课程参数化：config.mjs（换课只改这一个文件）

`config.mjs` 是 engine/merge/backfill-imgs/run-k2 四脚本的全部课程相关常量**唯一入口**，自带空值防呆断言（缺键在 selftest 阶段就炸，不在 produce 深处炸）：

| 键 | 含义 | 本书值（示例） |
|---|---|---|
| `COURSE_NAME` | 成书命名/书签前缀 | `薛兆丰的经济学课`（→ `薛兆丰的经济学课-全419讲.pdf`） |
| `COURSE_DIR` | 课程根绝对路径 | 本书课程根（换书 = 新目录的绝对路径） |
| `TARGET` | 课程主页 URL（侧栏枚举起点） | `https://www.dedao.cn/course/article?id=…` |
| `SIKAO` | 课后思考整段删除锚文本 | `课后思考` |
| `PROMO_MD5S` | 宣传图 md5 指纹集 | 经典版 + 视频课变体两枚 |
| `END_IMG_KEEP_MODULES` | 章末删图（压缩阶梯②）豁免模块——按模块 dirName/label **子串匹配**；开篇模块（发刊词等）的章末图属课程身份，保留 | 本书 `["课前必读"]`；新课按模块清单逐个裁决（07 步骤 3）。**无豁免模块也不能留空数组**——防呆断言对空数组即炸，填一个不匹配任何模块的占位串（如 `["（无）"]`） |
| `OUT_DIR` | 成书输出目录名 | `终局成书` |
| `VENV_PY` | pypdf venv python 绝对路径 | 本书为课程内 venv 的 `bin/python`（新书自建或复用） |
| `LASSO_ROOT` / `CDP_PORT` | 共享基础设施（跨课程恒定） | lasso 仓库绝对路径 / `9226` |

仍属**站点级**（换一门得到课通常不动；换站点必须白盒重定）：engine.mjs `JS_*` 片段的 DOM 选择器组与 dedao.cn URL 前缀过滤；backfill-imgs.mjs 的 `piccdn3.umiwi.com/img/YYYY/MM/NAME` CDN 反推模式；engine/merge 头部的共享件 import 路径。

## 2. 生产启动（正典 = K=2 并发；solo 为退化档）

### 2.1 K=2 全量（正典，约 2× 速度）

```bash
cd "<课程目录>/.engine"
nohup node run-k2.mjs >> logs/run-k2.nohup.log 2>&1 &
echo $! > logs/run-k2.pid
```

- 编排语义：启动**自动清理 `BREAKER.trip`**（上轮残留不阻断本轮）；worker0 即起、worker1 错峰 20s；两 worker 按 manifest.idx 奇偶分片，`[K0]/[K1]` 前缀 + 独立日志 `logs/*-w0/-w1`。
- **存活栅栏**：任一 worker 先完工不得先 transport.close——lasso shutdown 的 TabSession.restore 会关掉他人工作 tab；由 run-k2 统一等待双方退出。
- 指定章均分：`node run-k2.mjs --only "标题A,标题B"`；透传 `--retry`。

### 2.2 solo 退化档（小批补跑/排障）

```bash
nohup node engine.mjs produce >> logs/produce-full.nohup.log 2>&1 &   # 或 --retry 只重跑失败章
```

- solo **不读 `BREAKER.trip`**（跨进程跳闸只在 K2 语义下存在）；solo 下熔断为进程内三阈值。
- 引擎内建：`logs/<RUN_TS>-produce[-wK].log`（每章一行 QC 证据）+ nohup 合流双文件一致；单章看门狗 10 min；每 25 章整页复位（worker 档 15）；state.json 每章原子写。
- P28 三层防御内建：JS 对话框事件层自动 accept + 15s 盲发兜底 + renderer 楔死换 tab 自愈。
- **静默纪律**：引擎复用既有 tab，建 tab 一律 `Target.createTarget {background:true}`；每章后 chromeGuard PID 定向复隐。执行代理不得对 9226 做任何 bringToFront/activate/截图整窗操作。
- MCP 配额：transport 恒设 `LASSO_CALLER_CAP_DEFAULT=1000000`（P25：批量高频调用撞 anonymous 100/60s，192 章阵亡）；瞬态网络错调用级重试×3（2s/4s 退避）。

## 3. 运行中监控 + 批级熔断（每 15-20 min 一次）

```bash
cd "<课程目录>/.engine"
tail -5 "$(ls -t logs/*-produce*.log | head -1)"    # [OK]…| 进度 i/N…ETA（K2 兼看 -w0/-w1）
node engine.mjs status                             # done/failed 汇总 + 失败清单
osascript -e '…visible of (first process whose unix id is <PID>)'   # 应 false
```

### 3.1 熔断器三阈值（engine 内建）

| 阈值 | 动作 |
|---|---|
| 连续 FAIL ≥5 章 | PAUSED_BATCH_BREAKER 暂停（台账已逐章落盘，断点续跑） |
| 本批累计 FAIL >15 章 | ABORT_BATCH_BREAKER 中止 |
| 20 min 无任何 [OK] | ABORT_BATCH_BREAKER 中止 |

K2 下任一 worker 触发 → 写 `.engine/BREAKER.trip` → 所有 worker 章边界停机（run-k2 结束汇总会打印 trip 原因）。处置：`status` 看失败清单 → 记问题档案新 P 条目（附 fatal 串与 scratch 证据）→ 白盒修因后 `run-k2.mjs --retry`。`switch_failed`/`article-title 未出现` 密集 = 登录态/页面异常信号，同途处置。

### 3.2 5 分钟外部监控双保险（runner 点火必配）

熔断器是进程内自保；**外部 5 分钟级监控是第二道保险**——防「进程活着但空转」（70 分钟空跑事故教训，见 [档案/问题集/P25](档案/问题集/P25-全量首跑410失败三模式.md)）。监控最小动作：每 5 min `tail` 最新日志确认有新 `[OK]` 行 + `status` 计数在涨；连续两个周期无进展 → 人工介入。观察器自身是负载源：常驻监测间隔 ≥2s，取证完成即撤。

## 4. 完成判定与补图

1. `node engine.mjs status` → **done=<分母> failed=0**（以最新 log 末尾 `BATCH DONE` 为准）。
2. 若 failed>0：`produce --retry`（或 `run-k2.mjs --retry`）；个别章 3 次仍败 → **不盲目第 4 次**：记档案新 P 条目，人工白盒后再 `--only <该章>`。
3. 产物抽数：每章三件套 `<模块dir>/<title>.pdf + .md + images/`（标题含 `/` 落盘全角化）。
4. **补图收尾（必须在 merge plan 前跑）**：

```bash
node backfill-imgs.mjs
```

盘点 MD 引用但未落盘的图（下载失败远程保底章）→ 按 `piccdn3.umiwi.com/img/YYYY/MM/NAME` 反推补下载 → **手工把对应 MD 远程引用改写为本地** `images/…` → `merge.mjs plan` 复验图全在。为什么必须在 plan 前：engine 门禁⑤允许下载失败的图以远程 URL 保底进 MD（不静默丢图），但 `merge.mjs plan` 的完整性门禁对缺图**直接 FATAL 退出不产半本**——不补齐就到不了 render。

## 5. 终局合并（路线 b′；done=分母 且 plan 全绿后执行）

**脚本**：`merge.mjs`（分片渲染器）+ `merge-assemble.py`（pypdf 组装，venv 走 config `VENV_PY`）。**正典四步 + 抽查**：

```bash
cd "<课程目录>/.engine"

# ① 完整性门禁：全章 MD 齐 + 引用图片全在（缺任一 FATAL 退出，不产半本）
node merge.mjs plan

# ② 按模块分片渲染（每片 pass1→flow 决策→pass2→gapfill 闭环≤6轮；已存在且未陈旧的片自动跳过）
node merge.mjs render
#    单片失败重渲：node merge.mjs render --module 7 --force

# ③ 前言两遍 TOC 回填 + pypdf 合并 + 页码统一盖章(跳过封面) + 模块/章两级书签 + 六门禁 + 墨迹终扫
node merge.mjs assemble

# ④（独立复核，不重渲染）对成品重跑全部门禁
node merge.mjs qc
#    裁决留痕两旗（可选；前置=逐门归因到底，语义红线见 06-质量门禁.md §4.1）：
#    --waive-blanks（G2 空白类残留人工豁免）/ --adjudicate-inorder（inOrder 经 06 §3.4 定性伪影后放行）

# ⑤ 视觉抽查 PNG（页号按成品页数取：封面/目录/各模块首章/随机/末页）
node merge.mjs sample --pages 1,2,3,20,120,400,900,1300,1360
```

一键等价：`node merge.mjs all`（plan→render→assemble 连跑；建议分步，便于片级定位）。

> 墨迹终扫（pdftoppm 36dpi 全本灰度扫描）在 assemble/qc **常开**——2026-08-20 起 G2 新标准不再依赖历史 `--ink` 开关；若见旧文档写 `assemble --ink` / `qc --ink`，即现常开语义。

### 5.1 分片跳过的章数守卫（P31/P32 事故防御，已内建）

`render` 对已存在分片**不是无条件跳过**：

- **render 陈旧守卫**：片 meta 章数 ≠ 当轮 plan 章数（或 meta 缺失/损坏）→ 判陈旧，**强制重渲**（log「陈旧分片强制重渲（meta N 章 ≠ plan M 章——P31 守卫）」）。
- **assemble 二道守卫**：拼装前同样校验片 meta vs plan 章数，不等直接 throw 拒绝合并——render 可跳过，assemble 不许拼「旧片+新 plan」。
- **QC FAIL 交付隔离**：全量（非冒烟）成品六门禁 pass=false → 立即改名 `*-QC-FAIL.pdf` 隔离 + FATAL log，不得以正式名落盘被当成品取走。
- 背景事故：陈旧 5 章旧片被「已存在，跳过」信任 → 成书缺 105 章正文（[档案/问题集/P31](档案/问题集/P31-终局成品缺105节-陈旧分片放行与QC交付阻断.md)/[P32](档案/问题集/P32-陈旧分片被已存在跳过信任-成书缺105章.md)）。任何「跳过已存在」输出都要核对章数吻合才可信。

### 5.2 冒烟三件套（全量前机制验证，不落正式分片名）

- `--partial`（仅纳入 done 章）/ `--titles <file>`（钉死章集，同输入重渲对照）/ `--tag-suffix <s>`（分片产物后缀，防全量误判「已渲染」跳过）；`--out-name <name>` 定成品/report 基名。

### 5.3 版式与降级语义

- **连续流式（P29）**：章级零强制分页，同页紧接下一章章头；模块题头块不整页分隔；封面/目录独立分页；G2 收紧为「除结构性边界外任何页尾墨迹空白 ≥40% 失败」。
- **降级语义（P27 终局加固）**：三重全本扫描（gap 断言/洞报告/墨迹终扫）单项超时/异常**不弃报告**——如实记 `report.degradedScans[]`，对应门标注 degraded，pass 不因降级假阳。
- **超时按全本规模校准**：pdftoppm 对 307MiB/1360 页全本单次可 >9.5 min——sample 单页 timeout 570s、assemble 子进程 5700s 已按此设；新书页数/体量差异大时先校准再跑全本。
- **压缩阶梯**（全书 ≤300M 目标）与 `--keep-end-imgs` 对照开关见 [05-注意事项与教训.md](05-注意事项与教训.md) §7。
- **预计耗时**：分片渲染 ~15-40 min + 组装/QC ~8-20 min（pdftotext 全书一次 + pdftoppm 36dpi 墨迹终扫是大头）。
- **中断恢复**：render 按片幂等（重跑跳过未陈旧的已成片）；assemble 可整体重跑（`.work/` 中间件自动重建）；qc/sample 只读。

### 5.4 兜底（路线 a，仅 b′ 渲染故障时）

单章 PDF 已全在产，用 venv pypdf 按 manifest 顺序拼接（无统一 TOC/页码，保底成品）：

```bash
"<VENV_PY>" - <<'EOF'
import json, pathlib
from pypdf import PdfReader, PdfWriter
base = pathlib.Path('.')
flat = json.load(open('.engine/manifest.json'))['flat']
w = PdfWriter()
for f in flat:
    t = str(f['title']).replace('/', '／').replace('\\', '＼')   # safeName 同款
    w.append(PdfReader(str(base / f['dirName'] / (t + '.pdf'))))
with open('<OUT_DIR>/兜底-路线a.pdf', 'wb') as fh:
    w.write(fh)
EOF
```

## 6. 故障速查

| 症状 | 处置 |
|---|---|
| `curl 9226` 不通 | Chrome 死。按 lasso 流程以专用 profile 重启隐藏 Chrome，复隐，回 §1 重查后重启 producer（断点续跑不丢进度） |
| 9226 活但全部页级调用超时 | renderer 楔死（P28-②）：引擎 `ensurePagesResponsive` 自动换 tab 自愈；整 Chrome wedge（P9）→ 判死重启（profile 登录态无损） |
| `BREAKER.trip` 存在 | 上轮熔断残留。看内容（worker+原因）→ 修因 → `run-k2.mjs --retry`（启动自动清）；solo 不读此文件 |
| `switch_failed:notfound` 密集 | 虚拟列表病理（P7）：引擎自带整页重导航兜底；仍失败 → `--retry`；再失败 → 记 P 条目 |
| `qc_failed:+promo-present` | promo 指纹未入集。取证两路：① `scratch/<章>.*.json` 的 `promoMd5s[]`（引擎已对全部 1080×607 候选存**全量 md5** 与 match 标记，match:false 即缺的指纹）；② `node probe-figs.mjs "<章标题>"` 现场采样（nat=1080×607 即候选，全量 md5 `curl -s "<图完整URL>" \| md5`）。→ 入 config `PROMO_MD5S` → `--retry` 该章 |
| `assert_failed:title-mismatch` | 章名归一化问题（时长前缀等）：核 manifest 章名 vs 页面标题，记 P 条目 |
| `ssrf_blocked:dns_failed` 阵亡 | TUN 间歇 DNS：已内建调用级重试×3；仍批量阵亡 → 查网络代理/TUN 路由后 `--retry` |
| `ready-timeout(expectImgs=N)`（merge） | 该模块 images/ 有 404/缺失：核 `merge-plan.json.missingImgs` → `backfill-imgs.mjs` 补图（或重产该章）→ 该片 `render --module K --force` |
| MD 远程引用图 | `node backfill-imgs.mjs` 补下载 + MD 改写本地 → `plan` 复验 |
| pypdf `overlay pages != book` | `.work/page-numbers.pdf` 生成态过期：重跑 `assemble`（自动重建） |
| 章失败 `qc_failed:+sikao-residual` | 课后思考段界变化（P20 类）：看 scratch meta 的 sikao 审计块，记 P 条目后人工定段界 |
| QC 全本扫描超时 | 降级记 `degradedScans`（不弃报告）；重跑 `qc` 前先按全书页数/体量校准 pdftoppm 超时 |
| 磁盘紧张 | 单章 PDF ~0.7MiB×419 ≈ 300MiB + 成书 ~300-400MiB + 片件；确保卷余量 >2GB |
