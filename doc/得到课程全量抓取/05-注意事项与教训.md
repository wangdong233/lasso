# 05 注意事项与教训（P1-P32 精华，按主题归并）

> 源档案：[档案/问题集/](档案/问题集/README.md)（每条这里只有结论，细节回源档 P*.md 全文）。按「再开一本新书会不会再踩」的视角归并。

## §1 激活与焦点（最高优先——用户可感知被打断）

- **建 tab 一律 `Target.createTarget {background:true}`**。HTTP `/json/new` 是前台语义 = activate Chrome = 抢用户当前 app 焦点；可见性守卫只能事后压回，**焦点还不回去**（P27 定案）。全链激活源五处已清零，见 P27 终局表。
- `Page.bringToFront` 只许 opt-in 显式要求时用（上游 select_page 的 bringToFront 参数默认不传）。
- 「闪现」与「抢焦点」是两个信号：前者=可见性被掀（可守卫纠正），后者=真激活（只能源头消灭）。用户报「抢焦点」时直接去查激活原语，别再加固守卫。

## §2 静默执行体系（工具层职责，非工作流纪律）

- 隐藏 Chrome（PID 定向 osascript set visible=false）+ **desiredHidden 粘滞账**（`~/.cache/lasso/desired-hidden.json`；`lasso chrome-hide --pid N` 写账、`chrome-show` 清账）+ lasso server 内异步看门狗每 1.5s 复隐兜底——三层防线，但主防线是 §1 的零激活。
- **server 进程内禁 spawnSync 长阻塞**：同步 osascript 曾阻塞事件循环致引擎 5.7× 降速（osascript 在 Chrome 忙时 AX 枚举可 >2s）。一律 execFile 异步 + 4s kill。
- **PID 定向，永不按进程名**（E8 事故红线：按名 hide 会误伤用户日常 Chrome）。归属验证用 cmdline `--user-data-dir` 落在 `~/.cache/lasso/` 命名空间（地面真源，比台账强）。
- 登录流程：visible 窗口登录 → `chrome-hide` 转后台（登录态在 profile 持久，CDP 照常工作）。
- 自动化必须自感知自处理浏览器对话框：CDP `Page.javascriptDialogOpening` → `handleJavaScriptDialog accept` + 15s 兜底轮询（P28）。

## §3 规模与超时

- **固定超时要按全本规模校准**：pdftoppm 对 307MB/1360 页全本渲染 >9.5 分钟（内存压力下），原 9.5min 超时崩掉终局 QC——终扫类超时按 25min 起，且**扫描失败必须降级记 degraded 不丢报告**（merge qcFinal 现语义）。
- **Map.get 结果喂 CLI 前必须守卫**：`pdftotext -f undefined` 直接 usage error 崩整个流程（TOC 回填未命中的章）。
- K=2 双进程优于单进程多 tab：单进程多 tab 经 lasso 会被 ensureOwnPageSelected 拨回选中页（死刑）；K 进程各自上游实例可行，但须**存活栅栏**（先完工者不得先 transport.close——lasso shutdown 的 TabSession.restore 会关掉他人工作 tab）。
- `npm run build` 必须在仓库根目录跑；曾在错误 cwd 静默失败，dist 停留在旧版酿成同步看门狗事故（构建命令用 `&&` 链，不用 `;`）。

## §4 站点特性（得到系）

- **章节树是虚拟列表**：需滚动枚举（慢滚多 pass 合并 + 有序插入），一次抓只有 14/419（P7/P18）。
- **章内懒挂载 UI**：课后思考/辞典徽章/播放器 UI 等在 cleanup 时刻可能不存在——清扫必须**幂等 + 在每次捕获边界重扫**（JS_UI_SWEEP 范式，P26）。
- **排除项**：标题上方图、音频、首次发布及以下、尾部宣传图（md5 内容寻址集合，勿用文件名正则——会过拟合，P25）、课后思考整段。
- **视频课页五病**（模块 12 全灭过）：后台 timer 深度节流（400ms setTimeout 实际≥60s）→ 切换改**零 timer**（页内只做同步单语句，等待全在 Node 侧）；标题回退 document.title；时长前缀剥离（NORM_T）；「- 得到APP」后缀剥离；播放器实时时间码破不变量 → 删 video+UI。
- **文件名含半角 `/`**（如「（2/2）」）会 ENOENT——safeName 转全角 `／`，PDF/MD 落盘名与 merge 侧同款绑定（P26①）。
- pdftotext 的 x 流提取伪影：同页混排对齐（居中 vs 左对齐）会颠倒提取序——排版统一 `text-align:left` 是正字也是解法（P26-③q 第七单元串讲翻案）。
- 下载失败的图会留远程 URL 保底——合并前必须 backfill-imgs 补落本地（merge plan 门禁会 FATAL）。

## §5 质量红线

- **词级零丢失**：pdftotext 全文 vs 清理后 DOM innerText 词级 diff 为空——每章内建，不可妥协。
- 章节顺序完全复原：无编号章穿插真实位置（manifest flat[].idx 严格等于数组序）；重名章会撞台账状态键——去重并记录。
- QC 报「+order」失配先验视觉/DOM 谁是权威（印刷品=视觉序），再查提取器伪影，最后才动内容。

## §6 流程纪律

- 批量脚本内建熔断（连续 FAIL≥5 暂停 / 累计>15 中止 / 20min 无 OK 中止）+ 全局跳闸文件（K 进程共享）+ **外部 5 分钟监控**双保险——runner 点火必须双保险，防 70 分钟空跑复演（P25 教训）。
- 观察器/轮询类工具自身是负载源：300ms osascript 轮询 40 分钟把 System Events 打到 66% CPU——取证完成后即撤，常驻监测用 ≥2s 间隔。
- 任务变更记录到问题集（白盒三分类：产品缺陷→修 / 预期行为→结论 / 环境限制→结论），禁黑盒推测。
- **断点续跑类「跳过已存在」优化，跳过判据必须对照计划校验内容完整性**——文件存在≠有效（P31/P32：陈旧 5 章旧片被「已存在，跳过」信任 → 成书缺 105 章正文。现 render/assemble 双守卫=片 meta 章数必须==当轮 plan 章数；QC 的对照基准与被测物不能同源，wordBase 必须来自独立全集）。
- **门禁 FAIL 必须逐门归因到底才能交付**：P32 的 G3「no_start_page」105 条就是事故第一声警报，被当「回填未命中的记录问题」降级处理酿成交付事故——任何门的异常明细都不是小噪音，详见 [06-质量门禁.md](06-质量门禁.md)。

## §7 压缩阶梯（全书 ≤300M 目标；文字零丢失红线不参与压缩）

四档由轻到重，**只动图与 UI 噪音，文字块永不动**：

| 档 | 机制 | 开关/位置 |
|---|---|---|
| ① 章尾空余收敛 | 分页 gapfill：大空缺（≥35%）且次页顶有图 → 等比缩入（下限 200css）；缩不进 → 删图记日志；cosmetic（12-35%）只缩不删。链感知（标题 break-after:avoid 链头建模）+ 轮次上限 6 带严格递减守卫（P30） | 渲染内建（共享 gapfill.mjs） |
| ② 章末删图 end-img-drop | 章 blocks 末尾连续 img 块删除（遇首个非 img 块停——文字结尾章不动）；正典 MD 不改（仅渲染层剔除）；删除清单落 `end-imgs-dropped.json`，G4 期望值自动随降、账自洽 | **默认开启**；`--keep-end-imgs` 对照开关（对照实验用）；**豁免模块** `config.END_IMG_KEEP_MODULES`（dirName/label 子串匹配）——开篇模块（本书=课前必读）的章末图属课程身份保留（2026-08-20 用户更正；新课按模块清单裁决，无豁免也不能空数组——断言即炸，填占位串） |
| ③ 图像重压缩 img-opt.mjs | **影子目录**压缩：正典 images/ 与 MD 一字节不动，压缩只发生在渲染时拷入的影子副本；幂等缓存（同源 mtime+size+同参数→复用）。sips（macOS 自带，无 ImageMagick 依赖）maxDim 1400 / quality 78——打印内容宽 ~6.5in、200dpi 需 ~1300px，超出为屏显冗余；PNG 保格式只降采样，JPEG 系总尝试重编码、压不过原大自动弃用；任何失败原样直通（降级不阻断） | [脚本/合并/img-opt.mjs](脚本/合并/img-opt.mjs)；CLI 自检 `node img-opt.mjs <图> [maxDim] [quality]`；当前独立模块（含库接口 `prepareImgOpt`），尚未在 merge.mjs 接线 |
| ④ 欢迎留言/笔记区删除 | 站点 UI 噪音（`div.my-comment` / `div.message-v2` 留言区、笔记浮层）在 engine cleanup 层删除，不进任何产物（P26-③b：remount 同治，每次捕获边界重扫） | engine cleanup 内建 |

使用纪律：换书先跑 ①+②（内建零配置）；体积仍超目标再评估 ③ 接线（改一次 CSS/渲染参数可全书重渲——路线 b′ 的可重排版收益正在于此）；④ 是 cleanup 职责不是压缩手段，列在阶梯里只为提醒「减体积先减不该进书的东西」。对照实验用 `--keep-end-imgs` 跑一次同输入重渲（`--titles` 钉死章集），量化 ② 的体积与版式差异后再定去留。
