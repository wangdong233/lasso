# P27-定案（2026-08-20 01:2x）：用户报「闪跳 + 抢焦点」→ 真根源抓获并源头消灭

## 一、抢焦点 ≠ 闪现（关键分辨）

用户在 merge 运行期感到「浏览器闪跳一下 + **抢夺焦点**」。抢焦点 = 有操作 **activate** 了 Chrome（activation 偷走用户当前 app 的键盘焦点）；复隐守卫只能压回可见性，**焦点还不回去**——这就是「缓解 ≠ 根治」的机理。

## 二、真根源（观察器同秒对齐 + 原语语义白盒）

**merge.mjs `openTabWs` 的 HTTP `/json/new` 端点**——前台语义（等价无 background 的 `Target.createTarget`）：每次片渲染/前言渲染开 tab 都 activate Chrome。merge `all` 期间高频触发 = 用户实感的闪跳+抢焦点。engine 侧 `swapStuckTab`（前案）与之同族。

## 三、源头消灭（不是缓解）

| 文件 | 修法 | 验证 |
|---|---|---|
| merge.mjs openTabWs | `/json/new` → 浏览器级 WS `Target.createTarget {url,background:true}` + /json/list 解析 page WS（保留 4 次重试+失败清理） | /tmp/bg-tab-test.mjs：建 tab 前后 **frontmost app 不变 + Chrome visible 不变**（✅ 零激活实证） |
| engine.mjs:490 零 tab 兜底 | 同款补 `background:true`（上游 pages[0] 自动选中不受影响——那是记账不是激活） | 静态 |

**原则定案：建 tab 一律 background:true（Chrome 从不激活 → 无闪、无抢焦点、无需任何事后纠正）。** 粘滞看门狗/章尾 guard 降级为纯 belt（防御未知未来源）。
