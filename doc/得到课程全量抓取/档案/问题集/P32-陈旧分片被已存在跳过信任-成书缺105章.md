# P32：陈旧分片被「已存在跳过」信任——成书缺 105 章正文（严重事故）

## 现象与发现链（2026-08-20 09:3x，终局 QC 报告落盘后验尸）

1. assemble#3 终局 QC：`G3 TOC 314/419`，105 章 `no_start_page`；印刷 TOC 同 105 章页码为「—」
2. 全书正文标记 `MARKCH` 计数 = **314**（应 419）——105 章正文未进书，非 TOC 伪影
3. shard metas 合计 chapters=314：**shard02（模块 01 东西不够，应 110 章）只有 5 章/19 页**——其余 13 片章数与 plan 完全一致
4. `merge all`（00:20:18）日志：`[shard02] 已存在，跳过（--force 重渲）`——该片是早期（模块 01 仅 5 章 done 时）渲染的陈旧产物，**跳过前未校验 meta.chapters 数量 vs plan 分片章数**

## 根因（白盒）

`merge.mjs render` 的跳过判据只看「片 PDF 文件存在」，把「存在」等同于「有效」——对**分片产物在 plan 变化（全书逐步完成）期间留下的中间态**零防御。这违反机械可核原则：产物有效性必须对照 plan 校验，不能信任文件名。

## 影响

- 已交付的 `薛兆丰的经济学课-全419讲.pdf`（1360 页）实含 314 章正文 + 419 条 TOC（105 条页码「—」）
- **G1 词级零丢失为何没拦住**：wordBase 与书同源（都来自 metas 圈定的章集）——盲区。跨集校验（wordBase 必须= plan 全集）缺位
- 用户已目检验收（外观质量结论仍有效），但完整性结论须重下

## 修复（双管）

1. **补正当前书**（工作流实施段完成后执行，避免 merge/gapfill 编辑冲突）：
   `node merge.mjs render --module 2 --force` → `node merge.mjs assemble --ink` → 复核 MARKCH=419 / G3 419/419 / 页数~1700
2. **根治跳过判据**：render 的已存在跳过必须加双校验——`meta.pdf 存在 && meta.chapters.length === plan 对应分片章数 && meta 版式标记 == 当前版式(flow)`，任一不符即重渲。同型防御：qcFinal 的 wordBase 改为**全集构建**（plan.included 全量），缺章直接 G1 爆 missing——本事故本可在 QC 层拦下（G1 盲区修复）

## 教训（入 05-注意事项）

- 断点续跑类「跳过已存在」优化，跳过判据必须**对照计划校验内容完整性**，文件存在≠有效
- QC 的对照基准与被测物不能同源（同源=盲区）；零丢失校验的 wordBase 必须来自独立全集（plan）
- 终局 QC 的 G3「no_start_page」不是小噪音——它就是这次事故的第一声警报，被当作「回填未命中的记录问题」降级处理了。**门禁 FAIL 必须逐门归因到底才能交付**
