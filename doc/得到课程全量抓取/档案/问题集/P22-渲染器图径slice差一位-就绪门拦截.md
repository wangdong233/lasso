# P22 — 路线 b 渲染器 MD 图径 slice 差一位（images→mages 全 404，被就绪门拦截）

- 日期：2026-08-19（架构师轮，合并演示）
- 组件：`合并演示/render-merge-b.mjs` `parseMd` 图块分支

## 现象

整本渲染就绪门超时：页面加载成功（bodyLen 7644）但 11 张图全部 `bad`，失败 src 一律是 `…/mages/2017…jpg` —— `images` 的首字母 `i` 被吃掉。

## 根因

图块解析 `joined.trim().slice(5, -2)`：`![](` 是 **4** 个前缀字符、`)` 是 1 个后缀字符，正确应为 `slice(4, -1)`。首版按 5/-2 切，恰好吃掉路径首字符。（对照：行内图走正则 `!\[\]\(([^)]+)\)` 无此问题——同一数据两种解析路径，手写索引的那个错了。）

## 修复与教训

- 修复：`slice(4, -1)`（已落地）；就绪门 dump 让 404 一眼可见（`…/mages/…` 直接指认切错位）。
- **门禁前置的价值实证**：就绪门（期望图数 + bad==0）把「静默丢全部图」拦在出厂前——若只有页数/文字检查，11 图全丢仍会过（文字零丢失不覆盖图）。合并工步的图完整性门 = 期望图数（MD 计数）vs `pdfimages -list` 计数，已进 merge-b-report.json 证据链。
- 工程规则：字符串下标切取一律用括号正则或带断言的切法；两处同义解析必须共用一个实现（本例 figure 块与行内图不同源即裂缝）。
