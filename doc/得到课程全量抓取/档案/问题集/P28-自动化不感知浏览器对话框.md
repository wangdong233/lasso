# P28：脚本触发的浏览器对话框未被自动化感知与处理（用户指正）

## 现象
脚本导航/刷新触发 Chrome「离开此页面？」beforeunload 确认弹窗——页面被卡住等人工点选。用户指出：**操作是我们发起的，弹窗就该由我们主动选择**（接受离开），不应留给用户。

## 判断：自动化完整性缺口（引擎+产品双层）
自动化闭环 = 发起操作 → 处理该操作的一切后果（含对话框）。留弹窗给用户 = 静默性破功 + 效率破功。

## 修复
①引擎/调用层接 CDP `Page.javascriptDialogOpening` → 自动 `handleJavaScriptDialog({accept:true})`（导航意图自明）+ 日志 dialog_auto_accepted；②停滞 >15s 看门狗探测挂起对话框；③产品层（v1.18.3）：browse 通道内建对话框自动处理（默认接受+如实记录）。
