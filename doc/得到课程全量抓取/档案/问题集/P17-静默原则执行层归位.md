# P17：静默原则的执行层错误——应是工具机制，不是工作流纪律

## 用户指正（2026-08-19）
「浏览器尽量静默后台执行这是当前项目的特性吧，这应该是工具要处理的，不是工作流要处理的吧？」

## 判断：架构归层错误（成立）
P16 的修复（给工作流 COMMON 注入静默纪律）把机制责任放在了错误的层——prompt 纪律对每个未来工作流/用户都要求记忆，必然再犯（doc/23 方法论「制度 vs 自觉」同型教训）。静默必须是 Lasso 的**机制属性**。

## 产品层两个真缺口与修法
1. **隐藏态不粘滞**：chrome-hide 无 desiredHidden 记号，无自愈。修法：台账加 desiredHidden；server 守护（复用 reaper tick）巡检可见即 PID 定向复隐。
2. **dogfood 旁路**：pdf 走不通（P10 上游无工具）迫使 agent 裸 CDP 绕道 → 静默保证失效。修法：pdf action 改走自有 CdpClient（Page.printToPDF），打印收回产品内。

## 处置
两项修复排 round-2 工作流完成后实施（避免运行中 dist 切换）；工作流纪律降级为纵深防御。
