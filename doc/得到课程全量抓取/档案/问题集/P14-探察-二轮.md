## 3. 分页策略候选设计（任务③，先设计后实施——S-A 配方已实验验证）

### S-A（推荐主策略）：DOM 预处理——删宣传图 + 逐图缩放进剩余空间（scout8 JS_FIX 已实现并实测）

- 做法：cleanup 后重测 pagemap（每 figure 的 top→页号/剩余空间 rem）；`h>rem 且 h≤0.85×PAGE` → `img.style.max-height=(rem-14)px; width:auto`；`h>0.85×PAGE`（课程表类）→ 不动（Chrome 自动切片，无害）。
- **实测**：第003讲 6→5 页，中部空洞 0，两图 345→203/345→316 落位成功（pdfimages ppi 152→252/161 证实实际缩小）；发刊词 promo 删除后 14 页、p14 尾空 41%（自然尾）。
- 风险与实证：**屏幕测量≠打印落位**——fk p2 洞在 S-A 首过未除（屏幕 700px 宽度布局下 fig2 显示「放得下」，打印 717px 内容宽重排后被推）。→ 需 S-A' 闭环补齐（见下）。

### S-A'（S-A 补强，推荐合入）：打印产物反馈闭环（快测已验证）

- 闭环：print#1 → `pdfimages -list`（0.1s 级）得每图**实际**落页；与 pagemap 预测页比对，`实际>预测` 即被推图 → 用 `pdftotext -bbox`（实测 0.07s/页）取该页词框 max yMax 量出洞高 → 换算 css px（×96/72）→ 对被推图设 max-height=洞高-安全量 → print#2 复验。迭代≤2 次（上游缩图会使下游重排）。
- 验证精度：bbox 洞高 234.4pt vs 光栅墨迹 244.1pt（线框底 vs 字形墨底，差 4%），安全量 14px 足够覆盖。
- 全程无光栅化（pdftoppm 对含课程表的 PDF 要 2 分钟/份，禁入主管线；墨迹分析只留作出厂抽检）。

### S-B（否决为主策略）：CSS 注入（img max-height 全局上限 / break-inside / orphans-widows）

- `figure{break-inside:avoid}` = 现状（整块推页）不解决问题；全局 max-height 不知每页剩余量；orphans/widows 只管文本行。仅可作 `p{orphans:3;widows:3}` 卫生项附带。
- 打印宽度钉扎（把 .editor-show 宽度设为 716.93px 使屏幕布局=打印布局）可作为 S-A 的首过精度增强，降低闭环迭代次数，但不替代闭环（print media 仍有差异面）。

### S-C（否决）：打印参数（scale/margins）——见 §2.3，scale 实测恶化，margins 无差别修复力。

### S-D（兜底，最后手段）：丢图——仅当闭环 2 次后仍放不下且图非内容性（装饰图）；课程表类内容图**不丢**（用户红线只禁丢文字，但课程表是实质内容，空洞 7.4% 可接受）。

### 文字零丢失验证法（定案并已 4/4 验证通过）

`pdftotext(PDF)` vs **cleanup 态** `article-body-wrap.innerText`（打印前同 DOM 态快照）做归一化（去空白/软连字符）多重集+保序双 diff，**missing 必须为空**。实测：fk base/fix、l003 base/fix 四对全过（missing=[]，inOrder=true）；fk PDF 侧多出的字符为 CSS 列表序号（1.~10.）等 innerText 天然不含的标记，良性。**教训**：r2 轮 dom-inner 取的是未清理页（混入 header/侧栏「得到App 充值 已购57%」文本）导致假阳性——快照必须取 cleanup 后、打印前的同态；S-A 修图前后 innerText 逐字节相同（fixSameAsBase=true ×2）证明图操作零文字影响。

## 4. 全量方案预研（任务④）

### 4.1 单章耗时构成（实测）

- 首次 navigate+ready：~21s（每批一次）。
- 每章：switch 1-2s + stabilize(懒加载全滚) 6-9s + pagemap/promo dump 1.5s + cleanup 1s + print ~1.3s/次 ≈ **12-16s**（b3 全量版 6-18s/章同量级；scout8 含 2-3 次打印为 18-21s）。闭环版每章 +1~2 次 print（+2.5s）+本地快测（+0.5s）→ **~15-20s/章**。
- 113 章 × 15-20s ≈ **28-38 分钟**（单 tab 串行）+ 批首 20s。

### 4.2 并行可行性裁决

- **单 Chrome 多 tab（推荐，≤2-3 tab）**：每 tab 独立 renderer + 独立 SPA 实例，直连 CDP 可按 tab webSocketDebuggerUrl 并行 print；登录态共享（同一 profile）。收益 ~1.5-2×（stabilize 滚动与 print 流水化）→ ~18-25 分钟。风险：内存（课程表 943KB×14 页渲染的重 tab）、dedao 切章 API 频率（每章 1-2 请求，3 并发无压力）；**多 tab 会放大 P16 可见性面**——见 §5。
- **多 Chrome 实例（否决）**：profile 复制需冷拷贝（Chrome 运行中锁定），登录 cookie 可迁但复杂度+可见窗口管理面倍增，收益不抵。P2/P13 已有先例约束。
- **裁决**：生产脚本单 Chrome 2-tab 流水（或先 1-tab 串行求稳，113 章半小时量级完全可接受）。**skill 化**（`.claudy/skills` 或 lasso doc/ 工作流）：封装「章节清单→断点续跑（逐章幂等落盘+失败章记录）→每章三层质检（词级零丢失+bbox 落页断言+末页无 promo）→问题集自动记条」，比盲目并行更值——失败重跑成本 O(1 章)。

### 4.3 重产前 3 子章节（用户本轮直接要求）的实施配方

batch3 管线 + 三处增量：①JS_CLEANUP 后加 JS_FIX（M2∧M3∧M4 删 promo + 逐图缩放）；②print#1 后跑 pdfimages/bbox 闭环（≤2 迭代）；③终检三断言（零丢失 diff 为空 / pdfimages 无 1080×607 / 中部洞≤1 处且≤8%）。预期：发刊词 14 页 p2 洞消除、001/002/003 类似 l003 全清。

### 7.2 探察结论的修正与新增（实测否决/证实）

1. **新增否决**：`break-inside:auto`（+legacy `page-break-inside:auto`）对超页高图**无效**——Chrome 仍锁定页边界起切片（fk p4 62.4% 分毫不动）。探察期未测此路径。
