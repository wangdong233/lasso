# P13 — lasso Chrome 台账出现陈旧条目（port 9222 / pid 42 / profile=/tmp/x），非本管线产物

- 时间：2026-08-19 14:06（首批抽取收尾状态核查时发现）

## 现象

`~/.cache/lasso/launched-chromes.json` 在本批执行窗口内从 `[]`（探察报告 §4.7 交接态）变出一条：

```json
{ "port": 9222, "pid": 42, "profileDir": "/tmp/x", "launchedAt": 1787119256407, "status": "ready", "launchMode": "visible" }
```

时间戳 = 2026-08-19 14:00:56（本批 PDF 已落盘之后）。本管线脚本从未调用 launch-chrome；专用 Chrome 是 9226 / pid 85359 / dedao-profile，与该条目无关。

## 复现 / 来源

本 agent 未复现创建动作。特征（port 9222、pid 42、`/tmp/x`）与 lasso 测试夹具风格一致，疑似并行会话（用户或其他 agent）跑了测试/工具写入真实台账路径。**禁止黑盒推测归属**——记录为「来源未定的环境观察」。

## 白盒证据

- `ps -p 42`：进程不存在（只剩表头）。
- 本批 3 次 server 进程退出（batch2/batch3×2 + diag）后专用 Chrome pid 85359 始终存活（`curl :9226/json/version` 通）——与 `chrome-stop` 的 ps 归属验证（探察 P3 记录的「探活→ps 归属验证→SIGTERM→树杀→删账」）一致：僵尸条目不会被误杀成真进程，也不会牵连 9226。

## 判断

**环境限制 → 结论**：条目 pid 已死，后续 server 停机收尾会因归属验证跳过它，无实害；但它说明台账路径被并行会话共享写入。下一批执行者注意：不要因台账非空就以为 9226 Chrome 归属谁——以 `curl :9226/json/version` + `pgrep -f dedao-profile` 实测为准（本批交接口径不变：Chrome 85359 存活、可直接 `LASSO_CDP_PORT=9226` 使用）。
