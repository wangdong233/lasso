# 渲染档并行验收隔离配方(同机多 agent)

> 2026-09-02 实证问题:同机多 agent 并行真机验收时,各自跑的「清场」命令互杀对方在用的
> 渲染档 Chrome(9224 实例)。本文是该场景的**支持用法配方**——三个 env 组成命名空间,
> 配齐后并行 agent 互相不可见、互不误杀。
>
> 适用场景:同机并行真机验收 / 并行 CI 分片。**生产 attach(多消费方只读共享单实例)
> 不需要本文**——attach 路径只做幂等 ensure + touch 续命 + disconnect 非 close,从不
> 触发任何清场命令,天然免疫互杀(见 doc/对接实施说明-渲染档x-media-gen-mcp.md)。

## 0. 排程纪律与归属判定(先判车道,再选配方)

> 2026-09-02 F 并入。回答编排层两问:**「同机多 agent 并行真机验收互杀 9224」归谁
> 解决;该场景下验收怎么排程。**

**归属判定结论:不是 lasso 默认路径需要修的缺陷;归属 = 工作流排程纪律 + 既有隔离
原语的正确使用。**依据:

1. 生产形态(attach 只读共享默认口)天然免疫——attach 只做幂等 ensure + touch 续命
   + disconnect 非 close,从不触发任何清场命令(见本文档头);
2. 互杀入口(§1)全部是「有意全局」的维护逃生口(设计决议 3.5/3.7),单用户维护窗
   语义正确;原唯一真正的 lasso 侧设计债(`--stop` 不认 port env 的不对称)已于
   2026-09-02 裁决并落地(doc/提案-render-stop端口作用域化.md §6:显式合法=只收该
   port / 未设=全收 / 非法=exit 1);
3. 隔离原语已齐(本文 §2 三 env + §3 `chrome-stop --port N --modes render` 精准
   收口)——缺的是排程层「知道该走哪条车道」,这正是编排器/对接文档的职责,不是
   lasso 代码的职责。

**排程车道表**(验收执行者先判车道;车道 A 在「全局默认口域」内互斥,B/C 不受限):

| 车道 | 适用 | 排程规则 |
|---|---|---|
| **A 默认口验收**(串行独占) | lasso 自家 `test/render-tier-acceptance.mjs`(9224 硬编码=验收语义,§3 例外条款)及一切**未设 env** 的真机验收 | 同机同一时刻至多 1 个——编排器加互斥锁/独占窗口;其 step0 清场作用于全局台账,**开启前须确认默认口空闲**(无 env `--status` running=false,或等 idle reaper ≤10min 自退),不得撞正在使用的 C |
| **B 并行隔离验收** | 同机 ≥2 个 agent 各自真机验收 | 每 agent 配齐 §2 三 env(编排器派发互异端口 + 独立分账/执守目录);遵守 §3 清场纪律;命名空间互不可见,**与 A/C 可共存** |
| **C 生产/门禁 attach**(默认口) | media-gen 生产渲染与其 npm 门禁(默认口 attach,只读共享,靠 idle reaper 自退) | 自身无排程约束,与谁都可共存;唯一脆弱点是被 A 的全局清场误杀——由 A 的窗口纪律保护,不靠 C 自己设防 |

**互杀事故止血**:被误杀实例无持久损伤——渲染实例无状态,下一次 attach/ensure 幂等
重拉;进行中的那批渲染作废重跑即可。编排器检测到 A 撞上在用的 C 应记**排程违规**
(修 A 的窗口),而不是让 agent 用重试清场来"恢复"——清杀共享台账在用实例正是本
配方要防的反模式。

## 1. 互杀机理(为什么会互杀)

三条清场路径全部作用于**全局台账** `~/.cache/lasso/launched-chromes.json`(默认单文件):

| # | 命令 | 作用域 | 互杀面 |
|---|------|--------|--------|
| 1 | `render-chrome --stop` | **未设 env**:台账内全部 render 记录(任意 port,设计决议 3.7 未设分支);**显式设 `LASSO_RENDER_PORT`**:只收该 port(2026-09-02 提案 §6 落地;非法值 exit 1) | 未设 env 时仍全局——历史互杀第一入口;显式设 port env 后只收自己 |
| 2 | `chrome-stop --all`(无 `--modes`) | 台账内全部记录(含渲染档,设计决议 3.5 有意「全停」出口) | 同上 |
| 3 | 验收脚本 step0 清场 | 通常封装以上两条 | 同上 |

**只设 `LASSO_RENDER_PORT` 曾不构成隔离**(2026-09-02 提案 §6 落地后已部分构成):
port env 现对 ensure/status/--stop 构成端口作用域;`render-chrome doctor` 孤儿判定
作用域化随提案 §6.2 同轮实施(见 §1 第四面),而 `chrome-stop --all` 与共享台账 idle
reaper 仍需台账/执守 env 才隔离——三 env 配齐的必要性不降级。

第四面(边缘但真实,分账隔离下才暴露):`render-chrome doctor --clean` 的孤儿判定
= 指纹对 + **你的台账缺位** + 存活 >10min(`RENDER_ORPHAN_MIN_AGE_SEC=600`)。分账后
其它 agent 的合法实例不在你的台账里 → 会被误判孤儿杀掉。**并行期间禁跑 `doctor --clean`**
(它只许在单 agent 维护窗使用)。

## 2. 配方:三 env 命名空间(缺一有暗坑)

并行验收 agent 各配一套,**三件必须配齐**:

```bash
# agent A                                    # agent B
export LASSO_RENDER_PORT=9234                export LASSO_RENDER_PORT=9235
export LASSO_LAUNCHED_CHROMES_PATH=~/.cache/lasso/accept-A/launched-chromes.json
export LASSO_RENDER_GUARDIAN_PID_PATH=~/.cache/lasso/accept-A/render-guardian.json
# touch 目录无需覆盖:touch 文件名含 port(chrome-touch-<port>),端口互异天然不撞
```

| env | 作用 | 缺失的暗坑 |
|-----|------|-----------|
| `LASSO_RENDER_PORT` | 端口命名空间:拉起/ensure/status 只认自己的端口 | 两 agent 抢同一端口,后者 exit 3 |
| `LASSO_LAUNCHED_CHROMES_PATH` | 台账命名空间:记录/清场/收割只读自己的台账 | `--stop` / `chrome-stop --all` / idle reaper 全部作用于全局台账 → 互杀依旧 |
| `LASSO_RENDER_GUARDIAN_PID_PATH` | 执守命名空间:reaper 守护各自收割自己的台账 | 新 guardian 入口自检「别的执守在世 → 让位 exit 0」,继承旧 env 只读旧台账 → 你的分账实例**无收割宿主**,滞留到 doctor 24h 陈年扫描或手工清理 |

配齐后:该 agent 的全部 lasso 命令(ensure / status / stop / chrome-stop / idle reaper)
只看得见自己命名空间内的记录,互不可见即互不误杀。

## 3. 并行清场纪律

并行会话期间:

- 允许:命名空间内清场(设齐三 env 后 `render-chrome --stop` 只收自己台账内的 render 记录)。
- 允许:单实例精准收口(不动他人)——`chrome-stop --port N --modes render`(现存旗标,
  端口+mode 双重限定,2026-09-02 实测);同台账确需全收渲染档时 `chrome-stop --modes render`。
- **禁止**:`chrome-stop --all`(即便分账,也只许单 agent 维护窗跑,养成肌肉记忆)。
- **禁止**:`render-chrome doctor --clean`(跨命名空间孤儿误判,见 §1 第四面)。
- 验收命令序列 / media-gen 侧验收脚本:step0「清场」段必须以三 env 前缀执行,或干脆
  删除全局清场、依赖 idle reaper 10min 自动回收(`LASSO_RENDER_IDLE_MS` 默认 600000)。
  **例外**:lasso 自家 `test/render-tier-acceptance.mjs` **不适用三 env 前缀**——它按
  设计硬编码默认口 9224 + 真实全局台账(验收的就是默认生产契约,多处断言钉死 9224),
  设 env 会让断言假红。该脚本同机并行不支持,只能串行 / 单 agent 独占窗口跑。
  另注(2026-09-02 提案 §6 落地后):调用 shell 若泄漏 `LASSO_RENDER_PORT`(尤其
  =9224)会把该脚本的全局清场**静默收窄**为 port 限定(item 0.2 指纹归零假红 + 收尾
  漏杀);泄漏非法值则 stop exit 1 → item 0.1 假红。脚本已配启动 fail-fast 守卫
  (三 env 任一已设非空即一句话报错退出)。

## 4. 已知不对称(已裁决落地,2026-09-02)

`--ensure`/`--status` 认 `LASSO_RENDER_PORT` 而 `--stop` 不认的不对称,已于
2026-09-02 裁决并落地(doc/提案-render-stop端口作用域化.md §6):`--stop` 现认显式
`LASSO_RENDER_PORT`——显式合法=只收该 port(与 ensure/status 对称);未设=全部 render
记录(设计决议 3.7 语义不变);显式非法=exit 1 用法错。engine 层零改动
(`stopLaunchedChromes` 的 `opts.port` 过滤与 `chrome-stop --port N` 早已在,只补了
render-chrome CLI 接线);全局收口出口不变:`chrome-stop --modes render` 或临时
unset env。`render-chrome doctor` 的孤儿判定作用域化(+touch 新鲜度豁免)随提案
§6.2 同轮实施(见 §1 第四面)。

## 5. 自检

```bash
# 配齐三 env 后,应只见自己的记录(port 应等于自己设的 LASSO_RENDER_PORT)
lasso-mcp render-chrome --status
# 并行结束时,自己命名空间内收尾(不动他人)
lasso-mcp render-chrome --stop
```
