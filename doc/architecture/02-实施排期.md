## 0. 排期原则

1. **能力跃升优先于工时**：阶段分割以「用户能做的新一类事」为界，不以代码量/工时为界。每阶段交付后能力集合发生跃升（不只是多 1 工具，而是多 1 类用法）。
2. **每阶段可独立交付与验证**：有可运行 MCP server + 量化验收用例；任意阶段失败可打 tag 回退。
3. **依赖前置清晰**：v0.3 多步链式依赖 v0.1 tri-state；v0.3.5 desktop 依赖 v0.1（tri-state/StateStore/doctor）+ v0.3（expect/多步）。
4. **MVP 先于完备**：desktop Rust helper 分阶段（v0.3.5 只 ax+screenshotVlm，appleScript/cgEvent v0.4+）。
