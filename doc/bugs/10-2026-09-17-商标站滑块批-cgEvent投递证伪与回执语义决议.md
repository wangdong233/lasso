## 2. 决议 B（P2）：evaluate 返回值契约——自动 IIFE 兜底 + 错误教学

### B.1 `evaluateFunctionArg` 形态判定扩展（保守、零回归方向）

在既有三形态（函数表达式透传 / IIFE 包表达式体 / 语句体包裹）之上加**两条表达式路由**，判定规则（全部机械可测，导出供单测）：

1. **括号表达式路由**：起手 `(` 且——首平衡括号组**后不接 `=>`**、且组内容（trim 后）不以 `async`/`function` 起手 → 判**括号表达式**（`({...})`、`(1+2)`、`(a+b)`）→ 包 `() => (\n<t 剥尾;>\n)`。括号组内可跨行（括号内换行语法合法）；组后接 `=>` 或内容为函数起手 → 维持透传（现行行为字节级不变）。
2. **单行裸表达式路由**：**单行**（无 `\n`）+ 剥尾 `;` 后**无内部 `;`** + 不以语句关键字起手（`const|let|var|return|if|for|while|do|switch|try|throw|class|with|debugger|function|async function|import|export`）+ 括号/引号平衡 → 判**单表达式**（`JSON.stringify({...})`、`document.title`、`1+2`）→ 包 `() => (\n<t>\n)`。
3. 其余（多行、多语句、声明、语句关键字）→ 语句体包裹，**现行行为字节级不变**。

**保守性论证（沿既有「响亮优于静默」取向，方向翻转已核对）**：表达式误包语句 → 上游语法错（响亮可修）；语句误落表达式路由被排除（关键字/分号/多行三闸）→ 不存在「今天能跑、明天报错」的输入类——多行 `JSON.stringify({\na:1\n})` 落语句体仍 undefined，但 B.2 的教学回执会当场告诉调用者为什么与怎么改（诚实边界，非静默）。

### B.2 错误教学（v1.27.1「错误即教学」体系补位）

- evaluate 结果为 `undefined` **且** lasso 包裹形态为语句体 → result data 增 `js_form:"statement_body"` + `js_form_hint`（一句：statement bodies return undefined unless you `return` — send one expression (now auto-returned), an IIFE, or add `return`）。
- 上游错误串含 `is not a function`（evaluate 路径）→ 错误文案追加同款 hint 前缀（分类处接线，`eval_upstream_error` 前缀语义不变）。

### B.3 descriptions 契约句（INV-92 族：描述与钉它的断言同 commit）

evaluate 段「All work.」后补 RETURNS 子句：any other single-line EXPRESSION (`JSON.stringify({...})`, `({a:1})`, `document.title`) is auto-wrapped as an expression body and its VALUE is returned; multi-statement bodies (declarations / `;` / multiple lines) return undefined unless you `return` — prefer one expression per call。DESKTOP/其余工具零触碰。真源导出（`evaluateFunctionArg`/`isIifeString` 已导出先例）同 commit 扩 e4 spec。
