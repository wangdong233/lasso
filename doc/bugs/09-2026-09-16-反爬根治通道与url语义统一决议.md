## 1. 决议 A：反爬根治通道——**路线④ 分层防御梯（L0/L1/L2）+ 驱逐哨兵**

### A.0 目标 / 非目标

**目标**：对「JS 层重定向驱逐」类站点（tm.aliyun.com 形态），把消费方状态从「完全没办法」（context destroyed 深埋错误串、无差别重试）变为「三层可退 + 死因可观测」。
**非目标**：不承诺通过一切反爬（服务端 IP 拦截、验证码墙不在本案）；不自动化对抗（无行为模拟、无代理轮换——后者属新组件红线区）。

### A.1 四路线裁决矩阵

### A.4 HeadedChannel 规格（L2）

1. **落位**：`src/channels/HeadedChannel.ts`，`extends BrowseChannel` 平级兄弟（SteelChannel 先例配方：R-CI-02 守、装配四处 `channelToSpec` / 工具注册 / `initialCapabilities` / `longBreakers`、INV 新增）。
2. **spawn（r1 修订）**：`chrome-devtools-mcp@1.7.0`（同一 `LOCKED_CDP_MCP_VERSION`，**不带 `--headless`**）+ 显式 `--user-data-dir=<~/.cache/lasso/headed/<run_id>>`（**替代裸 `--isolated`**：上游 browser.js:138-144 不传 isolated 且不传 userDataDir 时会落到 `~/.cache/chrome-devtools-mcp/chrome-profile` 持久共享 profile——必须显式传 lasso-owned 路径；该路径同时是 ps 级归属锚 + reap hook post-kill rmSync 清理点，headless freshProfile 同款先例）+ `--no-usage-statistics`（INV-79b 四通道族扩展为五通道）。**零新二进制、零新依赖、同一上游不同 flag 组合 ⇒ 不触「新组件」红线。** CDP 走 pipe（上游 browser.js:172 `pipe:true`）——无 TCP 端口暴露（攻击面更小，但见⑤r1：台账/chrome_status 按 port 的机制对 headed 不可达）。
3. **stealth 策略**：**不接 StealthEngine 指纹注入**（真实有头环境即真实指纹；注入痕迹本身是信号——与 HeadlessChannel 相反的取舍，注释写明理由防后人「顺手对齐」）。仅保留 `--chromeArg=--disable-blink-features=AutomationControlled`（抹 navigator.webdriver）。实现期 audit 一遍 puppeteer 默认 flags（`--enable-automation` infobar 等）并在 spec 显式排除（上游 `--ignoreDefaultChromeArg` 已核实存在，WT0/WT2 期用）。
4. **窗口策略**：`--window-position` 屏幕边缘最小可见（macOS 完全屏幕外窗口会被系统判 occluded → `visibilityState:hidden` + rAF 节流，可能反成行为评分负信号）。**L3 真机验证项**（开放项 1/3）：边缘露出 vs 屏幕外全藏的 visibilityState 差异 + tm 站实效对照。
5. **生命周期与用户接管防线（r1 全文重写——N1 复核证实原案建立在错误收割器域上）**：
   - **域事实（先钉死，防后人再引错域）**：HeadedChannel 是 SubprocessManager procs 域成员，**不落 chrome-ledger**。visible/userTakenAt 豁免是 chrome-idle-reaper 的谓词（chrome-idle-reaper.ts:281-291），两域分工是结构性的（:14-17）；userTakenAt 全库仅两条写径（B1 确认窗/chrome-show，chrome-ledger.ts:291-294）——对 procs 域不可达。CDP 走 pipe 无 TCP 端口 ⇒ chrome_status 按 port 的归属鉴定同样不可达。**原案「SubprocessManager 统一注册（同 headless）+ 复用 chrome_status/user_taken_asset 语义」三处机制引用全部落空；「对齐默认 30min」引错域（headless 域实际默认 5min，config.ts:74——照原案实现，用户接管中的窗口 5 分钟无 lasso 调用即被 cleanupZombies 树杀，doc/bugs/03 F4 同型事故重演）。**
   - **两态生命周期（替换原「对齐」一句）**：
     - **态一·未接管**：idle 收割生效，独立阈值 `LASSO_HEADED_IDLE_MS`（config 新键，默认 **30min**）。依据：有头窗口弹出是屏幕上的显式可见事件，回收窗口须宽于 headless 域 5min 以覆盖「用户正走向电脑」竞态；数值对齐 ledger 域 `LASSO_LAUNCH_IDLE_MS` 默认而非 headless 域。
     - **态二·已接管（粘滞，永不回落）**：**接管探测器**——经 pipe 会话 30s 周期 evaluate `document.hasFocus()`（窗口获用户焦点 ⇒ 真实用户在场交互），命中即标记 session `userTaken` 粘滞 ⇒ **永不 idle 收割**；BUG-06 式硬顶兜底（`LASSO_HEADED_HARD_CAP_MS` 默认 24h，防孤儿舰队——media-gen-mcp P0 教训）。**用户关闭出口**：有头窗口用户可自行点 X（pipe 断 ⇒ proc exit ⇒ SubprocessManager 既有清理路径）——这是有头相对 hidden 的结构性优势，也是「接管后永不自动杀」能够安全成立的前提。lasso 侧关闭出口 = 显式 stop（admin/browser_recycle 族，须带归属校验）。

6. **免解锁与 consent 契约（r1 修订——N3）**：独立工具 `browse_headed`（对齐 browse_headless/browse_logged_in 命名族，R-CI-01），默认注册。**免解锁依据重写**：不以「本地资源、无付费、无 key」（成本维度——静默守则的判据是打扰维度，成本不构成豁免）为由，而以**本机工具族先例**（browse_logged_in 同默认注册，操作本机 Chrome 资产）+ **打扰面用 consent 契约治理**为由：browse_headed 是 S2 介入型工具（调用即弹真实窗口），非 S1 零打扰通道——**description 首行钉死 `opens a real on-screen window — call only after explicit user consent`**，hint 同步带 ask-the-user 指令（A.2r1）。INV-25 式部署级解锁门**定向驳回**（r1 表 N3 行论证：介入面反而更大且弱化每次调用的 consent 检查）；保留升级出口：实施后若实测 agent 无视 consent 语言，回写本文件升解锁门。SSRF guard 与三层安全经 BrowseChannel 继承，**零削弱**。

## 2. 决议 B：url 语义统一——单一 ensure-navigation 模型（P1-A/B/C 一体）

### B.1 统一语义（全部 url 感知 action，四族收敛为一）

1. **url 缺省** → current-page 模式（会话守卫：无会话 ⇒ didnt + `no_active_session`，不静默空白页）。**白名单 += evaluate**（CURRENT_PAGE_ACTIONS 三项：screenshot/wait/evaluate）。
2. **url = 当前页** → **零导航直执行**（不 reload——同 URL 导航会毁 SPA 状态；evaluate 现语义泛化到全族）。
3. **url ≠ 当前页** → 先导航（保留 hash same-document 检测/no_reload 语义）再执行，回显 `did_navigate: true`。
4. 所有 url 感知 action 返回体统一带 `did_navigate: true/false`（如实回显，消灭「url 是装饰」）。

### B.2 四族收敛明细

| action 族 | 现状 | 统一后 | 行为变化 |
|---|---|---|---|
| evaluate | ensure-nav（已是目标语义） | 不变 + 白名单补缺省形态 | 缺省 url 从拒绝 → current-page（**修复 descriptions 谎言**） |
| snapshot/extract | FRESH_PAGE_NAV 空白门控 | ensure-nav | url≠当前页：从「读残留页（假数据）」→ 导航后读（**修复 P1-B 本体**）；空白会话+url：行为等价；已导航+缺省 url：行为等价（观察流 `navigate→click→extract` 无 url 照旧） |
| network/screenshot/pdf | NAV_FIRST 无条件导航 | ensure-nav | url=当前页：从 reload → 跳过（**改善**：保 SPA 状态；记 CHANGELOG 行为标注） |
| wait/click/fill | current-page 动作 | 不变（wait 已在白名单） | 无 |

三个 Set（NAV_FIRST/FRESH_PAGE_NAV/ensure-nav 分裂）收敛为单一 ensure-navigation 实现 + CURRENT_PAGE_ACTIONS 白名单——R-CI-02「同一类操作一种做法」落地，BrowseChannel 语义面**净减**一个概念。

### B.3 兼容 / 安全 / 测试面

- **有意 breaking**（修复目标本身）：依赖「extract+url 读当前页」的 workaround 流（喵虎时间线 7 证存在）统一后行为改变。CHANGELOG + descriptions 显著标注 + 返回体 did_navigate 使新旧行为可判读。
- **安全**：ensure-nav 语义下每次导航仍过 SSRF guard（wrapNavigate 路径不变）；current-page 模式零新增导航面。
- **测试**：dispatch 矩阵单测（action × {缺省, 相同, 相异} × {有会话, 无会话, 空白会话} → 导航行为 + did_navigate 回显值）；INV-92 族（schema↔description 同 commit）同步更新；FRESH_PAGE_NAV golden 测试重写为统一语义版。

- **真值来源 = 链尾一次 readCurrentHref**（wrapChainResult 内新私有 helper，browse() steps 分支收尾处）——无论链经何路径到达，尾读是地面真值；**永不回显请求串**（StepEngine.ts:330 `final_url: url` 删除，改为种子链：最后携带 final_url 的 step partial → entryNav.final_url → undefined；尾读覆盖种子）。**种子等值守卫（r3）**：种子候选（step partial / entryNav 的 final_url）等于链请求串时**视同缺席**——doNavigate 自身 `extractFinalUrl(r) ?? url`（`:1339`）在 upstream 散文解析失败（extractFinalUrl 匹配不到 http(s) 子串 ⇒ undefined）时回退请求串，不经守卫会经「尾读失败 → 先导 nav final_url」把回显洗白进链级真值（消谎目标被旁路）。等值即弃是来源判据的保守实现：种子=请求串时无法区分真值与回显，诚实 prefers 缺席；navigate 本尊单 action 返回体维持 `?? url` 既有契约不动（消费方契约零破坏）。
- **先导导航透传**：browse() 捕获 nav partial（现状 :362 丢弃）→ runChain 增可选参数 `entryNav?: {final_url?, same_document_navigated?, same_document_reloaded?}` → ChainResult 种子 + sd 双标注透传（对齐 I-2 单 action 组合形态）。
- **链级 did_navigate** = entryNav 在场 ∨ 任一 worked navigate step；ChainResult 增字段，wrapChainResult 传播至 data.did_navigate。
- descriptions 同步三处（:261-263 steps 语义句 / :294-295 Returns 句 / :359 交叉引用）：限定语从「steps chains carry no did_navigate」更新为链级回显真值语义。
- **测试面（r3）**：dispatch 矩阵扩展（steps × {navigate 先导, 链内 navigate step, 残留页, url==当前页} × {final_url ≠ 请求串断言, did_navigate 值, sd 透传, 尾读失败省略}）+ **INV-100 链真值契约（r3 来源化措辞）**：worked 链 ⇒ data.final_url 的**来源绝不=请求串回显**——来源判据、非值判据（页面真落于请求 URL 时尾读=请求串属真值，非违约；r2 的「绝不=请求串」值措辞会误伤此形态）；grep 锚×2：StepEngine `final_url: url` 模式消灭 + 链种子等值守卫在场；值断言夹具纪律：landing≠request 形态断言值；新增用例「尾读失败 ∧ 上游 navigate 无 finalUrl ⇒ data.final_url 缺席（非请求串）」。
