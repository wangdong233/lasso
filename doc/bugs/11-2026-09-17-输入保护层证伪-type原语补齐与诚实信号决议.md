## 1. 决议 A（用户核心问题·边界判定）：**①「原语补齐 + 诚实信号」**——墙在那里，告诉你，穿不穿交给调用方

### A.0 前提重置：P0「输入保护层拦截」不成立

承白盒定谳（§0 断言 7/8）：不存在「程序化设值被瞬间清除的拦截层」。真实机制是**框架/引擎的状态完整性语义**：

1. tm.aliyun.com 搜索框是 **React 16/17 受控组件**（`__reactInternalInstance$`/`_valueTracker`/onChange 均在；下午只查 React 18 的 `__reactFiber$` 故误判「非 React」）；
2. 只走脚本写入（`element.value=`）的值**不触发** React onChange → 受控状态仍是空 → **blur/下次 commit 时 React 把 DOM 回写成已提交状态**（值存活到 blur，不是毫秒级消失）；
3. 站点另有实例级 value accessor 劫持（setter 记录+转发、getter 透传）——同族机理；
4. 经**可信输入管道**（CDP `Input.dispatchKeyEvent` 逐字派发，浏览器标记 `isTrusted:true`，React onChange 正常触发）键入的值 blur 后存活——**lasso 现有 uid 路 fill（短值）当天在 tm.aliyun.com 全链路完成真实搜索**（新 tab 结果页、无滑块、webdriver=true 且无 stealth 仍放行）。

下午「六路全败」的重排：实验 1（chain fill+click）**实际成功**（搜索完成，观察面错误误判失败）；实验 2/5/6（evaluate JS 设值 + click/Enter）失败是上述机理的正确表现（脚本值 + blur 回写 → 空值提交）；实验 3（tracker 欺骗）「方法不适用」判定本身错误（tracker 在，只是没找到）；实验 4（物理点击）投递链完好但值已被回写清空——**与滑块无关，滑块从未出现是因为搜索已成功**。

### A.1 三选一裁决

| 选项 | 裁决 | 论据 |
|---|---|---|
| ① 原语补齐 + 诚实信号 | **采纳（本批交付物）** | (a) P1 是真实能力缺口：click/fill/type 三原语的第三缺，Playwright/Puppeteer/上游 chrome-devtools-mcp 全员标配（§0 断言 1-2），lasso 作为交互抓手 MCP 无理由残缺；(b) 保护层失败模式此前**不可见**（fill 报 worked、值静默消失）——`input_guard_suspected` 信号（决议 C）把墙显式化；(c) 零对抗成本：用对原语（可信管道）即可穿过「墙」，而那本来就是标准自动化能力 |
| ② 主动对抗（穿透手法） | **REJECTED-BY-DESIGN（§8-1）** | (a) **伦理红线**：`_valueTracker` 欺骗（伪装用户输入骗过框架状态追踪）、accessor 反劫持（拆除站点的 setter 包装）、isTrusted 伪造、人类节奏拟态——全部是「欺骗站点侧机制」而非输入能力，本批任务书明令拒绝；(b) **无必要**：待补齐的 `type` 原语走可信管道，正门是开的；(c) **脆性**：对抗手法与站点实现版本强耦合，维护成本无上限 |
| ③ 不处理（纯站点行为） | 驳回 | 把 P1（正当原语缺口）和诚实信号一起扔掉，违背 lasso「CC 全交互抓手」定位；且失败静默（fill worked 但值没了）本身就是 lasso 的可观测性欠账 |

### A.2 伦理边界声明（本批最重，实施与后续演进双适用）

1. **正当**：`type`/`press` = CDP `Input.dispatchKeyEvent` 逐键派发，与 Playwright `page.keyboard.type()`、Puppeteer `keyboard.type()`、上游 `type_text`/`press_key` 同级的标准输入原语。CDP Input 域事件被浏览器标记 `isTrusted:true` 是协议的公开设计（所有 DevTools 驱动自动化的基础），提供它 = 能力对齐，不是欺骗增强。
2. **拒绝实现**（任何人未来提需求也拒绝，除非用户显式推翻本节）：键入节奏随机化/人类拟态延迟（欺骗行为检测）；`_valueTracker`/`isTrusted`/accessor 任何形式的伪造或拆除；「让 fill 看起来像人输入」的一切包装。
3. **lasso 立场**：提供诚实原语 + 如实信号——**墙在那里我们告诉你**（信号 + hint），穿墙方式只有两种合法形态：换可信原语（type），或**请用户物理输入**（hint 指引；headed/visible 窗口场景）。绝不替用户决定攻墙。

## 2. 决议 B（P1）：`type` / `press` 两 action——上游工具映射，禁 CDP 直连

### B.0 实现路径（按 §0 断言 9：映射，非自建）

- `src/browse/cdp-actions.ts` `CDP_UPSTREAM_TOOL_NAMES` 增 `type_text: "type_text"`、`press_key: "press_key"`（INV-6 集中表，上游漂移只改一处）；`ACTION_TO_UPSTREAM_TOOL` 增 `type: "type_text"`、`press: "press_key"`（P10 前置门自动覆盖，D-β）。
- `src/channels/BrowseChannel.ts` `actionDispatch` Map 增两行（INV-33：必经 Map，禁第二套 dispatch）；`BROWSE_ACTIONS` frozen 列表**同 commit** 增 `"type"`/`"press"`（truth spec 相等性断言钉死，漏一处即红）。

### B.1 `type` action 形态

- **入参**：`selectors = { "<uid|ref>": "<text>", ... }`——与 `fill` 同形（uid→text 多字段顺序键入；`^r\d+$` 键 = lasso ref，复用 REF_PATTERN 双路先例）。**零新 zod 键**（selectors 既有 record）。
- **uid 路**：每字段 `callTool("click", {uid})`（可信鼠标点击获得焦点——上游 `type_text` 的文档化前置「previously focused input」）→ `callTool("type_text", { text })`。
- **ref 路**：`evaluate_script` 定位（复用 `buildRefLocateExpr`）+ `el.focus()` + 回读 `document.activeElement === el` 作 focus 回执（失败 → throw `type_focus_failed:<ref>` → didnt 档）→ `callTool("type_text", { text })`。
- **不暴露 submitKey**（上游 type_text 有此参数）：提交显式走后续 `press key:'Enter'` 或 `click`——两步链更可审计（上传 tap 子串/意外提交零风险）。v1 最小面，开放项 4 复评。
- **长值**：不设长度上限（逐字派发天然覆盖 D-α 断层的 ≥100 字符不可信场景）；describe 注明长文本性能特征（逐字 ~ms 级/字符）。

### B.2 `press` action 形态

- **入参**：新 zod 键 `key: z.string()`（如 `"Enter"`/`"Control+A"`——与上游 press_key key 契约逐字一致，修饰键由上游拆解+失败释放保证，§0 断言 2）；`steps[].key` 同步（Step 链内可用）。`types.ts` `BrowseOptions` 增 `key?: string`。
- **实现**：`callTool("press_key", { key })` 直通，零包装。

### B.3 表登记（全部同 commit）

## 3. 决议 C：`input_guard_suspected` 信号（驱逐哨兵同范式：纯信号，零副作用，绝不自动改道）

### C.1 判据（三探针，一次 in-page evaluate，零新增 RTT——内嵌进 ref 填充/键入的既有表达式返回值）

| 判据 | 探测 | 对应机理（§0 断言 8） |
|---|---|---|
| **G1 安装态** | `el` 自身有 `value` own property **或** 原型链上 `value` 访问器 `String(desc.set)` 不含 `[native code]` → `check:"value_setter_non_native"` | 实例级 accessor 劫持 |
| **G2 生效态** | 设值后 in-page 延时 ~250ms 读回 ≠ 所设值 → `check:"fill_readback_mismatch"` | MutationObserver/异步重置族 |
| **G3 受控分叉** | `'_valueTracker' in el` 且 `tracker.getValue() !== el.value` → `check:"react_tracker_divergence"` | React 16/17 受控回写（tm.aliyun.com 本体机理） |

### C.2 回显与 hint

- `data.input_guard_suspected = { checks: string[], target: "<ref|uid>", at_ms }`——**advisory，outcome 照旧 worked**（值此刻在 DOM，风险在 blur 后；不伪造失败）。`browseSingle` 返回组装点检测到该字段时置 `result.hint = this.inputGuardHint()`（consumeEviction 同款单组装点）。
- hint（双假设措辞 + 可复制 call shape，🔴 单引号形参——INV-98 源锚 `[^"]+` 红线）：
  > `suspected site input guard (not confirmed — value setter is non-native / filled value was not kept / React tracker diverged; script-set values may be rewritten on blur or re-render); per-key typing enters the trusted input pipeline: browse_headless({url:'...', action:'type', selectors:{'<uid>':'<text>'}}) — or re-extract and fill via snapshot uid (fill_form types short values per key); if typed keys are also rejected, ask the user to type physically`
- **值守区 = 信任阶梯第 2 层**：doFill ref 路 + doType ref 路内嵌三探针。uid 路 v1 不探（已在第 1 层可信管道；快照解析探针的成本>增值——如实文档化此边界）。

### C.3 红线（驱逐哨兵同款，逐字沿用精神）

**只供信号，绝不自动改道**——检测到保护层不得自动换 type/自动重试/自动换通道（惊吓面与归因权交给知道真相的调用方）；hint 里的换路指引是指令不是行动。信号路径零 FallbackDecider 调用、零 spawn、零页面副作用（G1/G3 纯读；G2 的 250ms 在页内 sleep，不发事件、不 blur、不 focus 别处——**明确禁止为探测合成 blur**，blur 会触发提交/校验）。

## 4. 决议 D：P2（fill 时序）+ P3（no_reload 语义）

### D.1 P2 —— 修复重定向：时序防御证伪，真缺口是**观察面**（D-ε）

- **证伪登记**：「fill 赶在引擎初始化前执行导致值被覆盖」无 reproducer——白盒受控重析中 uid 路 fill 当天全链路成功（§1.A.0）。**无 reproducer 不写防御代码**（白盒纪律：上一批「决定性实验」被证伪的教训）。
- **真修复 1（代码，小）**：`doWait` 两个 `wait_timeout:` throw 点（BrowseChannel.ts:2182/:2191）文案丰富化——追加教学句 `…; if the action opened a NEW tab (window.open), the original page URL never changes and this wait cannot succeed — inspect open pages or use the desktop channel`。`window.open` 形态的 wait 超时第一次携带归因线索。
- **真修复 2（文档）**：`doc/usage/02-TROUBLESHOOTING.md` 新 §2.19「新 tab 观察面」：submit 走 `window.open` 时原选中页 URL 永不变（`wait url_contains` 结构性失明）+ 链配方 `navigate → wait{selector:<input>} → fill → press/click`（hydration 竞争的通用防线 = 显式 wait step，已支持，无需新机制）。

### D.2 P3 —— 语义本身正确，缺陷是**可读性**：describe 澄清 + 语义钉，零行为变更

行为矩阵（§0 断言 10 核对，现状即正确）：

| 形态 | did_navigate | same_document 标注 | no_reload 效果 |
|---|---|---|---|
| URL 规范化后全等（含 hash） | `false`（规则 2 零导航） | 无 | 死键 → `ignored_options` 如实标注 |
| hash-only 差异，默认 | `true` | `navigated:true, reloaded:true` | — |
| hash-only 差异，`no_reload:true` | `true` | `navigated:true, reloaded:false` | **跳过补 reload**（SPA 自管 hash 的显式逃生） |
| 实质不同 URL | `true` | 无 | 消费但无 same-document 分支（「期权」语义） |

- 修复 = `NO_RELOAD_DESCRIBE`（src/tools/browse.ts:82）补一句：`this is NOT a skip-navigation flag — navigation still happens whenever the url differs; identical-URL targets never navigate at all`。下午「no_reload:true 仍 did_navigate:true」是第三/四行的**正确行为**，误会源是描述缺这句。

## 8. rejected-by-design（R-CI-06）

1. **保护层穿透族**（决议 A-② 全量）：`_valueTracker` 欺骗作为 fill 策略、accessor 反劫持、isTrusted 伪造、键入节奏随机化/人类拟态——伦理红线 + 无必要 + 脆性（§1.A.2）。
