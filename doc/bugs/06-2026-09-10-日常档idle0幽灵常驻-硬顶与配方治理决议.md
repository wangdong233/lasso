# 设计决议：日常档 `--idle-ms 0` 幽灵常驻——硬顶天花板 + 双意图逃生口 + 超龄可观测 + 配方治理

> 事故日期：2026-09-10（用户实锤）· 实例：pid 97247 / port 9223 / 2026-09-09 23:36 由 CC 会话按固化配方拉起 · 严重级：**事故级**（违反产品宪法「静默服务前提 = 可发现可关闭」：无窗口 + 执守压窗 + 永不回收 = 12h 幽灵常驻，Dock/菜单栏不可见，用户「关不掉」；已当场 `chrome-stop` 收掉）
>
> 输入：白盒五任务闭环 + 外部调研（ZooKeeper maxSessionTimeout / browserless 全局 TIMEOUT 顶 / GKE Autopilot 平台级上限 / kubectl·systemctl·hdparm 双意图旗标先例）。设计合成员已对全部源码锚点逐条复核（launch-chrome.ts / config.ts / index.ts / chrome-ledger.ts / chrome-idle-reaper.ts / desired-hide-enforcer.ts / render-launcher.ts / render-guardian.ts / render-flags.ts / chrome-status.ts / doctor.ts / 既有测试面）。
>
> 🔴 **用户红线（沿用）**：禁项目外新组件；永不 kill 用户浏览器（userTakenAt/visible 豁免语义零变化）；**硬顶不得误杀合法长任务**（渲染档 `LASSO_RENDER_IDLE_MS` 语义独立——日常档显式 0 与渲染档无关，不得交叉污染）；消费方契约零破坏（nohup 配方行为变化属预期 breaking，须 changelog 显著位 + 通知）。纪律：改行为必配测试；`npm run gate` 读汇总行；单主题 commit 不 push 不发版。

## 1. 现象与溯源（白盒复核确认）

- 97247 = port 9223（媒体生成/Flow 惯例口），hidden 日常档，`--idle-ms 0` 显式启动。ownerPid 97245 已死是 **CLI 常态非异常**（launch-chrome spawn 后 `process.exit()`，所有权靠磁盘台账跨进程传递——chrome-ledger.ts 头注）。
- 配方源头链（C 治理对象）：`doc/bugs/02:45` 首创 `node dist/index.js launch-chrome --port 9223 --idle-ms 0`（v1.18.5 时代的正确缓解）→ 固化进 `doc/usage/02-TROUBLESHOOTING.md:397`（标注「推荐」）→ 传播至 `doc/usage/01-KEY-GUIDE.md:169`、`README.md:331/342`（+英文版）→ 消费方 media-gen-mcp `doc/flow-api-contract.md` 同步采用。v1.21.0（BUG-03 A1）已把 CLI **默认** idle 从 0 翻 30min，但显式 `--idle-ms 0` 仍字面无限——本决议根治该缺口。
- 事故时收割宿主其实活着：hide-enforcer 执守（97263）双职责收割在跑、阈值 60s（`enforcerCfg.launchIdleMs` = DEFAULT_LAUNCH_IDLE_MS）。**单点让 97247 不死的正是 record 级 0 分支**（chrome-idle-reaper.ts:240-241）。

## 2. 根因链（五点，全部设计合成员源码复核）

1. **CLI 解析放行 0**：launch-chrome.ts `--idle-ms` 分支守卫 `!Number.isNaN(n) && n >= 0`——0 合法入参。
2. **env 同样放行 0**：config.ts `parseLaunchIdleMs` 守卫 `Number.isNaN(n) || n < 0` 才回退默认——`LASSO_LAUNCH_IDLE_MS=0` 原样通过（0 =「禁用」文档化语义）。
3. **CLI 装配默认**：index.ts `launch-chrome` 路由——env 未设才用 `CLI_LAUNCH_IDLE_DEFAULT_MS`（30min）；env 设了（含 0）→ `cliCfg.launchIdleMs` 透传。
4. **台账保真落位**：chrome-ledger.ts `idleMs: typeof === "number" && Number.isFinite ? 原值 : undefined`——0 是 Finite 被保真记录（台账忠实记录请求，正确）。
5. **收割判定永久跳过**：chrome-idle-reaper.ts:240-241 `const idleMs = rec.idleMs ?? defaultIdleMs; if (idleMs <= 0) continue;`——record 级 0 = 永不进入收割判定。收割宿主在世也无济于事（本事故实证）。

附带发现（同链复核，D 面输入）：全局 env `LASSO_LAUNCH_IDLE_MS=0` 更强——`startChromeIdleReaper` 直接返 null（reaper 整体不启动），连 per-record `idleMs>0` 的记录也无人收割。

## 3. 定性

- **平台层缺天花板**：lasso 把「永不自收」做成了一个无界的单旗标语义。外部调研的四个成熟模式共同教训：**字段/请求无界时，平台层必须加顶**（ZooKeeper 把客户端 session timeout 夹进 [2×tick, 20×tick]；browserless 企业版全局 300s 顶在每会话 TIMEOUT 含 -1 之上；GKE Autopilot 对无上界 terminationGracePeriodSeconds 补 ~600s 平台上限——上游 API 无硬编码上限，discuss.kubernetes.io/t/32094）。同时**毁损级例外必须双重意图**（kubectl 强删须 `--grace-period=0 --force` 两旗并给；systemctl `--force --force` 字面重复；hdparm `--yes-i-know-what-i-am-doing`）。
- 与 BUG-03 的关系：A1 修的是**默认值**（0→30min），本决议修的是**上界形状**（0 的语义）。二者正交：A1 管「不写旗标的人」，本决议管「写了旗标/抄了配方的人」。
- 产品宪法判例：「静默服务前提 = 可发现可关闭」。visible/userTaken 档可发现（有窗口）可关闭（用户自关）；hidden 档可发现性靠 chrome-status/doctor、可关闭性靠 chrome-stop + idle 收割——`idleMs:0` 把唯一自动出口拆了，12h 幽灵 = 宪法违例。

## 4. 架构决议（A–E）

### 决议 A：硬顶天花板机制（本批核心）

**A-1 值与旋钮**

- 新单一真源常量 `LAUNCH_HARD_CAP_DEFAULT_MS = 86_400_000`（24h），落 **chrome-ledger.ts**（与 `CLI_LAUNCH_IDLE_DEFAULT_MS` 同位同理由：launch-chrome / index / enforcer / doctor 四方共用零环——chrome-ledger 只 import node:*，config.ts 反向 import 它无环）。
- 新 env **`LASSO_LAUNCH_HARD_CAP_MS`**（命名沿用 `LASSO_LAUNCH_IDLE_MS` 域前缀，刻意区别于渲染档——三套 idle 勿互抄的既训）：config.ts `parseLaunchHardCapMs`，未设 → 24h 默认；显式 `0` → 全局禁用硬顶（部署级策略开关）；**NaN/负数 → 回退默认**（防笔误静默拆掉安全网——失效方向必须偏「有顶」）。config.json 扁平层 key 同 env 名，自动继承既有合并机制。
- 默认值依据（外部惯例映射）：browserless 全局顶 = 其典型会话时长的 ~10×；GKE ~600s ≈ 典型 30s grace 的 20×。lasso 日常档合法长任务 = 小时级长会话抓取（30min CLI 默认的语义场景），24h = 默认值 48×、事故时长 12h 的 2×——**显著高于两个业界先例的倍率**，因红线把「不误杀合法长任务」权重置于「快收」之上（误杀代价 = 会话数据损失；不收代价 = 可观测 + 手动收）。

**A-2 语义（「不自收，但 N 硬顶」+ 双意图真无限）**

日常档记录的有效回收期限：

```
capApplies   = hardCapMs > 0 且 rec.launchMode !== "render" 且 rec.hardCapExempt !== true
effectiveMs  = !capApplies ? idleMs                    // 旧语义原样（0=无限）
             : (idleMs <= 0 ? hardCapMs                // 0 → 硬顶兜底
                           : min(idleMs, hardCapMs))   // ZooKeeper 式夹紧
```

- 计时基 = **lastUse 三源 max**（launchedAt / touchMap / touch 文件 mtime）——touch 活跃永不触发硬顶（合法长任务在用就一直活，红线机械化）。
- 真无限（旧 0 语义）需**双重意图**：CLI `--idle-ms 0 --no-hard-cap` 两旗并给（kubectl/systemd/hdparm 先例），或部署级 env `LASSO_LAUNCH_HARD_CAP_MS=0`。
- 收割出口不变：`stopFn({port})` → `stopLaunchedChromes` 验证杀路径（归属验证/树杀/删账 100% 复用；INV-78c 零新 kill 原语零违例）。日志 `chrome_idle_reaped` 增 `bound: "idle"|"hard_cap"` 与 `hard_cap_ms` 字段（审计可区分谁触发）。

**A-3 插入点裁决：收割判定处（chrome-idle-reaper.ts tick 循环），否决两个候选**

- ✅ **reaper tick（定案）**：单点判定、三宿主（server reaper / hide-enforcer 双职责 / 下述 cap-only 模式）一次全继承；visible/userTaken 豁免**结构性前置**（见 A-5）；读侧策略不改任何落盘数据。
- ❌ 启动时改写（recordLaunch 内夹紧 idleMs）：render-launcher 共用 recordLaunch——写入侧改值 = 渲染档交叉污染（红线）+ 台账失真（台账的天职是忠实记录请求，策略属执行层；ZooKeeper 也是服务端夹紧而非改写客户端请求）。
- ❌ 新独立守护/chrome-stop 扩权：违反「禁项目外新组件/禁新常驻守护」红线；且 chrome-stop 是显式出口不该自起。

**A-4 宿主存活（cap-only 模式）**：`startChromeIdleReaper` 返 null 条件从 `defaultIdleMs<=0 && !autoHide` 改为 `defaultIdleMs<=0 && !autoHide && hardCapMs<=0`——全局 env `LASSO_LAUNCH_IDLE_MS=0` 时 reaper 仍以「仅硬顶」模式运行（idleMs>0 记录照旧按 min(idleMs,cap) 收；idleMs<=0 记录按 cap 收）。装配点：index.ts:495 启动条件加 `|| hardCapMs>0`（disabled 日志改 `chrome_idle_reaper_cap_only`）；desired-hide-enforcer `startEnforcerIdleReaper` 同款透传（其 readLedgerFn 已过滤日常档 hidden|headless|undefined→hidden，域正确）。**已知残余（诚实声明）**：若全局 idle=0 且 cap 开、且此刻无任何 lasso 进程在世（server 不在 + 执守已账空自退 + 无新 launch），则无宿主执行硬顶——退化为 doctor/chrome-status 可观测（决议 B）+ 下次任一 launch/server 启动补收。此残余与渲染档 r2 修的「guardian 死后不补拉」同形但代价低一个量级（不收 ≠ 误杀；失败方向安全），记入 §8 观察项，不为此加常驻组件（红线）。

**A-5 豁免继承（证明义务，机械化）**

- 结构证明：cap 分支文本位置在 tick 循环既有两道 `continue` 之后——`if (rec.launchMode === "visible") continue;`（P1 红线）与 `if (rec.userTakenAt !== undefined) continue;`（BUG-03 B1/A1 契约「唯一关闭出口 = 用户自己关或显式 chrome-stop」）。用户拥有记录**永不到达** cap 判定 → 豁免语义字节级不变。谓词锚 = chrome-ledger.ts `isUserOwnedRecord`（r2-F1 机械锚）。
- 渲染档隔离证明：cap 谓词含 `rec.launchMode !== "render"` 门；render guardian 的 readLedgerFn 本就过滤只剩 render 记录 → 该宿主 cap 恒 no-op；server reaper 无过滤但谓词门挡住 render。`LASSO_RENDER_IDLE_MS` 及 render-launcher/render-guardian/render-flags 三文件**零改动**（INV tripwire 钉死，见 §7-16）。

**A-6 记录字段（新增，加法式）**：`LaunchedChromeRecord.hardCapExempt?: true`——CLI `--no-hard-cap` 时由 runLaunchChromeCli 落盘；readLedgerSync typeof 守卫 `=== true` 才认（非法/缺省 → false → 有顶，失效方向偏「有界」）。旧版本 lasso 读新台账按既有前向兼容丢弃未知字段 → 降级为「有顶」，同样安全。

### 决议 B：超龄可观测（不加 kill 面）

- **chrome-status**：`evidence.ledger_record` 增 `idleMs`；命中条件（台账在案 + 非用户拥有 + 非 render + 有效期限=cap 且 lastUse 龄 > 50% cap）时附 **`hard_cap_watch`** 咨询块（cap_ms / idle_for_ms / ratio）+ `user_paste_pack` 增一行（预期回收时刻、touch 续命法、用户本人 `chrome-stop --port N` 出口）。**classification 不变（仍 lasso_live）、AGENT_DIRECTIVES 不变（allowed_commands 恒空）**——B 面零新增 kill/指令面（INV-88 契约不破）。
- **doctor**：`nextStepTextForClassification` 的 `lasso_live` 分支在同一数据在场时追加同一行提示（chrome-status 单一真源，doctor 纯渲染——既有 A4 分工不变）。
- 12h 事故在 24h cap 下的新行为 = **12h 起持续 warn、24h 自动收**——「可发现可关闭」宪法闭环。

v1.24.0 版本史**显著位**（🔴 前缀，与 v1.21.0 默认值翻面同级排版）：

## 5. 向后兼容分析

- `idleMs>0` 且 ≤cap 的记录：行为零变化（effectiveMs=idleMs）——存量绝大多数路径不受影响。
- `idleMs>cap`（如显式配 7 天）：改为 cap 夹紧回收——理论 breaking，但「>24h 的单次 idle 阈值」无任何仓内文档/配方/测试倡导，changelog 一并覆盖。
- 台账 schema：加法式可选字段 + typeof 守卫，旧读新丢弃（降级有顶，安全）、新读旧缺省（cap 生效，即修复本体）。
- CLI：加法式旗标 `--no-hard-cap`；未知旗标忽略的 forward-compat 既有语义不破。
- 渲染档/消费方 media-gen：零代码改动（D3 + C 通知）。
- reaper 既有注入面（readLedgerFn/nowFn/stopFn/touchStatFn）：`hardCapMs` 为新可选项，缺省值=默认 24h——**注意**：既有单测若断言「idleMs=0 永不收」需同步改语义（见 §7-6/7-7 双向钉），缺省 hardCapMs 的取值实现时须保证测试可显式传 0 复现旧行为。
