# 调研：远端无头浏览器登录态接力（Mac ↔ Tailscale ↔ Linux），2026-10-17

> 需求（用户口述）：Linux 机（jd-cloud-linux，京东云，Tailscale 100.120.87.40）上跑 lasso 无头浏览器；遇登录态时构建一条内网转发路径，Mac 上点开→看到远端页面→亲手登录→远端浏览器拿到登录态继续执行。
> 方法：白盒四路——R1 业界方案普查（带源码/文档锚点）+ R2 Chromium/CDP 源码级机制核验 + R3 登录态转移路线深查 + 主循环本地受控实验（lasso render-chrome，Chrome 150）。全程零黑盒猜测，未验证项显式标注。

## 一、本地实验实证（主循环，Chrome 150 headless via render-chrome）

| 机制点 | 实测结论 |
|---|---|
| CDP 默认绑定 | `127.0.0.1` only（lsof）；**无旗标可改绑**（见 R2 §1：`--remote-debugging-address` M111 已移除）|
| `/json/version` `/json/list` | 正常；每页含 `webSocketDebuggerUrl`；`devtoolsFrontendUrl` 指向 appspot（国内不可达，**忽略**，用本地前端）|
| `/devtools/inspector.html` | **本地 200，Chrome 自带 DevTools 前端**；`http://<ip>:<port>/` 即可点选目标的 discovery 页 |
| Host 头 | 伪装非 localhost IP 访问 `/json` **放行**（与 R2 源码结论一致：IP 字面量过、域名拒）|
| 指纹 | render 档 UA 含 `HeadlessChrome/150`（登录风控相关）|

## 二、Chromium 源码级机制定谳（R2，锚点见其报告）

1. **「直接绑 Tailscale IP」不存在**：地址开关 M111 已删，转发层是硬需求（socat 0.0.0.0 / ssh -L / tailscale serve 三选）。
2. **Host 校验反直觉**：任意 IP 字面量放行、**域名拒绝**（含 MagicDNS 名）——`http://100.120.87.40:9222` ✓，`http://jd-cloud-linux:9222` ✗。
3. **WS Origin 校验（M111+）比对象是服务端绑定端点**（127.0.0.1:port）而非 Host 头 → 浏览器侧链路几乎都要 `--remote-allow-origins=<精确origin>`；**唯一零旗标通路 = Mac 侧 `ssh -L 9222:127.0.0.1:9222` 后浏览器访问 `http://127.0.0.1:9222`**（与绑定端点字面同源）。
4. **M136+ 品牌 Chrome 默认用户目录静默无视调试口**（抗 infostealer，无报错最难排查）→ Linux 侧用 **Chrome for Testing / Chromium** 或非默认 `--user-data-dir`。
5. **screencast 交互回路源码级成立**（点击/键盘/滚轮全通，页面内 `isTrusted=true`）；死穴：**CJK 输入**（前端只取 ASCII charCode）、本机密码管理器、剪贴板/文件框。
6. **`/json/new` 仅收 PUT**（GET 405）。

## 三、Google 登录兼容性定谳（R1+R2 交叉）

| 形态 | Google 系登录 |
|---|---|
| headless=new 投屏登录 | **高风险不推荐**（UA 虽同 headed，2023-24 社区实证仍持续被拦"This browser or app may not be secure"）|
| **Xvfb + headed + VNC/noVNC** | **可靠基线**（真浏览器真输入，社区公认可过）|
| 混合折中 | Xvfb+VNC **一次性人工登录**进持久 user-data-dir → 之后 headless 复用该目录（同机交接零转移损耗，R3 定谳最优变体）|
| cookie 转移 | 最差（异地+异指纹触发重验证；jd 数据中心 IP 使该风险为真）|

## 四、路线矩阵（本场景：jd-cloud-linux + Tailscale）

| 路线 | 机制 | 适用站点 | 成本 | 关键条件 |
|---|---|---|---|---|
| **L1 ssh -L + DevTools screencast（主推起步）** | Mac `ssh -L` → `http://127.0.0.1:9222` 点目标开 DevTools 投屏 | 除 Google 系绝大多数 | 零旗标零新组件 | Chrome for Testing + 非默认 profile；须开 DevTools 的 screencast（Device toolbar）|
| **L2 常驻转发 + origin 旗标** | socat 0.0.0.0 或 tailscale serve + `--remote-allow-origins=<精确>` | 同上 | 常驻可用 | serve 场景 Host 头是否被改写**待实测**（若透传 ts.net 域名会被 Chrome 500，退回 socat+IP）|
| **L3 Xvfb+headed+noVNC 容器（Google 专用道）** | selenium-debug/KasmVNC 式容器，或自装 Xvfb+x11vnc+novnc | Google 系/CF 严防站 | 一个容器 | 登录后 profile 落 volume，headless 可复用 |
| **L4 cookie 转移（补充）** | Mac 导出 → CDP `Storage.setCookies` 注入（httpOnly 可设；`__Host-` 不带 domain）| GitHub/一般 SaaS | 最低 | macOS→Linux 整 profile 拷贝**死路**（Keychain）；注意数据中心 IP 风控 |
| **L5 Steel OSS 自托管（产品化形态）** | Steel docker + lasso 透出 debugUrl + `tailscale serve` | 全部 | 一套 docker | R1 读码：lasso SteelChannel 今天**显式丢弃** websocketUrl——透出即得 |

## 五、lasso 落地形态候选（研究结论，非实施授权）

- 最小闭环 = L1 的文档化配方（KEY-GUIDE 增「远端登录接力」节：ssh -L 命令 + 127.0.0.1 访问 + screencast 开关 + CJK 死穴提示）。
- 产品化 = `live_view_url` 输出面：browse_headless/launch 系返回 CDP discovery URL（含转发层状态）；Steel 用户走 L5（一字段透出）。须过 INV-82 输入保护语义（viewer URL=持有即控制，等价 bear token）。
- Google 道 = L3 容器配方文档化（与 render 档并行验收隔离配方同格式）。

## 六、安全红线（R2 §4）

1. CDP 口=无鉴权 root 级（`Network.getAllCookies`/任意 JS）——暴露面必须锁 tailnet（Tailscale ACL 限定源设备）或仅 ssh -L（不产生全接口监听）。
2. `--remote-allow-origins` 用精确值，禁 `*`。
3. 持久 user-data-dir=登录态资产（密钥级保护，L2-02 健康观测面适用）。
4. tailscale funnel 不用（公网暴露无鉴权 debugUrl）。

## 七、上机验证清单（jd-cloud-linux 5 分钟实测项）

1. Chrome for Testing 起非默认 profile + 调试口；Mac `ssh -L` → `http://127.0.0.1:9222` 点开 DevTools → screencast 登录一个测试站 → Linux 侧 `Storage.getCookies` 验证登录态落位。
2. `tailscale serve` 前置时 Host 头行为（透传域名→500 则退 socat+IP 直连）。
3. screencast 输 ASCII 密码实操（CJK 死穴确认）；2FA 短码可行性。
4. Xvfb 容器内 Google 登录一次 → headless 复用同 user-data-dir 跑通（L3 混合折中验证）。

## 八、结论一句话

**你要的「构建转发路径→本机点击→亲手登录→远端继续跑」原生可行且业界已是成熟品类**——最短路径是「ssh -L + Chrome 自带 DevTools screencast」（零旗标、登录态天生落远端、无 cookie 同步问题）；Google 系站点走 Xvfb+headed 专用道；lasso 产品化距 Steel 式 live view 仅「一字段透出+一命令」。
