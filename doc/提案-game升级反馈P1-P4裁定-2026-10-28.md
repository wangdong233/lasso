| # | 反馈声称 | 核查结果（v2 定谳） |

| F1 | `browse_headless` 首调报 `Could not find Google Chrome executable for channel 'stable' at /opt/google/chrome/chrome` | ✅ 机理定谳：上游 chrome-devtools-mcp@1.7.0 的 cli middleware 在 channel/browserUrl/wsEndpoint/executablePath **四空时默认 `channel='stable'`**（cli-options.js:334-338）→ puppeteer 按系统装位找 stable → Debian 无 /opt 装位即死（@puppeteer/browsers launch.js 抛错串与原文逐字吻合） |

| F3 | README 声称 browse_headless 免预装（自动拉 bundled Chromium） | 🔴 **声明无条件为假**（v1 曾定谳「条件成立」，审查 A4-F-1 推翻 + 提案方否定重查亲验闭合）：middleware 四空恒置 channel='stable' → puppeteer-core 25.5.0 ChromeLauncher 在 channel 已设时**只走系统装位解析**（`chromeExecutable = channel ? executablePath(channel) : resolveExecutablePath(headless)`——cache 分支不可达）；即 postinstall 下载成功也无救。**v1.11 锁版迁移（0.3.0→1.7.0）引入的隐性回归**，dev 机全有系统 Chrome 从未暴露，需求方是首个净土受害者。README:252 该格须按「不成立」重写（非补条件） |

## 拒绝面登记（v2——防窄化重提，全部带结构性证据）

- **per-call executablePath**：锚= LASSO_PROXY 先例（浏览器基础设施配置一律 deployment 级 config 键、per-call 留给任务语义如 freshProfile 身份语义——A4-F-10 预答「freshProfile 就是 per-call 重生」反例）
- **env 透传（PUPPETEER_EXECUTABLE_PATH/CHROME_PATH）**：**结构性死路非选择性问题**——lasso 侧已全量透传 process.env（SubprocessManager:649-653），但上游 1.7.0 打包 puppeteer 为 core 形态（isPuppeteerCore:true、无 configuration resolver）、全 bundle 零处读该 env（三 tarball 白盒实证，C4-F-3/A4 亲验）
- **lasso 私有路径文件（chrome-path 探针）**= 第三配置机制（R-CI-02）
- **像素断言族（color_absent/present/region 一切包装）**：主锚= 颜色断言容差/色彩管理语义无法在工具层诚实定义 + 断言属调用方测试域；「新依赖」不成立（node:zlib 内建可解，如实注记）
- **Firefox/Gecko 驱动**：A.6 #3 新组件红线 + 需求方环境自证不解决其场景（无头 WebGL 不可用）
- **通用 chromeArg 透传 / 浏览器配置穿堂化**（C4 正向评估预警）：准入不变量=只收单一语义、spawn 期、有具体场景、与上游旗标 1:1 映射的键；拒通用透传与 per-call 语义
