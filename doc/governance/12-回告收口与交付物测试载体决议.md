## 裁决四（expect-poll 稳定化）：时序语义测虚拟时间，不测机器速度

**回告**（§14 遗留时序 flake）：`elapsed < 80ms` 墙钟断言在全量并发压机时 141ms 红、
单跑绿。根因=断言设计：墙钟反映机器负载（timer 饥饿下 sleep(1) 实际 130ms+），
任何贴边阈值都必红——放宽阈值只调小 flake 概率，不消除。

**方案**（commit e240b72）：vi.useFakeTimers + 逐 1ms advanceTimersByTimeAsync，
断言改 **poll 步数判别**（步数 = deadline/interval 的函数，零机器依赖）：
- timeout_ms=5 用例：settle ≤10 步，判别面 <100 步（误用 default 100ms ⇒ ~100 步）；
- defaultTimeoutMs=10 用例：settle ≤15 步，50 步上限外未 settle 即红（防忽略 opts
  回潮到 DEFAULT_TIMEOUT_MS=5000）。

**阈值依据**：步数判别面 = 两个候选 deadline 之比（100/5=20 倍），不是拍脑袋常数。
**CI 重试语义**：确定性化后**不加** vitest retry——retry 只救不可消除的环境竞态，
这里已消除；加了会掩盖真回归（业界共识：retry 是最后手段不是时序测试的替代设计）。
**flaky 标注**：不标——vitest 2 无该注解语义，且标注=承认不可修，与事实不符。
**突变自证**：反转 timeout 优先级 → 用例当场红；还原 → 43/43 绿（判别力保持）。

## 裁决五（门禁固化）：显式计数断言，不押 pipefail

**教训**（§14）：vitest 输出经 `| tail` 管道，shell 拿到的是 tail 的退出码（恒 0），
全量 1 failed 被掩掉——判绿必须读 "Test Files" 汇总行。

**评估**：`set -o pipefail` 进 npm script 不可靠——npm script-shell=/bin/sh
（macOS bash-sh 模式 / Linux CI 或为 dash），pipefail 非 POSIX；且 pipefail 救不了
「人自己的管道」（人在 shell 里接 | tail 时，npm script 内部的 pipefail 管不到）。

**处置**（commit 1d2720d）：`scripts/gate.mjs` + `npm run gate`——
- 双源判绿：vitest 退出码 AND 汇总行显式计数断言（failed===0；spawnSync 捕获输出，
  脚本内部零管道）；
- 终局裁定块（GATE GREEN/RED + 各门 ✓/✗ + 汇总行原文）永远在输出末尾——人再接
  `| tail` 也看得见终局（这是对「人肉管道」的兜底：挡不住管道，但让终局藏不住）；
- 门：build / vitest run / check-invariants / check-readme-sync 四面。
README 不文档化（用户向内容守则：技术内部不进 README）。
