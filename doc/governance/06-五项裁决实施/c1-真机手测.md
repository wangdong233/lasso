## 1. RTE（contenteditable）确认

| 步骤 | 操作 | 预期 |
|---|---|---|
| 1.1 | 本机 Chrome `--remote-debugging-port=9222` 打开任一带富文本编辑器的页面（如 notion.so 草稿页 / duckduckgo.com 的 contenteditable demo） | — |
| 1.2 | CC 发：`browse_logged_in(url="<该页>", action="navigate")` 后跟 steps：`[{action:"click", selectors:{click:"<编辑器区任意 uid>"}}]` | CC 回合内弹 Lasso 确认表单：message 含 `rte` + evidence 片段；单选「继续执行 / 跳过本步 / 终止」 |
| 1.3 | 选「继续执行」提交 | 链继续：click 步执行，`outcome=worked`，无 `stopped_at`；lasso 日志 `evt=high_risk_elicited_continue` |
| 1.4 | 重跑 1.2，选「跳过本步」或「终止」 | 现行行为：`outcome=didnt` + `manual_abort` + `error="high_risk_pattern:rte"`；日志 `evt=high_risk_elicited_blocked` |
| 1.5 | 重跑 1.2，**不响应**（等 120s） | 超时 → 同 1.4（didnt + manual_abort）；日志 `evt=high_risk_elicit_error`（RequestTimeout） |
| 1.6 | 重跑 1.2 两次连续命中均选「继续执行」 | **每次都弹**（accept 无记忆，无跨步授权缓存） |

## 通过判据

- 场景 0：零弹窗 + v1.16 byte-identical（降级红线，真机复现单元测钉死的行为）。
- 场景 1-3：三分支（continue/skip|abort/timeout）行为与单元测映射一致；连续命中无缓存。
- 三个 pattern 场景至少各跑一次「继续执行」+ 一次「终止」。
- 全程 `rust-helper/` 零改动；不触碰 cookie 路径（INV-52 不受影响——elicitation 只在 gate 命中后介入）。

## 已知边界（文档化，不修）

- `skip` 与 `abort` 在当前 gate 语义下同为「维持 blocked」（gate 只有放行/拦截两态；「跳过单步继续链」需 StepEngine 语义扩展，parse24 §6.1 定案不进本轮）。
- 表单渲染样式由 CC 客户端决定（enumNames「继续执行/跳过本步/终止」是否展示为下拉/单选取决于客户端实现）。
- elicitation 与 CC 权限弹窗是两层：CC 自身的工具批准弹窗照旧先于/并行于本确认。
