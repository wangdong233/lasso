# 方向 B：CC 控制整台计算机 · 桌面/GUI 全景（02）

> 目标：CC 能像人一样控制整台计算机（GUI/桌面），从而完成非常复杂的任务。
> 核心现实：**CC 自己内置了 computer use，但它不能后台无头**；要真无人值守，得用独立的 Anthropic Computer Use API + Docker，但官方承认它慢且会出错。**确定性无视觉路线（macOS AXAPI）最稳但需自建**。

---

## 0. CC 自己的工具选择优先级（先理解这个）

CC 想操作一个 app/服务时，会按以下优先级选工具【验证，[code.claude.com/docs/en/desktop](https://code.claude.com/docs/en/desktop)】：

```
connectors（MCP 连接器）  >  Bash  >  Claude in Chrome  >  computer use（兜底）
```

> 「Computer use is the **broadest and slowest**. It tries the most precise tool first.」
> 「Screen control is reserved for things nothing else can reach, like **native apps, hardware control panels, mobile simulators, or proprietary tools without an API**.」

**含义**：computer use 是 CC 的**最后兜底**。能用 MCP 连接器、Bash、浏览器解决的，CC 不会动用 computer use。只有遇到「没有 API 的原生 app / 硬件面板 / 移动模拟器 / 专有工具」时才启用。

---

## 1. CC 内置 computer-use MCP（开箱即用，但不能无头）

CC Desktop 自带一个名为 `computer-use` 的内置 MCP server【验证，[code.claude.com/docs/en/computer-use](https://code.claude.com/docs/en/computer-use)】。

**怎么开**：
- 默认**关闭**，需在 Settings 里手动 Enable（CLI 走 `/mcp` 面板）。
- macOS 需授予 **Accessibility + Screen Recording** 权限。

**致命限制（决定它能否满足你的目标）**：
| 限制 | 说明 |
|---|---|
| ❌ **不能后台无头** | 仅交互式会话，**不支持 `claude -p`**。headless CLI 下权限提示会终止进程。 |
| 🪟 **运行时隐藏其它窗口** | 「while Claude is working, your other windows are hidden so it interacts with only the approved app」——只与已批准的前台 app 交互。 |
| 🍎 **平台门禁** | 仅 macOS CLI；Windows 仅 Desktop app；**无 Linux**。 |
| 💳 **套餐门禁** | 需 **Pro/Max plan**；需 claude.ai 鉴权；**不支持 Bedrock/Vertex/Foundry**。 |
| 🚫 **不支持 Team/Enterprise** | |

**结论**：CC 内置 computer use **满足不了「后台无头桌面控制」的目标**。它适合「你坐在电脑前，让 Claude 帮你操作前台 app」的交互式场景。

## 2. Anthropic Computer Use API（独立产品，可真无头）⭐ 无人值守首选

这是 **API 产品**，不是 CC 内置功能——你需要自己写代码调用它【验证，[platform.claude.com/docs/.../computer-use-tool](https://platform.claude.com/docs/en/agents-and-tools/tool-use/computer-use-tool)】。

### 怎么工作
- 通过 Messages API 的 tool-use 接口 + **beta header** 调用：
  - `computer-use-2025-11-24`：用于 Claude Sonnet 5、Opus 4.8/4.7/4.6、Sonnet 4.6、Opus 4.5。
  - `computer-use-2025-01-24`：旧（Sonnet 4.5/Haiku 4.5/Opus 4.1，deprecated）。
- Tool type：`computer_20251124`（新，支持 zoom）/ `computer_20250124`（基础）。
- 动作：screenshot、left_click、type、key、mouse_move、scroll、drag、right_click、double_click、triple_click、hold_key、wait、zoom。
- **client-side tool**：Claude 只下发 `tool_use`，**截图/鼠标/键盘由你的代码执行**。
- **agent loop**：请求 → 你执行 → 返回 `tool_result`（截图）→ Claude 决定下一步 → 重复。
- **坐标反算**：API 把截图压缩到 1568px（旧模型）或 2576px（Sonnet 5/Opus 4.8/4.7）长边；Claude 返回的坐标是压缩后的，**你的代码要反算回真实屏坐标**。

### 为什么能满足「后台无头」⭐
官方 reference 实现**全部跑在 Docker 容器内**，无需物理显示器【验证】：
- **Xvfb** 虚拟 X11 显示 + **Mutter** 窗口管理器 + **Tint2** 面板。
- 预装 Firefox-ESR / LibreOffice / gedit / xterm / pcmanfm / xpdf / galculator 等。
- 通过 **x11vnc / noVNC** 提供远程查看（可选）。
- Dockerfile：`FROM ubuntu:22.04`，[anthropic-quickstarts/computer-use-demo](https://github.com/anthropics/anthropic-quickstarts/tree/main/computer-use-demo)。

> 这是「CC 完成『后台无头桌面控制』」**可落地的少数方案之一**——用 Docker 起一个虚拟桌面，让 Claude 通过截图驱动它，全程无头。

### 官方承认的局限（重要，别当主力）
- **延迟慢于人类**：「The current computer use latency for human-AI interactions might be too slow compared to regular human-directed computer actions.」只建议用于「speed isn't critical」的场景，如**背景信息采集、自动化测试**等可信环境。
- **会幻觉坐标**：「Claude might make mistakes or hallucinate when outputting specific coordinates.」
- **小众应用 / 多应用并行可靠性下降**：「reliability might be lower when interacting with niche applications or multiple applications at once.」

> **落地姿态**：把 Computer Use API 当**兜底/夜间批处理/可信环境测试**，不要当实时主力。

### 定价注意
基础 tool use 定价 + 每个 tool 定义约 735 tokens + system prompt 额外 466–499 tokens + **每张截图的 vision 定价**。截图 loop 烧钱，控制好步数。

**装机步骤**：见 [04-CC集成操作手册.md](04-CC集成操作手册.md#anthropic-computer-use-api)。

## 3. OmniParser V2（微软）— 模型无关的屏幕解析层

[OmniParser](https://github.com/microsoft/OmniParser)，25k+ stars，**CC-BY-4.0**【验证，[MS Research 文章](https://www.microsoft.com/en-us/research/articles/omniparser-v2-turning-any-llm-into-a-computer-use-agent/)】。

**定位**：不是完整 agent，而是一个**把任意通用 LLM 变成 GUI agent 的「屏幕解析（grounding）层」**——模型无关。
- 把截图从像素空间「**tokenize**」成结构化的可交互元素，LLM 据此做**检索式下一步动作预测**。
- **V2 通过缩小 icon-caption 模型输入图，把推理延迟相对 V1 降低 60%**（A100 上 0.6s/帧，4090 上 0.8s/帧）。
- 提升小元素检测精度（ScreenSpot Pro 39.5%——注意：这个数字现在已不是 SOTA，Claude Opus 在该榜约 87.9%，见 caveats #3）。

**怎么用**：作为你**自建 vision 桌面 agent 的前置 grounding 模块**——OmniParser 负责把屏幕解析成元素，你的 LLM（可以是本地/任意）负责决策。适合不想绑死 Anthropic CU API、想用自己模型栈的场景。

## 4. UFO（微软）— Windows 专用 UI agent

[UFO](https://github.com/microsoft/UFO)，NAACL 2025 论文【验证，[MS Research](https://www.microsoft.com/en-us/research/publication/ufo-a-ui-focused-agent-for-windows-os-interaction/)｜[arXiv 2402.07939](https://arxiv.org/abs/2402.07939)】。

**定位**：**首个专为 Windows OS 任务完成设计的 UI agent**（区别于 Anthropic CU 等跨平台截图方案）。

**架构**：
- **GPT-Vision 驱动的双 agent 框架**：AppAgent（选 app）+ ActAgent（在 app 内操作）。
- 同时消费 **Windows UI Automation (UIA) 可访问性树**与 GUI 信息——不只是看截图，还读 UIA 树。
- 可跨多应用完成任务。
- **control interaction module 实现「无需人工干预的动作 grounding」**——从自然语言命令全自动执行。
- 项目已演进到 UFO² / UFO³。

**限制**：
- ❌ **非 headless**：控制可见的 Windows GUI，需要 Windows + GPT-Vision API。
- 仅 Windows。

**适合**：Windows 桌面无人值守（但需有 GUI 会话，比如 RDP 登录着）、跨多个 Windows 应用的复杂任务。

## 5. macOS 无视觉路线：AXAPI / Accessibility / AppleScript（确定性、可无头）⚠️ 未本轮深验证

这条路线**最契合「高效准确」**——不靠视觉、不靠截图、零坐标幻觉、可无头，但**需要自己写适配**，本轮调研未找到成熟的开箱 MCP 方案，以下为通识 + 方向指引【通识】：

**核心机制**：
- macOS 的 **Accessibility（AXAPI）** 暴露了完整的 UI 元素树（菜单、按钮、文本框），可通过程序读取和操作，**不需要截图、不需要坐标**。
- 操作手段：**AppleScript**（高层，控制支持 Apple Events 的 app）、**Accessibility API**（底层，遍历/操作任意 UI 元素）、**`cliclick` / `screencapture`**（兜底的鼠标键盘/截图）。
- Python 生态：`pyautogui`（鼠标键盘）、`atomacos` / `ApplicationServices`（AXAPI）。
- macOS Shortcuts / Automator 也可脚本化。

**为什么值得**：
- **确定性**：点的是「按钮 X」而不是「坐标 (340, 220)」，不会幻觉。
- **可无头**：只要 app 能在用户会话里跑（或通过 launchd / SSH 触发 AppleScript），不需要可见 GUI。
- **省 token**：操作结构化 UI 树，不需要把截图灌进 LLM。

**已知坑（通识）**：
- **每个 app 的 AXAPI 暴露质量不同**——有些 app（尤其 Electron/自绘）的可访问性很差。
- 需要 Accessibility 权限。
- **跨 app 协调复杂**，要自己写状态机。
- 没有像 browser-use 那样的成熟「agent 框架」，得自己用 Agent SDK + custom tool 拼。

**落地建议**：用 **Claude Agent SDK + custom tool**（包装 atomacos/AppleScript）做一个「macOS 确定性 agent」。对**固定工作流**（每次操作一样的几个 app）这是最优解；对**开放式任意任务**才需要 vision。

> 这条路线本调研未深入验证具体成熟度，列为本调研的「开放问题」之一，建议作为后续重点深挖方向。

## 7. 方向 B 选型小结

| 你的场景 | 选这个 |
|---|---|
| macOS 交互式、你坐电脑前 | **CC 内置 computer-use**（Settings 开启） |
| **必须无人值守 / 后台无头** | **Anthropic Computer Use API + Docker (Xvfb)** |
| Windows 桌面、跨 app | **UFO**（UIA + GPT-Vision 双 agent） |
| 想用自己模型栈做 vision agent | **OmniParser V2** 做 grounding 层 + 你的 LLM |
| **macOS 固定工作流、要确定性零幻觉** | **AXAPI / AppleScript 自建**（Agent SDK + custom tool）⚠️ 需自建 |

> 装机步骤见 [04-CC集成操作手册.md](04-CC集成操作手册.md)。
