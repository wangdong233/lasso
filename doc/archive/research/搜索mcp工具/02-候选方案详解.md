# 02 · 候选方案详解

> 7 个免费/部分免费方案的逐一剖析 + 3 个付费参考方案。每份含：定位、免费模型、Key 要求、中文、稳定性、返回质量、本机友好度、核验状态、链接、适用人群、优劣点。

**核验标记说明**：`3-0` = 三票全通过；`2-1` = 两票通过一票反对（有分歧但成立）；`medium` = 单源证据，需谨慎。

## 🥇 1. One Search MCP · `yokingma/one-search-mcp`

**定位**：9 后端可热切换的多源聚合 MCP，是当前调研中**唯一原生支持中文**的免费方案。

| 维度 | 详情 |
|---|---|
| **免费模型** | 🟢 `local` 与 `duckduckgo` 两个 provider 完全免费、无 Key |
| **Key 要求** | 仅 `local` / `duckduckgo` 不需要；`bing`/`tavily`/`google`/`zhipu`/`exa`/`bocha` 均需付费 Key |
| **中文** | ✅ **百度、搜狗**（`local` 模式经浏览器自动化）—— 差异化核心优势 |
| **稳定性** | ⭐⭐⭐⭐ local 模式复用已装浏览器，依赖浏览器进程稳定 |
| **返回质量** | 标准搜索结果（标题/URL/摘要），无全文抽取 |
| **本机友好** | ⭐⭐⭐⭐⭐ 自动检测 Chrome/Edge/Chromium/Chrome Canary，Windows 友好 |
| **核验状态** | `3-0` × 5（local 免费免费、ddg 免费、9 provider 聚合、provider 列表逐一确认） |
| **许可 / 活跃度** | MIT · TypeScript · 132 star · 最后推送 2026-07-03（活跃） |

**关键机制**：
- 环境变量 `SEARCH_PROVIDER` 热切换后端，默认 `local`。
- v1.1.0 起 Firecrawl 被移除，改用 `agent-browser`。
- 源码定义：`export type SearchProvider = 'searxng' \| 'duckduckgo' \| 'bing' \| 'tavily' \| 'google' \| 'zhipu' \| 'exa' \| 'bocha' \| 'local';`

**✅ 优点**：免费、无 Key、支持中文、多后端可升级（将来有 Key 可平滑切 zhipu/exa）。
**⚠️ 缺点**：`local` 模式要起浏览器进程（本机内存 ~94% 需留意）；纯英文场景 DDG 直连更轻。

**适用人群**：中文用户、想要"一个 MCP 覆盖所有后端"的人、本机已装浏览器的 Windows 用户。

📎 [GitHub](https://github.com/yokingma/one-search-mcp) · [Claude Marketplaces](https://claudemarketplaces.com/mcp/yokingma/one-search-mcp)

## 🥈 2. mcp-web-search · `tickernelz/mcp-web-search`

**定位**：真正零成本零 Key 的多源聚合，最大卖点是**三源自动 fallback**。

| 维度 | 详情 |
|---|---|
| **免费模型** | 🟢 完全免费，README 明文 "No paid API required" |
| **Key 要求** | 无（三家 provider 都不要） |
| **中文** | ❌ DDG/Bing/SearXNG 为主，中文召回无保障 |
| **稳定性** | ⭐⭐⭐⭐⭐ **三源自动 fallback 是核心优势** —— 任一源失败自动降级 |
| **返回质量** | 搜索结果 + `fallbackUsed` / `triedProviders` 字段，便于诊断 |
| **本机友好** | ⭐⭐⭐⭐⭐ 默认 DDG 无需浏览器，npx 一行起 |
| **核验状态** | `3-0` × 2（免费声明 + 多源 fallback 机制） |

**关键机制**：
- 默认 DuckDuckGo（无需浏览器）→ SearXNG（自建）→ Bing（Chrome+Puppeteer）。
- 输出 schema 显式暴露回源链：`DuckDuckGo → SearXNG → Bing` 等。
- npm 包 `@zhafron/mcp-web-search`，维护活跃（示例时间戳 2026 年）。

**✅ 优点**：免费、无 Key、fallback 设计抗单点故障、配置极简。
**⚠️ 缺点**：中文弱；Bing 回源需 Chrome+Puppeteer（较重，但非默认）。

**适用人群**：纯英文搜索、追求"装了就不操心"的稳定性、不想依赖浏览器进程。

📎 [GitHub](https://github.com/tickernelz/mcp-web-search)

## 🥉 3. Jina AI MCP · `jina-ai/MCP`

**定位**：远程托管、零运维、**返回质量全场最丰富**（19 个工具）。

| 维度 | 详情 |
|---|---|
| **免费模型** | 🟡 **部分免费**：全文阅读免 Key，搜索需免费 Key |
| **Key 要求** | `read_url` / `capture_screenshot_url` / `parallel_read_url` = **免 Key**（匿名 20 RPM，r.jina.ai）；`search_web` / `search_arxiv` / `search_images` = **需免费 Key**（s.jina.ai 匿名直接 block） |
| **中文** | ⭐⭐⭐ 阅读中文页面 OK，搜索中文无专项优化 |
| **稳定性** | ⭐⭐⭐⭐⭐ 远程托管，Jina 官方运维 |
| **返回质量** | ⭐⭐⭐⭐⭐ **全场最好** —— URL→Markdown 全文、截图、重排序、向量化、PDF 图表/公式抽取 |
| **本机友好** | ⭐⭐⭐⭐⭐ 远程 HTTP，本机零负担 |
| **核验状态** | `3-0` × 4 + `2-1` × 1（s.jina.ai 拒绝匿名） |

**关键机制**：
- Endpoint：`https://mcp.jina.ai/v1`（SSE 在 `mcp.jina.ai`）。
- 每个新 API Key 含 **1000 万免费 token**（⚠️ 据条款限**非商业**用途）。
- 19 个工具覆盖：搜索、全文阅读、截图、重排序（Reranker）、向量化、PDF 抽取。

**✅ 优点**：功能最全、远程零运维、免 Key 即可用阅读类工具。
**⚠️ 缺点**：搜索要 Key；匿名 20 RPM 限速；非商业条款。

**适用人群**：需要网页全文/截图/PDF 抽取的人、想要"兜底阅读器"的人、不想自建任何服务。

📎 [GitHub](https://github.com/jina-ai/MCP) · [Jina Reader](https://jina.ai/reader/)

## 4. Exa MCP

**定位**：接入摩擦最低 —— 远程 URL 免 Key 免费层，粘贴即用 <1 分钟。

| 维度 | 详情 |
|---|---|
| **免费模型** | 🟡 远程 URL 模式有免费层（~1000 req/月）；本地 npx/stdio 模式仍需 `EXA_API_KEY` |
| **Key 要求** | 远程 URL 模式 = 无；stdio 模式 = 需要 |
| **中文** | ❌ 无专项中文优化 |
| **稳定性** | ⭐⭐⭐ 有用户反馈"crashes frequently"（Reddit r/mcp） |
| **返回质量** | ⭐⭐⭐⭐ 语义搜索 + 结构化 JSON，为 agent 设计 |
| **本机友好** | ⭐⭐⭐⭐⭐ 远程 HTTP，零负担 |
| **核验状态** | `3-0`（免费层存在，多源佐证） |

**关键机制**：
- 远程 URL：`https://mcp.exa.ai/mcp`，免费层无需 Key。
- 高频使用触发 429；~1000 req/月。
- Exa 被多个来源称为"2026 年 agent 最常用的搜索 MCP"。

**✅ 优点**：接入最快、语义搜索质量好、为 agent 优化。
**⚠️ 缺点**：额度小、有稳定性反馈、中文弱。

**适用人群**：想最快跑通的人、英文 agent 搜索、低频使用。

📎 [Firecrawl 博客佐证](https://www.firecrawl.dev/blog/best-web-search-mcp) · [Exa 官方](https://x.com/ExaAILabs/status/1912223340812738845)

## 5. duckduckgo-mcp-server · `nickclyde/duckduckgo-mcp-server`

**定位**：最简单 —— 一行 `uvx` 启动，纯 DDG 后端。

| 维度 | 详情 |
|---|---|
| **免费模型** | 🟢 完全免费，MIT |
| **Key 要求** | 无（env 仅可选 `DDG_SAFE_SEARCH` / `DDG_REGION` / `DDG_SEARCH_BACKEND`） |
| **中文** | ❌ DDG 中文召回一般 |
| **稳定性** | ⭐⭐⭐ **已知 TLS 封锁隐患**（见下） |
| **返回质量** | ⭐⭐⭐⭐ `search` + `fetch_content`（分页，默认 8000 字符，清洗全文） |
| **本机友好** | ⭐⭐⭐⭐ Python 原生，uvx 一行 |
| **核验状态** | `3-0` × 2 + `2-1` × 1（TLS 封锁隐患） |

**⚠️ 关键稳定性隐患（维护者自披露，2-1 通过）**：
- `html.duckduckgo.com` 会基于 **TLS 指纹**封锁默认 `httpx` 客户端，**静默返回空 HTTP 202**（"no results"）。
- 解决：安装可选 `[browser]` extra（`curl_cffi`，模拟 Chrome 131 TLS 握手）。
- 当前默认 backend 已改为 `auto`（先 httpx，失败回落 curl）。
- **务必装 `[browser]` extra 才稳定**：`pipx install "duckduckgo-mcp-server[browser]"`。

**✅ 优点**：极简、纯免费、带全文抓取。
**⚠️ 缺点**：TLS 反爬对抗、中文弱、单源（DDG 挂了就没了，无 fallback）。

**适用人群**：想最简单起步的人、能接受装 browser extra 的人。

📎 [GitHub](https://github.com/nickclyde/duckduckgo-mcp-server)

## 6. whw23/searxng_http_mcp（自建 SearXNG · 自包含）

**定位**：SearXNG 打包进 Docker 镜像的自包含方案，聚合 200+ 引擎，**最稳定**。

| 维度 | 详情 |
|---|---|
| **免费模型** | 🟢 完全免费（SearXNG 本体聚合 200+ 引擎，官方称最多 279） |
| **Key 要求** | 无 |
| **中文** | ⭐⭐⭐⭐ SearXNG 可配百度/搜狗等中文引擎 |
| **稳定性** | ⭐⭐⭐⭐⭐ 自建 + 多引擎聚合，最抗封 |
| **返回质量** | ⭐⭐⭐⭐ 结构化 JSON（`/search?format=json`） |
| **本机友好** | ⭐⭐ **需 Docker**（本机未装，落地成本高） |
| **核验状态** | `3-0` × 4 + `2-1` × 1（免费定位） |

**部署方式**（三选一）：
- HTTP server
- Docker stdio（SearXNG 内置于镜像）
- uvx 独立运行（需 Python 3.14+ 与既有 SearXNG 实例，无需 Docker）

**⚠️ 许可**：MCP 代码 MIT，但 **SearXNG 本体是 AGPL-3.0**。

**✅ 优点**：最稳定、引擎最多、中文可配。
**⚠️ 缺点**：要 Docker（本机痛点）、AGPL 许可（商用注意）。

**适用人群**：有服务器的生产环境、追求极致稳定、可接受运维。

📎 [mcpservers.org](https://mcpservers.org/servers/whw23/searxng_http_mcp) · [GitHub](https://github.com/whw23/searxng_http_mcp)

## 7. ihor-sokoliuk/mcp-searxng（SearXNG · broker）

**定位**：轻量 broker，**必须**指向已存在的 SearXNG 实例。

| 维度 | 详情 |
|---|---|
| **免费模型** | 🟢 完全免费（但依赖既有 SearXNG 实例） |
| **Key 要求** | 无（仅需 `SEARXNG_URL`） |
| **中文** | ⭐⭐⭐⭐ 取决于后端 SearXNG 配置 |
| **稳定性** | ⭐⭐⭐⭐ 取决于后端实例 |
| **返回质量** | ⭐⭐⭐⭐ **额外带 `web_url_read` 全文阅读工具**（5 MiB 上限，分页/段落区间/章节过滤/标题提取） |
| **本机友好** | ⭐⭐ 需先有 SearXNG 实例（间接需 Docker） |
| **核验状态** | `3-0` × 3 |

**关键澄清**（被对抗核验强调）：
- 它**不是**搜索引擎，也**不能**作为 SearXNG 插件安装。
- 它只是 broker：通过 `SEARXNG_URL` 查询一个已存在的 SearXNG 实例。
- `SEARXNG_URL` 是唯一必需变量。

**✅ 优点**：轻、带全文阅读、可指向公共 SearXNG 实例（若你信任它）。
**⚠️ 缺点**：不自包含、依赖外部实例、公共实例可能限速/不稳定。

**适用人群**：已有 SearXNG 实例、或愿意用公共实例的人。

📎 [GitHub](https://github.com/ihor-sokoliuk/mcp-searxng) · [mcp.so](https://mcp.so/servers/mcp-searxng)
