## 四、选型逻辑（按你的两个目标）

### 目标 1：CC 高效准确、最好后台无头控制浏览器

```
第一步：能代码驱动吗？
├─ 能（页面有结构） → 走「外部代码驱动」路线
│   ├─ 要无头批量     → chrome-devtools-mcp --headless  ✅ 首选
│   ├─ 要本人登录态   → Claude in Chrome 扩展          ✅ 首选（非无头）
│   ├─ 长程复杂任务   → browser-use (skill install)    ✅ 首选
│   ├─ 复杂多变表单   → Skyvern
│   └─ 极致省 token   → Playwright CLI 包成 Skill
│
└─ 不能（Canvas/自绘/反爬） → 走「视觉」路线
    └─ Stagehand v3（CDP 直连，a11y tree 读页面）
```

**核心原则**：选「把页面状态写磁盘/转成代码」的方案，别选「把整页截图灌进上下文」的方案。

### 目标 2：CC 像人一样控制计算机

```
第一步：能用 MCP 连接器 / Bash / 浏览器解决吗？
├─ 能 → 用它们（CC 工具优先级：connectors > Bash > Claude in Chrome > computer use）
└─ 不能（原生 app / 硬件面板 / 无 API 专有工具） → 才用屏幕控制
    ├─ macOS、你坐电脑前、接受交互式 → CC 内置 computer-use（开箱）
    ├─ 必须无人值守/后台无头          → Anthropic CU API + Docker (Xvfb)  ✅
    ├─ Windows 桌面                   → UFO
    ├─ 要确定性零幻觉（macOS 固定流程）→ AXAPI/AppleScript 自建          ⚠️ 需自建
    └─ 自建 vision agent              → OmniParser V2 做 grounding + 你的 LLM
```

**核心原则**：computer use 是**兜底**，能用更精确的手段就别用它；要无人值守只能走 CU API + Docker 或自建无视觉路线。

## 五、给你的优先落地建议（按性价比排序）

结合你是 macOS 用户、有 Tauri/Rust 背景、追求高效准确：

1. **先装 chrome-devtools-mcp**（`claude mcp add chrome-devtools --scope user -- npx -y chrome-devtools-mcp@latest`）——覆盖 80% 后台无头浏览器任务，零学习成本。
2. **再装 Claude in Chrome 扩展**——需要本人登录态时零摩擦。
3. **复杂长程任务用 browser-use**（`browser-use skill install`）——Odysseys 实测最强。
4. **macOS 固定工作流自建 AXAPI MCP**——你的 Rust 背景正好用得上，做出来是确定性、零幻觉、可无头，长期性价比最高（这是本轮调研的空白区，也是潜在差异化项目方向）。
5. **无人值守桌面流水线**才上 Anthropic CU API + Docker——重，且慢且会出错，只做兜底/夜间批处理。
