## 0. CC 作为 MCP 客户端：配置基础

CC 支持把任意 MCP server 接进来当工具用【验证】。

### 配置文件
| 文件 | 用途 |
|---|---|
| `.mcp.json`（项目根） | 团队共享，可提交 VCS |
| `~/.claude.json` | 用户级 + 本地级（单文件含多 project 条目） |

### 三种 scope
| scope | 存储位置 | 可见范围 |
|---|---|---|
| `local`（默认） | `~/.claude.json` 该 project 下 | 仅本人 + 仅当前项目 |
| `project` | 项目根 `.mcp.json` | 所有 clone 队友 |
| `user` | `~/.claude.json` 顶层 `mcpServers` | 仅本人 + 所有项目 |

### 支持的 transport
`http`（streamable-http，推荐）/ `stdio`（本地进程）/ `ws`（WebSocket）/ `sse`（deprecated）

### 常用命令
```bash
claude mcp add --transport http  <name> <url>
claude mcp add --transport stdio <name> -- <command> [args...]
claude mcp add-json <name> '<json>'
claude mcp add-from-claude-desktop          # 从 Claude Desktop 导入（仅 macOS/WSL）
claude mcp list / claude mcp get <name> / claude mcp remove <name>
```

- 非 CLI 内还会读 `.mcp.json` 里的 `${VAR}` / `${VAR:-default}` 环境变量展开。
- `--mcp-config <file-or-json>` 可一次性传入（CI/脚本化）。
- 项目级 `.mcp.json` 首次加载会弹 workspace-trust 审批。
- **保留名（用户配置不能用）**：`workspace`、`claude-in-chrome`、`computer-use`、`Claude Preview`、`Claude Browser`。

## 1. Claude in Chrome（CC 原生，共享登录态）⭐

**这是 CC 自带的浏览器控制方案，最接近「寄生 agent」形态。**

### 装机
1. 装 Chrome 扩展：[Chrome Web Store · Claude](https://chromewebstore.google.com/detail/claude/fcoeoabgfenejglbffodgkkbkcdhcgfn)
2. 扩展里登录 Claude 账号，授权连接 Claude Code。
3. 在 CC 里它会以内置 `claude-in-chrome` MCP server 形式出现（保留名）。
4. CC 在浏览器任务上会**自动优先**使用它（如果已配置）。

**官方文档**：[code.claude.com/docs/en/chrome](https://code.claude.com/docs/en/chrome)｜支持页：[support.claude.com/.../12012173](https://support.claude.com/en/articles/12012173-get-started-with-claude-in-chrome)

⚠️ 限制：需要有头 Chrome（非无头）；扩展与 CC 的通信通道本轮未明确验证。

## 2. <a name="chrome-devtools-mcp"></a>chrome-devtools-mcp（方向 A 首选）

Google Chrome DevTools 团队项目【验证】。

### 装机（两条路径任选）
```bash
# 路径 1：CLI（推荐 user scope，所有项目可用）
claude mcp add chrome-devtools --scope user -- npx -y chrome-devtools-mcp@latest

# 路径 2：plugin marketplace
/plugin marketplace add ChromeDevTools/chrome-devtools-mcp
```

### 常用启动 flag
```bash
--headless              # 后台无头（无 UI）—— 命中「后台无头」目标
--slim                  # 精简工具集，降 token（只做基础浏览器任务时用）
--browser-url http://127.0.0.1:9222   # 复用已运行的 Chrome 实例（吃它的登录态）
--memoryDebugging       # 打开堆快照等内存工具（非默认）
--category-extensions   # 扩展管理类工具（非默认）
--experimentalVision    # 视觉实验工具（非默认）
```

> 默认工具数约 28–29，要拿完整 ~52 需开启上面几个非默认 flag。

### 拿到登录态的两种姿势
- **方式 A（推荐）**：先 `google-chrome --remote-debugging-port=9222` 启动并手动登录，再让 chrome-devtools-mcp 用 `--browser-url` 连上。
- **方式 B**：用 Claude in Chrome 扩展（更省事，但非无头）。
- ⚠️ 少数有反 WebDriver 检测的站点会拒登。

**源**：[ChromeDevTools/chrome-devtools-mcp](https://github.com/ChromeDevTools/chrome-devtools-mcp)｜[developer.chrome.com/blog/chrome-devtools-mcp](https://developer.chrome.com/blog/chrome-devtools-mcp)

## 3. <a name="browser-use"></a>browser-use（长程复杂 web 任务首选）

### 装机
```bash
browser-use skill install
```
它会把 markdown skill 写进 `~/.claude/skills/`（Claude Code）等助理目录，以 **skill + CLI 桥接**方式集成（不是 MCP server）。

### 用法
agent 只需粘贴一句安装 prompt 即可自动配置并指派浏览器任务。底层调用 Claude Opus 4.7。

**源**：[browser-use/browser-use](https://github.com/browser-use/browser-use)｜[docs.browser-use.com](https://docs.browser-use.com/open-source/browser-use-terminal)

> 注：browser-use 也有 MCP 集成路径，本手册聚焦 `skill install` 这条（更省 token）。

## 4. CC 内置 computer-use（macOS 交互式）

### 启用步骤
1. CC CLI 里 `/mcp` → 找到内置 `computer-use` → Enable。
2. macOS 系统设置里授予 CC：**辅助功能（Accessibility）+ 屏幕录制（Screen Recording）** 权限。
3. 仅交互式会话可用（**不支持 `claude -p`**）。

⚠️ 门禁：仅 macOS CLI / Windows 仅 Desktop app / 无 Linux；需 **Pro/Max** 套餐；claude.ai 鉴权（不支持 Bedrock/Vertex/Foundry）；不支持 Team/Enterprise；运行时隐藏其它窗口。

**源**：[code.claude.com/docs/en/computer-use](https://code.claude.com/docs/en/computer-use)

## 5. <a name="anthropic-computer-use-api"></a>Anthropic Computer Use API（真无头桌面）⭐

**这是 API 产品，要自己写代码。** 适合无人值守流水线。

### 跑官方 reference（最快上手）
```bash
# 官方 Docker 镜像（Ubuntu 22.04 + Xvfb + Mutter + Tint2 + 应用）
# 详见 repo
git clone https://github.com/anthropics/anthropic-quickstarts
cd anthropic-quickstarts/computer-use-demo
# 按 README 起 Docker（暴露 6080 noVNC / 8000 API / 5900 VNC 等）
```
- 容器内：Xvfb 虚拟显示 + Mutter 窗口管理 + 预装 Firefox-ESR/LibreOffice/gedit/xterm/pcmanfm。
- 通过 x11vnc/noVNC 远程查看（可选）。
- **全程无头**——无需物理显示器。

### 调用要点
- beta header：`computer-use-2025-11-24`（Sonnet 5 / Opus 4.8/4.7/4.6 / Sonnet 4.6 / Opus 4.5）。
- tool type：`computer_20251124`（支持 zoom）。
- agent loop：`请求 → 你的代码执行 screenshot/click/type → tool_result（截图）→ Claude 决定 → 重复`。
- **坐标反算**：API 把截图压到 1568px（旧）或 2576px（Sonnet 5/Opus 4.8/4.7）长边；Claude 返回的坐标要反算回真实屏坐标。

**源**：[platform.claude.com/docs/.../computer-use-tool](https://platform.claude.com/docs/en/agents-and-tools/tool-use/computer-use-tool)｜[anthropic-quickstarts/computer-use-demo](https://github.com/anthropics/anthropic-quickstarts/tree/main/computer-use-demo)

⚠️ 官方承认局限：延迟慢于人类、会幻觉坐标、小众/多 app 不可靠。当兜底/批处理，别当实时主力。

## 6. Playwright MCP / Playwright CLI（微软）

### 装 MCP（官方 quickstart 示例）
```bash
claude mcp add playwright -- npx -y @playwright/mcp@latest
```
**源**：[microsoft/playwright-mcp](https://github.com/microsoft/playwright-mcp)

### ⚠️ 但微软自己建议：改用 CLI 包成 Skill 省 ~4 倍 token
- Playwright MCP 10 步约 **114k tokens**；Playwright CLI（快照写磁盘）约 **27k**。
- 微软明确推荐：对 CC/Cursor/Copilot，**CLI-based workflow 暴露成 Skill 比 MCP 更省**。
- 机制：CLI 把快照（YAML）/截图（PNG）/日志写到磁盘，上下文只拿短文件路径。

> 如果你跑长程/批量任务，**优先把 Playwright 包成 Skill 而非用 MCP**。

## 8. CC 后台/无头运行（驱动 CC 本身）

CC 自己也能后台非交互运行【验证，[code.claude.com/docs/en/headless](https://code.claude.com/docs/en/headless)】：

```bash
claude -p "<prompt>"                          # 非交互一次性，--print 短形式
claude -p "..." --output-format json          # 结构化输出
claude --bare -p "..."                        # 跳过 hooks/skills/plugins/MCP/CLAUDE.md（CI 推荐）
claude -p "..." --mcp-config <file-or-json>   # 显式传 MCP server
claude -p "..." --allowedTools "Read,Edit,Bash" --permission-mode acceptEdits
claude --resume <session_id>                  # 续接 session
```

**关键限制**：
- `claude -p` 模式下 MCP OAuth 不可用（无 `/mcp` 面板）——需先在交互式 session 里 `/mcp` 授权。
- **computer use 明确不支持 `-p`**。
- 后台 Bash 任务在 `claude -p` 退出后约 5 秒被终止。
- piped stdin 上限 10MB。

### 用 Agent SDK 编程驱动（可做自己的 agent）
```python
# Python: claude-agent-sdk
from claude_agent_sdk import query, ClaudeAgentOptions
async for msg in query(
    prompt="Open example.com and describe what you see",
    options=ClaudeAgentOptions(
        mcp_servers={"playwright": {"command": "npx", "args": ["@playwright/mcp@latest"]}}
    ),
): ...
```
SDK 自带 agent loop + 内置工具（Read/Write/Edit/Bash/WebSearch/...）+ MCP 客户端。也可用 `@tool` 自定义工具包装 Playwright/pyautogui/atomacos。

**源**：[code.claude.com/docs/en/agent-sdk/overview](https://code.claude.com/docs/en/agent-sdk/overview)｜[agent-sdk/mcp](https://code.claude.com/docs/en/agent-sdk/mcp)｜[agent-sdk/custom-tools](https://code.claude.com/docs/en/agent-sdk/custom-tools)

## 9. hooks：把任意外部工具接进 CC

CC 的 hooks 是「胶水层」，能把外部浏览器/计算机控制工具接到 CC 的事件流上【验证，[code.claude.com/docs/en/hooks](https://code.claude.com/docs/en/hooks)】。

### 5 种 hook 类型
| 类型 | 能力 |
|---|---|
| `command` | 执行 shell 命令（stdin JSON、stdout/exit code 反馈） |
| `http` | POST 到 URL |
| `mcp_tool` | 调用已连接 MCP server 上的 tool ⭐ |
| `prompt` / `agent` | 用 LLM 评估 |

### 关键事件点
`PreToolUse`（可 allow/deny/改写 tool_input）｜`PostToolUse`（可注入 context/改写 tool_output）｜`Stop`/`SubagentStop`｜`SessionStart`｜`UserPromptSubmit`｜`FileChanged` 等。

### 能做 / 不能做
- ✅ 用 `mcp_tool` hook 在事件点调用任何已连 MCP server（含 Playwright/chrome-devtools-mcp/自建 browser server）。
- ✅ 用 `command` hook spawn 任意 shell（puppeteer/adb/AppleScript）。
- ✅ 用 `additionalContext` 把外部状态注入 Claude 上下文。
- ❌ hooks **本身不提供**浏览器/GUI primitive——必须借助 MCP server 或 shell。
- ❌ `SessionStart`/`Setup` 只支持 `command` 和 `mcp_tool`。
- ❌ hooks 运行无控制终端（`/dev/tty` 不可用）；`command` 默认超时 600s。

**含义**：想把「外部控制工具」优雅接进 CC 的事件流（而不是让 Claude 每次显式调工具），hooks + `mcp_tool` 是正道。
