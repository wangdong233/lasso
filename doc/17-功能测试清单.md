### 0.1 环境 / key 状态总表

### 0.2 测试执行纪律

1. **失败 → 先判定用例是否正确**：对照源码行为（本清单每条注明源码锚点）和 KEY-GUIDE.md，确认预期写对了才进入下一步。
2. **用例无误才修产品**：修产品前在结果表记录「用例判定结论」，避免把正确行为当 bug 改掉（例：127.0.0.1 被 SSRF 放行是设计行为，不是漏洞）。
3. **修后重测**：产品修复后必须重跑原用例 + 相邻用例（同模块至少 1 条），确认无回归。
4. 每条用例执行后回填「状态」列：`pending` → `pass` / `fail` / `blocked` / `waived(暂放)`。
5. 探测类前置（doctor 结果）先跑，用结论裁决后续条目，不重复探测。
