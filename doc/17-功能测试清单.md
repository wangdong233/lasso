### 0.2 测试执行纪律

1. **失败 → 先判定用例是否正确**：对照源码行为（本清单每条注明源码锚点）和 KEY-GUIDE.md，确认预期写对了才进入下一步。
2. **用例无误才修产品**：修产品前在结果表记录「用例判定结论」，避免把正确行为当 bug 改掉（例：127.0.0.1 被 SSRF 放行是设计行为，不是漏洞）。
3. **修后重测**：产品修复后必须重跑原用例 + 相邻用例（同模块至少 1 条），确认无回归。
4. 每条用例执行后回填「状态」列：`pending` → `pass` / `fail` / `blocked` / `waived(暂放)`。
5. 探测类前置（doctor 结果）先跑，用结论裁决后续条目，不重复探测。
6. **资源占用测于始、验于终（v1.9 新增）**：每个涉及浏览器/子进程的测试用例，执行时用 `test/helpers/resource-meter.ts` 测量 lasso 特征进程树（特征：`--user-data-dir=` 含 lasso / `chrome-devtools-mcp --disable-blink-features` / `dist/index.js`，含 ppid 后代闭包）的进程数 + RSS 总和 + CPU 时间：
   ```ts
   import { ResourceMeter } from "../helpers/resource-meter.js";
   const meter = new ResourceMeter();          // 生产环境直接 import 相对路径
   const before = meter.before();              // 基线（同时启动 peak 轮询）
   /* ...被测用例（browse / launch-chrome / server 生命周期）... */
   const peak  = meter.peak();                 // 期间峰值（count/RSS）
   const after = meter.after();                // 收尾采样（停止轮询）
   // 完毕验证释放：after 进程数 ≤ before 且 RSS 回基线（默认 10% + 50MB 容差）
   assert(meter.released(before, after));
   ```
   peak 数据记入用例结果表「资源」列（count/RSS before→peak→after 三元组）。released=false = 残留，必须在下一条清理前定位（v1.9 机制出口：等 idle 回收 / `lasso-mcp chrome-stop --all` / admin `tab_restore`；仍不回收则按第 7 条盘点）。
7. **面板收尾清残留**：每个测试面板（wave/子面板）结束前，盘点本面板自 spawn 的浏览器/tab 与 server 进程（`pgrep -f chrome-devtools-mcp`、`ps aux | grep "user-data-dir=.*lasso"`、9222-9230 端口占用），**先输出精确清单（含 ppid 归属判定），确认后再分批清理**——禁止一步式 `pgrep -f <子串> | xargs kill -9` 宽匹配批量击杀（2026-08-15 04:49 中断教训：宽匹配命令只能被整体拒绝，精确清单命令可安全放行）。lasso v1.9+ 优先用机制出口：`lasso-mcp chrome-stop --all` + admin `tab_restore` + 等 idle 自动回收。清理结果记入 wave summary「残留清理」小节（清理前后进程计数各一次，可用 resource-meter 采样）。

### 2.17 静默性（T-SILENCE，v1.17.2 增补）

> **来源**：doc/27-静默性全面审计（audit.md 白盒理论矩阵 + verify.md 真机实测矩阵 + fix.md 三修复 F-1/F-2/F-3）终版矩阵的正式回归化。**六维打扰面**沿用 doc/27 定义：①OS 焦点 ②窗口 ③Dock/cmd-tab ④音频 ⑤通知 ⑥资源。
> **断言方法底座**（全部可机械复跑，零人工目视）：
> - **frontmost 采样**：`osascript -e 'tell application "System Events" to get name of first application process whose frontmost is true'`（查询本身不改焦点；立即 + 1s 双采）；
> - **窗口计数**：`osascript -e 'tell application "System Events" to count windows of (first application process whose unix id is <pid>)'`（按 unix id 定向，永不按进程名）；
> - **Dock/cmd-tab 判据（ASN 断言法）**：`lsappinfo list` 解析——`type="Foreground"` 型 Chrome ASN = 有 Dock 图标 + cmd-tab 资格；`BackgroundOnly`/`UIElement` = 不可见。headless 实例的断言 = **Foreground 型 Chrome ASN 计数不增**（缺位断言法）；
> - **cmdline flag 断言**：`ps -o command= -p <pid>` 后 grep `--mute-audio` / `--no-startup-window`（活进程实证，非启动参数回显）；
> - **资源三采样**：`test/helpers/resource-meter.ts` 或 doc/27 `verify-data/probe.mjs` 的 chromiumTreeSum（按 `user-data-dir` 归属 + ppid 闭包）；
> - **进程残留**：`pgrep -f "user-data-dir=.*lasso"` + 与执行前预存 pid 清单做差集（预存进程零触碰纪律）。
> **执行纪律**：串行 + 用例间 2s 间隔；每条前置记录前台基线；结束清理零残留（chrome-stop / kill 自起 pid / 删临时 profile / 端口复核）；**预存进程（用户 Chrome / 其他会话 cdm）全数不碰**。执行记录：`doc/17-执行记录/silence-acceptance.md`（数据在 `silence-data/`）。
