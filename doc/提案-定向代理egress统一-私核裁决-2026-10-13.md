# 提案：定向代理（egress 统一与私核裁决）——飞轮工作流，2026-10-13

> 消费方输入（用户口述）：ClashX 未运行时，CC 会话经 lasso 的外网访问（google 搜索等）依然要通——lasso 利用 ClashX 的有效配置做动态定向代理；节点周期健康度（延迟+稳定性）→内部排名→按排名降级；连续三节点失败→全量重查（判定代理商/整体问题）。
> 工作流：用户指定的飞轮制——F1 多 agent 隔离分析 → F2 否定重查定真伪 → F3 简单架构+正向发展评估 → F4 测试用例先行 → F5 实施（待用户 GO 后另轮）。

## 〇、F0 侦察事实（主循环）

- ClashX Pro 正在运行（7890 混合口通 `generate_204`；9090 外部控制器 API 返回 Unauthorized=有 secret）。
- lasso 现状：`LASSO_PROXY`（config.ts:519，v1.11 T10）只喂 browse_headless `--proxy-server` + Steel `proxyUrl` + download 三引擎；**fetch_url/fetch_feed/wayback/search(serp/brave) 的 undici 层完全不消费代理**；fetch 出径已中心化于 `src/util/http-pool.ts`（INV-32 单点）。

## 一、F1 三路隔离分析（要点与锚点）

### A1 白盒·出径全景
- 单点接线面：http-pool.ts:29（每 origin 一 Agent）——fetch/feed/wayback/serp/brave 五路共用。
- browse_headed 零 proxy（v1.11 T10 只做 headless 的历史遗漏，HeadlessChannel.ts:158 范式可抄）。
- machine_mcp/VLM 走 McpClient.connectHttp（src/subprocess/McpClient.ts:219）→ SDK StreamableHTTPClientTransport——A1 判「无注入口，L 难度可能不可行」。
- logged_in 永不代理已有负向测试钉死（proxy-egress.spec.ts:133-172）；render-launcher.ts 是长驻进程生命周期模板（单飞锁/复用门/归属收尸）。
- 红线交互：SSRF 守卫在 URL 层自带 fresh DNS（ssrf-guard.ts:104,140）先于任何 dispatcher；TUN fake-ip 198.18.0.0/15 在 DEFAULT_ALLOW_RANGES（ssrf/defaults.ts:42-43）。

### A2 clash 生态·机制与约束
- **本机无独立 clash 核心**：ClashX Pro 将 clash-premium 以 Go 库编译进 47MB GUI 主程序；「发现式复用本机核心」落空。
- 真实订阅=~/.config/clash/ 下 3 份 yaml（节点内联含凭据；trojan×102 / vmess×17 / vmess×20；组=select+url-test+fallback）。9090 secret 不在 yaml（macOS UserDefaults 运行时注入）。
- 核心 API：GET /proxies、GET /proxies/:name/delay、PUT /proxies/:name（切节点）；mihomo 独有 GET /group/:name/delay（组测速）+ DELETE（清 fixed）。url-test/fallback/max-failed-times=排名/降级/熔断全可白嫖核心原生。
- 许可：原 clash 三仓已删库（404 实测）；mihomo main 分支 MIT（Meta 分支 GPL-3.0，双轨）。**公开 npm 包捆绑核心二进制不经济且有灰区。**
- Chrome 注入注意：`--proxy-server` 设定后 localhost 默认不绕过，须配 `--proxy-bypass-list`。

### A3 消费方·策略面
- 路由表：外网目标走代理；**CDP attach（9222-9224）/localhost:3000 new-api/SSRF 允许段绝不能进代理**（进隧道=功能自瘫+内网请求外泄给机场）。
- resolveEgress 单点建议：与 ssrfGuard 同调用位、同真源（私网/loopback→direct），堵 SSRF 旁路。
- charter 有条件适配五条件：只服务自身客户端/只听 loopback/永不改系统态与 ClashX/默认休眠+opt-in/用户核心在场附着优先。

## 二、F2 反方否定重查（十点裁决，全部实证）

|---|---|---|---|
| 1 | 私核 charter 越界 | **击穿** | lasso=公开实名 npm 包（MIT）：自动下载+运行翻墙核心+克隆含凭据订阅=包性质变「审查规避工具分发者」，opt-in 不改性质 |

| 3 | 频率质疑 | **击穿** | 实测本机 ClashX 常驻 16h+；主搜索源 machine_mcp=bigmodel.cn 国内直连无需代理 |

| 6 | machine/VLM「不可注入」 | **击穿（A1 事实错误）** | SDK 公开注入口：`fetch?: FetchLike`（streamableHttp.d.ts:79-81，「Custom fetch implementation used for all network requests」）+ requestInit 每请求展开；connectHttp 加可选参数即接线，实为 S/M 难度。主循环已亲自复核确认 |

## 三、F3 综合裁决

### 总裁决：**私核 NO-GO（公开包内）/ egress 统一 GO（瘦身 v1）**

**砍单（rejected-by-design，三支柱）**：
1. **性质面**：公开实名 npm 包内嵌「下载并运行翻墙核心+克隆凭据订阅」，包性质从「代理配置消费者」变「审查规避工具分发者」——供应链/法规/声誉三重暴露，opt-in 不改性质。
2. **频率/成本面**：ClashX 常驻（16h+ 实测）、machine_mcp 走国内直连、私核只覆盖窄缝；而排名/降级/熔断用户要的能力，**用户自己的 ClashX url-test/fallback 组每天原生在做**——lasso 不需要复制它，只需要在它不在场时把出路教给 agent。
3. **简单架构面**：私核=新进程治理+凭据加密+连接级 drain+下载矩阵+三分判决五块全要从零建（F2 #8/#9 证明 F1 方案在这两处不成立）；瘦身 v1=三个既有模式的一行级延伸。

**复活条件（若未来确需私核，全部不可妥协）**：仅限私有分支不进公开 npm；先立 governance 边界声明（13 号文 rejected-by-design 章节同款）再写码；凭据落盘加密对齐 INV-15 族；私核 controller 强制随机 secret+仅 loopback+allow-lan:false；连接级 drain 方案先行评审。

### 正向发展评估
- **加法**：3 个接缝（http-pool 代理注入 / connectHttp fetch 参数 / HeadedChannel flag）+ doctor 文案 + next_step 句式——零新模块、零新进程、零新端口、零新凭据面。
- **修债**：A1「machine/VLM 不可行」误判（实为 SDK 公开注入口）、headed 历史遗漏、http-pool 代理盲区、生效面文案不全四处存量债一次清。
- **砍 5 保 3**：私核引导/订阅克隆/健康排名/三分熔断/drain 五项砍——防过度工程连续第二次实证（bugs/15 砍6>加4 → 本次砍5>加3）。

## 四、v1 方案设计（组件级）

### 组件 1：http-pool 代理注入（fetch/feed/wayback/serp/brave 五路一次打通）
- `acquireHttpClient(origin)` 增可选代理参数：有代理→该 origin 的 Agent 换 `ProxyAgent`（经 download/engines/proxy.ts 既有 makeProxyDispatcher/normalizeProxyUrl）；无代理→现行为 byte-identical（INV-32 守卫改写，不是废除）。
- **池 key 变更**：key 从 origin 扩为 `origin|proxyUrl`——同 origin 不同代理不共享 Agent（修复 F2#5 的缓存永不清除盲区的一半）。
- **失效语义（显式契约）**：代理配置变更后，新请求按新 key 建 Agent；旧 Agent 不主动销毁（keep-alive 自然过期）——语义=「新请求新路，存量连接自然衰减」，写进 doctor 文案与 KEY-GUIDE。
- 代理解析源：**沿用 resolveProxy 三级链（LASSO_PROXY→HTTPS_PROXY→env off）**，不动 config.proxy 浏览器面语义（分叉是 README:432 明文承诺——F2#5 裁决：不收编，文档化即可）。

### 组件 2：McpClient.connectHttp 可选 fetch 注入（machine_mcp/VLM）
- connectHttp 加可选 `fetchImpl` 参数透传 SDK `fetch?: FetchLike`（d.ts:79-81）。
- 默认不传=现行为零变化；传=经组件 1 的池（带代理解析）。

### 组件 3：HeadedChannel 补 --proxy-server
- 与 HeadlessChannel.ts:158 同款（含 config.proxy 同源）；顺带核查两档 `--proxy-bypass-list` 对 `<-loopback>` 的需求（Chrome 默认不绕过 localhost——browse 到 127.0.0.1 目标的语义要在实施轮定并钉测试）。

### 组件 4：诚实信号与出路（errors-as-teaching 正式化）
- doctor `proxy_config` check 扩全生效面清单（七面接线+logged_in 例外+热生效语义）。
- 外网失败错误分类（fetch_failed:connect_timeout 等 BUG-08 E-2 族）next_step 增补：检测到 LASSO_PROXY 未设且 7890 探测无用户代理 → 提示「`open -a "ClashX Pro"` 或设 LASSO_PROXY=http://127.0.0.1:7890」。
- 严禁自动 spawn/下载任何代理进程（负向源码守卫钉死，见 F4-7）。

## 五、F4 测试用例设计（先行，实施前冻结）

1. **池 key 与隔离**：同 origin 不同代理值→不同 Agent；无代理→现 Map 行为 byte-identical（INV-32 改写守卫）。
2. **注入透传**：connectHttp 传 fetchImpl → SDK `_fetch` 被真用（mock 断言）；不传→默认 fetch（零行为变化）。
3. **headed flag**：args 含 `--proxy-server=`（抄 headless spec 范式）；logged_in 零 proxy 不变量复验（既有 proxy-egress.spec 全绿）。
4. **解析序**：三级链 LASSO_PROXY>HTTPS_PROXY>off 在 fetch 面的解析测试（对照 download 面同序）。
5. **doctor 文案**：生效面清单断言（七面+例外+热生效句）。
6. **next_step 句式**：外网失败错误含 ClashX 出路文本（errors-as-teaching 断言）。
7. **负向守卫（新 INV 候选）**：src 内禁 mihomo/clash spawn/download 形态（源码 grep 守卫，防私核借尸还魂）；禁读 ~/.config/clash（敏感面 R3 钉死）。
