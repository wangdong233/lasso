## 1. 裁决一：R2 生命周期持有者 = (c) detached 渲染执守进程

### 1.1 结论与论据

**定案 (c)**。三形态 8 轴对照（架构轮结论，本轮复核维持）：

| 轴 | (a) launchd 直管 | (b) 常驻 daemon | (c) detached 执守 |
|---|---|---|---|
| SIGKILL 免疫 | ✅ | ✅ | ✅（结构性：Chrome detached PPID=1 + 执守 detached + 台账落盘，三重独立） |
| idle 退场语义 | ❌ KeepAlive 与 idle 收割对冲（reap→秒级重拉循环） | ✅ | ✅ 执守内嵌既有 reaper 循环 |
| 生命周期权威唯一性 | ❌ launchd 成为第二权威（违反 R-CI-02；launchd 重拉的 Chrome 无台账记录会被 doctor 判孤儿） | ❌ daemon 内存态与磁盘台账双真源（R-INT-07 同源耦合面） | ✅ 台账仍是唯一权威 |
| 新增安装面 | ❌ plist 安装 + 版本管理未定项（对接说明 §五.3） | ❌ 常驻进程注册 | ✅ 零（ensure 顺手拉起） |
| 常驻足迹 | ✅ 少一个进程 | ❌ 违背本仓「账空自退」哲学（desired-hide-enforcer 已验证的反daemon 形态） | ✅ 账空 2 tick 自退 |
| 与既有机制复用 | ❌ 新管道 | ⚠️ 若按需 spawn 即退化成 (c) 多余的永驻性 | ✅ 100% 复用（reaper/ledger/stop/touch） |
| 失联自愈 | ✅ KeepAlive | ✅ | ✅ 每次 `--ensure` 复验补拉（消费方唯一入口即心跳源） |
| 复杂度/测试面 | ❌ 最大 | ❌ 大 | ✅ 最小（全部模式已在 hide-enforcer 实战验证） |

**关键解耦**：Chrome 持有者 =「无人」——detached + unref + `~/.cache/lasso/launched-chromes.json` 磁盘台账共有制（本仓既有模型，launch-chrome.ts:407-418 同款 spawn 形态）。执守进程不是持有者，只是**收割调度器**的宿主；消费方 / lasso server / 执守任一方死亡均不杀 Chrome。

### 1.2 执守机制细节（照 desired-hide-enforcer.ts 逐条复刻）

- **pidfile**：`~/.cache/lasso/render-guardian.json` `{pid, startedAt}`（env `LASSO_RENDER_GUARDIAN_PID_PATH` 覆盖，测试隔离）
- **cmdline 标记**：`render-guardian`（spawn argv 自带；复验防 pid 复用假阳性——pidfile 数字之外的结构证据）
- **执守体**：`node <dist>/index.js render-guardian`，detached + unref + stdio ignore；`hideEnforcerEntryPath()` 同款「dist 布局一级之隔」教训直接继承（`../index.js` 解析 + accessSync 诚实降级）
- **🔴 持活（r2 修订，独立进程生死线）**：`startChromeIdleReaper` 的调度 timer 是 `unref()`（chrome-idle-reaper.ts:192——为「server 进程内」形态设计，不阻 server 退出）；执守是**独立进程**，若照 §1.3 组合而不另持 ref'd handle，入口函数返回后事件循环即空 → **毫秒级退出，执守出生即死**。必须照 runHideEnforcerCli（desired-hide-enforcer.ts:229-238）既有解法持一个 **ref'd keep-alive** `setInterval(() => {}, 60_000)`；`onIdleExit`（账空自退）与 SIGTERM/SIGINT 统一 `clearInterval(keepAlive)` 后 `process.exit(0)`；主流程不裸 `process.exit`。函数级 DI 单测测不出进程真退——由 §8.1 集成测试 `render-guardian-process.spec.ts` 钉死
- **后到者让位**：并发双起时，入口自检 probe 发现前者即 exit 0
- **账空自退**：连续 2 tick 台账无 render 记录 → 清 interval + 退出（照 hide-enforcer exitWhenIdleTicks）
- **拉起时机（r2 修订：ensure 成功路径全分支）**：`render-chrome --ensure` 一切 exit 0 出口（fresh launch 记账成功后、**reused:true 直接返回前**、单飞锁败者轮询转正后）均调 `ensureRenderGuardianRunning()`——这是 §1.1「失联自愈 = 每次 --ensure 复验补拉」的落地条件。🔴 原案「仅记账成功后」对渲染档不等价于 hide-enforcer 的既有触发链（launch-chrome.ts:463，仅 fresh 路径）：日常档 hidden 默认 idle 0 不回收，enforcer 缺位只损失「复隐」可逆语义；渲染档默认 10min **必须**回收，guardian 一死（kill -9 / 机器事件）后续 ensure 全走 reused:true 永不补拉 → 无任何收割宿主 → Chrome + profile 无限期滞留（P0 泄漏形态复活）。probe = readFile + kill(0) + ps 三 syscall 级开销，guardian 在世时零 spawn。server 启动**不**拉执守（渲染档与 MCP server 生命周期零耦合 = R2 硬约束「--ensure 不依赖 server 存活」的反向对称）

### 1.3 执守体内部：内嵌既有 reaper，零第二套收割管道

执守体 = 入口让位自检 + 自写 pidfile + `startChromeIdleReaper()`（chrome-idle-reaper.ts 既有入口）+ 三个 DI + **ref'd keep-alive 持活**（§1.2 持活项；进程形状照 runHideEnforcerCli 整体复刻）：

| 参数 | 传值 | 说明 |
|---|---|---|
| `defaultIdleMs` | env `LASSO_RENDER_IDLE_MS`（默认 600_000） | 渲染档专属 idle 默认；≤0 = 该执守不收割（显式 opt-out，文档化） |
| `readLedgerFn` | `() => readLedgerSync().filter(r => r.launchMode === "render")` | **过滤 render 记录 = 零核心改动**（DI 注入既有的读面） |
| `stopFn` | 默认 `stopLaunchedChromes({port})` | 归属验证/树杀/删账/profile 清理 100% 走 chrome-stop 验证路径 |

唯一核心改动：`startChromeIdleReaper` 新增 **opt-in** 选项 `exitWhenLedgerEmptyTicks?: number`（连续 N tick `readLedgerFn()` 返回空 → 自停；不传 = 现行为不变，server 侧调用零影响）。配单测钉死默认路径不退。

**与 server 内 reaper 双跑**：server 存活且日常档 idle > 0 时，server reaper 也会看到 render 记录（per-record `idleMs` 生效）双覆盖——**有意保留**（幂等安全：`stopLaunchedChromes` 二次调用命中 already_dead / 台账已删；同 hide-enforcer「双执守最坏一次重复」性质）。执守的意义 = server 不在时的兜底收割宿主。

### 1.4 外部模式对照（调研轮 14 路来源蒸馏）

| 生态模式 | 形态 | 本案处置 | 启示与差异 |
|---|---|---|---|
| browserless v2 | 独立 daemon 持有浏览器；CONCURRENT/QUEUED/TIMEOUT 三旋钮；TIMEOUT = 会话最大寿命安全网 | **不采纳 daemon 形态** | 生态确实收敛「所有者服务持有、消费方只 attach」——**所有权移交 lasso 成立**；但 browserless 的常驻是为了多租户容量（并发/排队），单消费方单实例用不上（R7 范畴）。TIMEOUT 硬寿命上限明确不采纳（见 §9） |
| Playwright launchServer | BrowserServer 进程持有浏览器，客户端 connect/disconnect 不持有 | 部分采纳 | connect/disconnect 语义 = 消费方「归还 = disconnect 严禁 close()」契约的生态先例（对接说明 §一.5 的 close 陷阱是同一道理：close() 对共享实例下发 Browser.close 直接杀掉） |
| launchd 直管（KeepAlive） | macOS 原生监督 | **否决** | 三处硬坑：KeepAlive 与 idle 收割天然对冲；GUI 进程须绑用户 Aqua 登录会话；自守护违反 launchd 契约。若非用不可，KeepAlive 应守护小 daemon 而非 Chrome 本体——即退回 (b)/(c) 之争 |
| puppeteer#4322（detached PPID=1 先例） | 拉起进程退出、Chrome 过继 init | **采纳其正面对** | detached 本身是合法形态；其反面「zombie Chromium」（无治理的 detached）正是 media-gen P0 的镜像——**detached 必须配台账+reaper 才成立**，本案的 (c) 就是给 detached 补上治理面 |

**综合结论**：外部生态的「所有者服务」在本仓语境下落地为「**无人持有（detached）+ 磁盘台账 + 按需执守**」，而非新增常驻服务——这是 02 清单 R-CI-02（不引入第二套生命周期）与本仓「账空自退」哲学的共同要求。

## 2. 裁决二：旗标路线 = (b) 冻结快照手拼 CLI（零新 npm dep）

### 2.1 结论

消费方《对接实施说明》§一.4 给了两条路线（a: 依赖 puppeteer-core 同款 launch；b: 手拼 CLI）。**定案 (b)**，且旗标面**冻结为快照**而非运行时继承。

### 2.2 否决路线 (a)（puppeteer-core 依赖）的四条理由

1. **生命周期模型冲突**：puppeteer.launch() 的语义是「拉起进程在自身生命周期内持有浏览器」（默认 pipe 传输、handleSIG* 钩子族、close() 联动）。R2 要的是「拉起进程退出后 Chrome 独立存活」——用 (a) 是逆着库的生命周期假设工作，退出前的 pipe/信号面都要逐一拆除，拆除不净即泄漏（恰是本 P0 的病根同族）。
2. **版本耦合舞蹈**：(a) 的「零漂移」只在 lasso 与消费方 puppeteer major 严格同步时成立（消费方升 25→26，lasso 必须跟版才有意义）——这是把消费方的一个依赖变成双方的双份协调义务（R-INT-08 外部契约耦合的放大）。(b) 冻结后漂移变成**显式、经评审的动作**（重导出→diff→golden 验证）。
3. **INV-64 哲学与依赖面**：launcher 家族至今零 npm dep（node:* + 相对路径，机械化守卫）；为拉起一个二进制引入浏览器驱动包违反本仓已付成本建立的纯度。render-chrome 只需要「以确定参数 spawn 一个二进制 + TCP 探活」，这正是本仓最成熟的模式（launch-chrome 同款）。
4. **二进制路径单一真源**：手拼 CLI 复用 `chrome-paths.ts` 候选路径表（消费方 `channel:"chrome"` 的解析语义对齐），日常档/渲染档共用一套 Chrome 探测——(a) 会形成第二套探测路径。

### 2.3 冻结快照机制

- **单一真源**：`src/render/render-flags.ts` 导出 `RENDER_DETERMINISTIC_FLAGS`（8 条，逐字同序照抄消费方 `browser-pool.ts:86-95`：`--no-sandbox` / `--disable-gpu` / `--font-render-hinting=full` / `--force-color-profile=srgb` / `--run-all-compositor-stages-before-draw` / `--disable-background-timer-throttling` / `--disable-backgrounding-occluded-windows` / `--disable-renderer-backgrounding`）+ `--headless=new` + **puppeteer 注入面冻结项**（导出全集减去 per-instance 项后的稳定集，至少含 `--mute-audio`、`--hide-scrollbars`；Linux 条件项按平台守卫）。
- **来源注释（provenance）**：文件头注明「源 = media-gen-mcp browser-pool.ts DETERMINISTIC_FLAGS @ da7ffd3 + §一.4 导出脚本产物 @ puppeteer-core 25.3.0」+ 导出日期。
- **导出协议**：实施轮先在消费方仓 node_modules 上以 /tmp 临时脚本跑 §一.4 的 dump 脚本拿当前精确全集（勿入库），落 diff 进快照注释。该脚本一次性使用，**不是**运行时依赖。
- **同步 tripwire 测试**：`test/unit/render-flags.spec.ts` 将冻结清单与 `test/fixtures/render-flags-snapshot.txt` 逐字比对——任何无意改动（含顺序）先红。有意变更流程 = 重导出 + 更新 fixture + 消费方 golden 验证。
- **漂移终裁**：消费方 golden（`MEDIA_GEN_RENDER_MODE=attach npm test`，含 render-video-determinism byte-identical + check-render-output strict）是确定性不可让步项（需求 §三.2）——lasso 侧 CI 不跑消费方 golden，交付与升级时触发跑（对接说明 §一.3 命令）。

### 2.4 确定性边界的诚实声明

传输层差异（消费方 legacy 自管走 puppeteer 管道 vs 渲染档 TCP 9224 多消费方 attach）不影响渲染产物——像素与页面时钟不经过传输层（消费方文档已裁定，本案沿用）。`/json/version` 是 wsEndpoint 权威来源。

### 3.2 端口：9224 固定 + 冲突即 exit 3（R-INT-08 外部带查证记录）

选值前查证（R-INT-08 强制动作，需求文档勘误口径）：9222 = lasso launch-chrome 默认档；9223 = media-gen Flow provider CDP 惯例；**9224 = 空闲**。定案：
- 默认 9224，env `LASSO_RENDER_PORT` 覆盖（**测试隔离用**；单值覆盖不构成端口协商，冲突仍 exit 3——协商留 R7）
- 拉起前 TCP 探测：端口被占且无台账记录 → **exit 3**（stderr 提示先跑 `render-chrome doctor` 清孤儿）；不做自动换端口
- 命名常量 `RENDER_CDP_PORT_DEFAULT = 9224` + 注释交叉引用 9222/9223 占用（可审计产物）

### 3.3 touch 契约：复用既有跨仓库约定，禁新造命名

- touch 文件 = `~/.cache/lasso/chrome-touch-9224`（`chrome-touch.ts:32-39` 既有 `chromeTouchPath(port)` 直接产出；🔴 不新造 `render-chrome-*.touch` 之类——破坏 bug02 跨仓库契约且需新收割管道）
- ensure 输出 `touchPath` 字段下发绝对路径，消费方不硬编码
- 消费方义务（对接说明 §一.2）：渲染前后各 touch 一次 + 会话存续期每 ≤60s heartbeat；触碰失败 warning 不阻断
- lasso 义务：idle 判定 = `max(launchedAt, lasso touchMap, touch 文件 mtime)` 三源取 max（reaper 现结构原样适用，chrome-idle-reaper.ts:211-215）；CDP 断连只作参考不作依据
- ensure 成功时自 touch 一次（给宽限，`touchChromePort` 复用）

### 3.4 profile：每实例临时目录 + 三路径连带清理

- 命名 `~/.cache/lasso/render-chrome-profile-<ts>-<rand>`（固定可识别前缀；R-INT-08：查证 `~/.cache/lasso/` 内无同名占用带）
- **清理单点落在 chrome-stop**：`stopLaunchedChromes` / `stopLaunchedChromesSync` 处理 `launchMode==="render"` 记录时 `rmSync(profileDir)`（在归属验证/杀进程之后，best-effort 不影响退出路径）——CLI stop / reaper / 执守 / doctor 四条收割路径**自动继承**，零四处分支
- doctor 额外兜底陈年目录（3.9）

### 3.5 chrome-stop CLI 补 `--modes <m1,m2>` 旗标

现 CLI 仅 `--port N / --all`（parseChromeStopArgs，chrome-stop.ts:266-283），modes 只是 API 选项。补 `--modes` CSV 解析（值域 hidden|visible|render，非法值报错）+ help 文案；无 `--modes` 的 `--all` 语义 = 全停（含渲染档），属有意「全停」出口，文档化。需求验收 4 依赖此旗标。

### 3.6 ensure 契约（消费方 `JSON.parse(stdout)` 强依赖，逐条满足）

- **stdout 纯净性**：stdout 只一行 JSON；一切日志/警告走 stderr
- **字段**：`wsEndpoint`（取自 `http://127.0.0.1:<port>/json/version`）/ `port` / `startedAt`（与台账 launchedAt 同源）/ `reused`（true = 复用既有健康实例）/ `touchPath`
- **退出码全集**：`0` 成功；`2` Chrome 二进制不存在（chrome-paths 探测失败）；`3` 端口被非渲染档占用 / 既有渲染档不健康且重生失败；`4` 拉起超时（>20s）；`5` 内部错误；未列举非零 = 未知失败。台账写失败不改退出码（best-effort，与 chrome-ledger 容错一致）
- **幂等（r2 修订：reused 四条件门）**：`reused:true` 必须**四条件全过**——①台账有该 port 的 render 记录；②`aliveFn(rec.pid)` pid 探活在；③**归属验证** `verifyOwnership(rec.pid, rec.profileDir, psFn)`（chrome-stop.ts:78-93 既有导出原语：ps cmdline 含 `--user-data-dir=<profileDir>` 精确标记，尾部空白/行尾边界防前缀拼接）；④CDP `/json/version` 探活通过（wsEndpoint 即取自该响应）。🔴 原案两条件门（台账 + CDP 探活）有现实击穿面：`/json/version` 对**任何**监听 9224 的 Chrome 一律 200——渲染档 Chrome 崩溃/OOM 被杀后台账陈留（至下一次收割 tick 前不清）+ 第三方先行占 9224（手工 `chrome --remote-debugging-port=9224` 等）时，ensure 会把**他人实例**的 webSocketDebuggerUrl 以 `reused:true` 交付，消费方在无 8 条确定性旗标的 Chrome 上渲染全部产物，golden 静默漂移、零报警——本设计存在的根本理由（确定性保证）被静默击穿。③的 marker 恰好同时是确定性旗标归属的结构证据
- **收尸重拉（四条件任一失败）**：先 `stopLaunchedChromes({port})` 收尸（陈留记录命中 `already_dead` → 清账 + rmSync profile；pid 复用命中 `pid_reused_skipped` → 只清账，🔴 绝不杀非归属进程——「只杀验证通过的 pid」红线在此分支天然维持：外来 Chrome 的 pid 不在台账，永不进杀路径）→ 重走拉起；重拉前 TCP 探测发现 9224 被非渲染档占用 → **exit 3**（3.2 语义不变，无新退出码）
- **并发单飞**：launch 前 `~/.cache/lasso/render-launch-<port>.lock` 以 `wx` 独占创建（内容 `{pid, ts}`）；败者轮询台账 + CDP 健康至超时；持锁者 pid 已死且超陈化阈值 → 夺锁重试。不做 double-launch（与消费方现单飞锁同语义）
- **超时预算**：内部拉起 20s（Chrome spawn 实测 ~2.3s + CDP 探活，余量充足；消费方外层 25s / npx 兜底路径 90s 由消费方契约覆盖）
- **20s 预算与 npx 税的关系（诚实澄清）**：`render-chrome --ensure` 直接 spawn Chrome 二进制，不经 npx 解析；npx 冷启税只发生在消费方以 `npx -y lasso-mcp` 兜底解析 lasso 时（消费方已放宽该路径 90s）。lasso 内部的 cdp-mcp npx 税是另一问题，见《性能准确率优化裁决表》PERF-1
- **install-agent / uninstall-agent：不存在**（形态 (c) 下无此子命令；消费方不依赖，错误文案统一指 `--ensure`）

### 3.7 status / stop 契约与 renderSessions 诚实降级

- `--status` 恒 exit 0：`{running, port, pid?, wsEndpoint?, startedAt?, idleMs, lastUseAt?, renderSessions, touchPath}`；`idleMs` = `rec.idleMs ?? renderIdleDefault`；`lastUseAt` = max(launchedAt, touch 文件 mtime)（CLI 进程无 server touchMap，取可得两源）
- **`renderSessions` 裁决（显式偏差声明）**：实现为**当前打开的 page/target 数**（CDP `/json/list` 实时计数），非「累计渲染会话数」。理由：台账契约「增量仅两处既有字段」禁新字段，累计计数必须引入持久状态（新文件/新字段均违反最小面）；消费方对 status 仅人读自省、不强依赖该字段语义。若 R5/R7 出现真实审计需求再升级（届时随独占锁一并设计）
- `--stop` 幂等（不在运行也 exit 0），输出 `{"stopped":[{port,pid,action}]}`，`action ∈ killed|already_dead|pid_reused_skipped`（chrome-stop 现形状）；实现在 `stopLaunchedChromes({modes:["render"]})` 之上；执守随台账清空 2 tick 内自退，无需显式停

### 3.8 执守（见 §1.2/§1.3）

补充定案：执守调度周期沿用 `CHROME_IDLE_REAPER_INTERVAL_MS = 15s`（关窗最坏延迟 = idle + 15s，既有语义）；日志经注入 logFn 走 stderr 单行 JSON；**执守进程主体必须持 ref'd keep-alive interval（r2 修订，§1.2 持活项）——reaper timer 全 unref，独立进程不持活 = 出生即死，且函数级 DI 单测测不出（进程语义在单测边界外），由 §8.1 `render-guardian-process.spec.ts` 集成测试钉死**。

### 3.9 doctor（R4：`render-chrome doctor [--clean]`）

- **孤儿检测**：`ps -Axo command=` 过滤指纹对（`--run-all-compositor-stages-before-draw` **且** `--font-render-hinting=full` 同时命中——单旗标可能撞他家用法，成对 + profile 前缀三重证据）；命中进程若台账无对应记录且 `etime > 10min` → 孤儿。🔴 不以 `puppeteer_dev_chrome_profile` 判定（puppeteer 通用名，chrome-devtools-mcp 等他家用，会误伤——对接说明边界 3）
- **默认 dry-run**：只报告；`--clean` 才执行。清理动作 = 指纹对 + `--user-data-dir` 含 `render-chrome-profile-` 前缀**双重证据**命中才树杀 + `rmSync` 其 profile。这是全仓**唯一**不经台账归属验证的杀路径——窄化为 R4 显式设计（孤儿定义即无台账），双证据 + 10min 年龄线 + dry-run 默认三重护栏，测试钉死「真身 Chrome 零误伤」
- **陈年 profile**：`~/.cache/lasso/render-chrome-profile-*` 不被任何台账记录引用且 age > 24h → 报告 / `--clean` 删除（24h 线避免与拉起窗口竞态）
- **主 doctor（doctor.ts）**：本轮只加一条信息性检查（render 档在档状态 + 执守在世状态，warn 级不 fail）；孤儿/清理的唯一出口保持 `render-chrome doctor`（单一清理器，杜绝双清理器竞态——对接说明阶段 3 已裁决 media-gen 侧 selfcheck 退役对齐）

## 7. 非采纳项（rejected-by-design，R-CI-06 增量）

1. **launchd 直管（形态 a）**：KeepAlive×idle 对冲 / Aqua 会话绑定 / 第二生命周期权威违反 R-CI-02（§1.1）
2. **常驻 daemon（形态 b）**：违背账空自退哲学；daemon 内存态×磁盘台账双真源（R-INT-07 面）；按需 spawn 即退化 (c)
3. **puppeteer-core 依赖（旗标路线 a）**：四理由（§2.2）
4. **browserless 式 TIMEOUT 会话硬寿命上限**：render-video 单会话可超 10min（3600 帧上限），touch 心跳是活性真源，硬顶必误杀长渲染；容量/排队旋钮属 R7 多消费方范畴
5. **新造 touch 文件命名**：破坏 bug02 跨仓库契约（3.3）
6. **端口协商**：固定 9224 + exit 3 最小可行；真实多消费方并发需求出现再开（R7）
7. **台账新增 renderSessions 累计字段**：违反「增量仅两处既有字段」契约；status 用实时计数诚实降级（3.7）
8. **render 档接入 chrome-show/hide/desired-hide 状态机**：headless 无窗口语义（边界 6）
9. **`launch-chrome --render` 复用路径**：launch-chrome 深耦合日常档链（粘滞账/enforcer/登录墙状态机/隐藏保险丝），渲染档一个都不需要——独立子命令（需求 R1 补充已裁定，本案维持）
