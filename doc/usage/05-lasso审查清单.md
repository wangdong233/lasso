# lasso 项目审查清单（基于架构想法 01/02/03 定制，2026-10-13）

> 来源：用户指定「参考 01 思想 / 02 清单 / 03 通用审查清单，制定当前项目相关的审查清单」。
> 定位：**lasso 专属维度 = 通用清单之外的增量面**——02 的 R-INT/R-DEP/R-CI 等通用规则仍然全部适用（不重复抄录），本清单只补 lasso 作为「MCP server + 浏览器/桌面治理工具」特有的审查维度。
> 用法：飞轮 F3（简单架构+正向发展评估）环节逐项过；fresh 审查 agent 的指派清单含本文件。

## L 系：lasso 专属审查规则

### L-1 治理一致性（治理面 vs 交互面 vs 消费方发现面三层对齐）
| # | 规则 | 检测 | 级别 |
|---|---|---|---|
| L1-01 | 每个治理能力（launch/status/hide/touch…）在三层的每一层都有入口或明确指向：治理面有的能力，交互面（工具）与消费方文档（README/KEY-GUIDE/TROUBLESHOOTING）不得断链 | 能力清单×三层 grep 对照 | 🟡 |
| L1-02 | 能力断层裁定须走「诚实边界」而非静默：做不到的面要文档化（如 stream kind 的 SSRF 边界句式），不得假装守住 | INV 文本+description 对照 | 🟡 |
| L1-03 | 端口/实例等外部命名空间值禁单点假设（BUG-13 教训：治理面多端口/交互面 9222 单口） | 「唯一端口/唯一实例/唯一路径」类假设扫描 | 🟡 |

### L-2 进程与资源生命周期（幽灵/泄漏/健康三查）
| # | 规则 | 检测 | 级别 |
|---|---|---|---|
| L2-01 | 一切 lasso spawn 的进程/长驻资源必须有：台账登记 + 归属验证的 kill 路径 + 收敛出口（idle 帽/硬顶/收尾命令三选一以上） | spawn 点逐个对照台账/kill/收敛三件套 | 🔴 |
| L2-02 | 长驻豁免（idle-0/visible/never-kill）资源必须有**健康观测面**（doctor/admin 可见：资源占用/活跃度/异常态——chrome-status evidence.health_note 先例）——豁免不等于失明（BUG-15 教训） | doctor check 覆盖对照 | 🟡 |
| L2-03 | stdio/管道生命周期与宿主解耦设计要显式裁定（H1 文件化教训：禁 pipe 自毁形态）；跨重启存活须有 reconcile/收养路径 | spawn 形态审计 | 🔴 |
| L2-04 | 资源劣化（内存压力/缓存膨胀/句柄累积）要有「可感知出口」——agent 或用户能在劣化变成故障前看到信号 | doctor/admin 输出面审计 | 🟡 |

### L-3 消费方契约（外部接口的稳定性与可诊断性）
| # | 规则 | 检测 | 级别 |
|---|---|---|---|
| L3-01 | 工具 description 与行为**逐字一致**（truth spec 锚）；示例与 schema 键一致（闸 1d）；预算帽守卫在位 | 既有 truth spec 体系 | 🔴 |
| L3-02 | 错误信息自带可操作出路（errors-as-teaching）：端口/版本/环境态诊断线索（BUG-13 §7-2 句式） | 错误面抽样 | 🟡 |
| L3-03 | 运行时态配置（env/config）热生效语义要显式（支持/不支持都写明），禁「改了配置但运行中不生效」的暗坑 | 配置项×热生效语义对照 | 🟡 |
| L3-04 | check 名/工具名/字段名是消费方契约，禁随实施改（cdp_9222_logged_in C5 先例；INV-88 反向削弱禁令） | 契约名变更扫描 | 🔴 |

### L-4 红线复核（历史事故的机械化防复发）
| # | 规则 | 依据事故 | 级别 |
|---|---|---|---|
| L4-01 | 永不 kill 用户资产：杀路径唯一+四要素归属验证+INV 钉死 | 09-08 浏览器事故 | 🔴 |
| L4-02 | 永不代用户决定（自动 hide/自动重连/自动改道）：只提示+出路 | input_guard 哲学/INV-82 | 🔴 |
| L4-03 | 探针失败=证据不足而非空属性；空输出≠空属性 | 09-08 教训 | 🟡 |
| L4-04 | fresh 审查含变异验证（守卫真锚非摆设）+ 测试禁依赖宿主机器状态（mtime/~/Downloads 存在性等） | cc-status-dot/config-file.spec 教训 | 🟡 |

## 用法注记

- 🔴 = 硬闸（违反即阻断）；🟡 = 趋势闸（需校准语境）——与 02 §0.1 级别语义对齐。
- 与 03 的关系：03 的 §1 六维度/§2 六阶段/§3.4 sign-off 是**流程骨架**，本清单是 lasso 的**领域增量**——审查时两者并行（03 管怎么审，L 系管审什么特有面）。
- 维护：每收一个 bug 台账批次，检查本清单是否需要增补规则（飞轮自审环节的固定动作之一）。
