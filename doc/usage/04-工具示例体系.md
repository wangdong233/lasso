## A. 示例形态定案（分层放置）

### A.1 核心约束（决定一切的一条）

MCP tool 定义只有 `name + description + inputSchema(+annotations)`。**Anthropic 的 `input_examples` 是 API 出参特性，不是 MCP 能力**——MCP server 放了 CC 也看不见。所以示例只有四个可放置层，且每层成本模型不同：

| 层 | agent 可见性 | token 成本 | 适用内容 |
|---|---|---|---|
| **L1 description EXAMPLES 段** | 最高（CC 每会话装入全部工具描述） | **每次会话预付**，无论是否用到 | canonical 调用形态（一行 call shape） |
| **L2 schema `.describe()`** | 高（inputSchema 随工具列表渲染） | 预付，但按字段粒度、最省 | 枚举值表 / 字段语义短句 |
| **L3 错误 hint / next_step 内嵌** | 上下文最高（错的那一刻出现） | **零预付**，只在失败时付 | 正确形态的纠正片段（errors-as-teaching） |
| L4 README 消费方专节 | 对 agent ≈0（调用时不可见） | 不占 prompt | 人类深度模式（P2，非本批交付面） |

**定案：L1/L2/L3 三层分工，L4 只做人类副本。** 判据来自成本模型：能放到 L3 的不放 L1（错误恢复示例零预付）、能压缩成枚举表的不写成散文（L2 一行胜 L1 三行）、L1 只留「首次调用就要对」的 canonical 形态。

### A.2 示例格式正典

**一行 call shape**，不用完整 JSON payload：

```
browse_headless({url:"https://example.com", action:"extract", options:{extract_mode:"markdown"}})
```

理由：(1) token 成本约为完整 JSON 的 1/5；(2) 这是仓内已被验证的 house style——read_text 的示例（descriptions 与 continue_hint 双处同形）是唯一**从未产生过求助事故**的示例；(3) 与 `continue_hint` 运行时回显同构，agent 看到的两种示例形态一致。

### A.3 每工具给几个 + 预算

分层供给（tier 由考古事故驱动，不是版本新旧驱动）：

- **Tier-1（有已记录事故或属 v1.20→1.27 新面）**：browse_headless / browse_logged_in / browse_headed / screenshot / admin。每工具 **EXAMPLES 段 ≤5 行**（只数放置列标「EXAMPLES 段」的行；标「内联段落」的行不计行数、只计字符），本批 L1 增量 **≤180 tok ≈ ≤650 chars**（r1：原 ≤220 tok 与 fleet 帽 1,000 冲突——5×220=1,100>1,000；调低至 180 与原 BROWSE_HEADLESS 特例帽取齐为**通用帽**，5×180=900 + Tier-2 松量 100 = fleet 1,000，数字自洽）。
- **Tier-2（自明或无事故）**：fetch_url / wayback / fetch_feed / doctor / search_local / interact 三件套 / network / pdf / search / desktop。**本批 0-1 个**（仅当存在真实歧义点；无事故不发明示例——「示例不是发明是考古」）。

**硬预算（写进 truth spec，见 E）**：

| 指标 | 限额 |
|---|---|
| 单工具 EXAMPLES 段 | ≤5 行（只数「EXAMPLES 段」行；内联行不计） |
| 单工具 L1 增量（Tier-1 通用；原 headless 特例帽收编） | ≤180 tok ≈ ≤650 chars（法定 chars） |
| L1 fleet 总增量 | ≤1,000 tok ≈ ≤3,600 chars（= 5×180 满配 + 100 tok Tier-2 松量，自洽） |
| L2 fleet 总增量 | ≤600 tok ≈ ≤2,160 chars |
| L1+L2 合计 | ≤ +1,600 tok ≈ 5,760 chars（≈基线 +10% 封顶） |
| L3 | 不占预付预算；单条 hint ≤2 句 + ≤1 个 call shape 片段 |

注：`BROWSE_HEADLESS_DESCRIPTION` 已 3,229 tok 触膨胀红线，其增量受通用 650 chars 帽约束；**裁剪是另一个单主题，不混批**。

## C. 错误自描述升级（errors-as-teaching）

原则：**高频 didnt 类错误必须内嵌正确形态的可复制片段**；凡能从运行时真源（Set/Map）动态派生的枚举，一律动态派生——**drift-free by construction 优于 tested consistency**。

| 错误码 | 现状（已核） | 升级 | 真源 |
|---|---|---|---|
| `unknown_action:<action>` | **无 hint**（BrowseChannel.ts:865） | `hint: "unknown action '<action>'. Legal: " + [...this.actionDispatch.keys()].join("\|")` + 半句指路（current-page 三 action 可省 url） | actionDispatch Map keys（运行时派生，零漂移） |
| `url_required_for_action:<action>` | 有一行散文 hint（:450） | 追加 call shape 片段；action ∈ CURRENT_PAGE_ACTIONS 时改指 current-page 形态 | CURRENT_PAGE_ACTIONS Set 动态判 |
| `no_active_session:current_page_{screenshot,wait,evaluate}` | 散文已教正确形态（:888-905，质量高） | 追加紧凑恢复片段（如 `e.g. screenshot({url:"..."}) one-step, or navigate first then screenshot({})`）。**INV-95/bug09 锚定区：additive suffix，实施时核对既有断言是否 byte-exact** | 错误码族白名单 |
| `mcp_request_timeout` | **范本**（`(e.g. 300000)`，马拉松 P0 验证有效） | 不动 | — |
| 驱逐 hint（`evictionHint()`，:678） | 散文好但无可复制形态 | 在「ASK THE USER FIRST, then retry with」后内嵌 `browse_headed({url, action:"snapshot"})` 片段；**consent 语序不得后移** | — |
| `stale_root_ref`（interact） | 散文在描述 | P2（无事故不升级） | — |

配套规则：所有 hint ≤2 句 + ≤1 个 call shape 片段；hint 不教 kill/危险操作（既有「只教正门」纪律延续）。

## D. schema field description 补齐清单（L2）

全仓从零 `.describe()` 起步。清单（每字段 ≤2 行）：

1. **单一真源改造（前置）**：把 BrowseChannel.ts 模块级 `ENSURE_NAV_ACTIONS`（:2472）∪ `CURRENT_PAGE_ACTIONS`（:2493）∪ {navigate, click, fill} 导出为 `BROWSE_ACTIONS` 冻结列表（或抽出共享 const 模块），**actionDispatch Map 改由它构建**（零行为变更的微重构）。该列表同时供：(a) schema describe、(b) unknown_action 动态 hint、(c) truth spec 三方消费。**r1 追加**：同批导出 `CONSUMED_OPTIONS`（:2531，现模块私有）——D.5/budget_ms 等 option-scope describe 与闸 4 的派生源（同零行为变更）；**顺手修正 browse.ts:102-103 过时注释**「steps chain 时间预算」→ 双语义（steps 链预算 + 单 action evaluate MCP 超时，BUG-08 A-2 已兑现）——D.5 初稿的事实错误正是从这颗过时注释衍生的（注释级修正，零行为）。
2. `browseSchema.action` + `steps[].action`：`.describe("one of: navigate \| snapshot \| screenshot \| extract \| click \| fill \| wait \| evaluate \| pdf \| console \| network. url-optional (current-page) actions: screenshot \| wait \| evaluate")`——第二句是杀 url_required 猜错环的最高价值一行。
3. `url`：`.describe("omit + screenshot/wait/evaluate = act on current page (needs an active session); present = ensure-navigation (navigates only if different; echoes data.did_navigate)")`。
4. `options.js`：**三形态全收**（house 惯例先行）——函数表达式 `() => document.title` 原样直传（上游自调用）；IIFE `(async () => {...})()` 包成表达式体、**返回其结果**；语句体 `return document.title` 包裹调用（BrowseChannel.ts:2280-2318 `evaluateFunctionArg`；与 L1 descriptions.ts:182-186「THREE forms accepted…All work」同一断言双层锚）。**r1 修正**：初稿「必须为函数表达式/箭头形态，非语句块」与真实行为**相反**——专为零漂移设计的 L2 层会带着事实错误出厂，且原四道闸无一覆盖字段 describe 文本。马拉松 IIFE 试错的预防面靠「house 惯例先行 + 三形态如实」达成，不靠收窄性谎言。
5. `options.freshProfile`（仅 headless；logged_in 传入即拒）、`no_reload`（仅 navigate，hash-only 同文档）、`budget_ms`（**steps 链预算 + 单 action evaluate 的 MCP 超时**：`budget_ms ?? LASSO_EVAL_TIMEOUT_MS ?? 120s`，zod 上限 600s；其余单 action 传入 → `ignored_options` 回显）、`screenshot.filePath`（仅 screenshot 消费，否则 ignored_options 回显）、`selectors`（`{click:"<uid>"}` uid 映射）、`expect`（四条件 text/selector/url_contains/gone + timeout_ms）。**r1 修正（budget_ms）**：初稿「仅 steps 链」与 CONSUMED_OPTIONS.evaluate 直接矛盾（BrowseChannel.ts:2544 含 budget_ms；:2200-2201 doEvaluate 以其为单调用 MCP 超时），且与本决议 E6 示例自相矛盾——照写会让 agent 在长批 evaluate 上停传 budget_ms，恰是马拉松 P0 恢复路径的行为退化。**derive 纪律**：budget_ms/freshProfile/no_reload/screenshot.filePath 四条 describe 的作用域枚举部分由 CONSUMED_OPTIONS / ENTRY_CONSUMED_OPTION_KEYS / NAV_ONLY_OPTION_KEYS 拼（见闸 4），禁手写字符串。
6. screenshot 工具 `url`、admin `options`（browser_recycle 的 channel/reason/freshProfile）。

**不做的**：`action: z.string()` → `z.enum`。理由：会改 MCP 层错误契约（zod invalid_params 取代结构化 `unknown_action` didnt），且森林 interact_act 路径绕过 MCP schema 仍依赖 channel 守卫——两套错误方言；INV-95/bug09 系锚定在现契约上。`.describe()` + 动态 hint 已达成可见性目标，零行为变更。（未来若要 enum，走独立行为变更提案 + 测试纪律。）

## E. 防漂移机制（truth spec 锚）

四道闸，全部沿用仓内已验证的 truth spec 先例（`test/unit/bug09-r2-description-truth.spec.ts` 的 toContain/toMatch/not.toContain 模式 + `tool-descriptions-no-leak.spec.ts` 的三方一致模式）：

1. **`test/unit/tool-examples-truth.spec.ts`（新，与第一批示例同 commit 落地——纪律：description 变更也要有 truth spec 锚）**：
   - **doc→code 正典锚**：读本文件（doc/usage/04）B 节表格，提取每行反引号内示例，断言对应 DESCRIPTION **逐字包含**——删例/改写即红（变异可见性）。doc 是正典、代码是抄本，方向单一。
   - **consent 共现顺序锚**（E8 专用）：`expect(desc).toMatch(/ASK THE USER FIRST[\s\S]{0,120}browse_headed\(\{/)`——示例行与 consent 前提不得分离或倒序。
   - **合法值锚**：正则提取 descriptions 内所有 `action:"X"`，断言 ∈ BROWSE_ACTIONS（示例不得引用不存在的 action）。
   - **call-shape ⊆ schema 锚（r1 新增——E1 类病灶的参数键主通道封死）**：轻量解析 B 表提取 `toolName({...})` 形态的示例（E9 响应形态/E14 字段注记无 `tool({` 起手，自然跳过；E6 为裸片段无工具前缀，同跳过），断言示例**顶层参数名 + options 键（含一层嵌套：steps 项 / screenshot 子对象）⊆ 对应工具 zod schema 键**（经 `.default()` 解包到 ZodObject `.shape`；browse 三兄弟共用 browseSchema，headed 同 schema（headed.ts:74-77），screenshot/admin 独立 schema）。原 E1（`options:{screenshot:{full:true}}` ⊄ screenshot 工具的 `{full_page}`）在此闸下必红——「合法值锚」只封 action 名，**不封参数键**；本闸补上。正典内示例语法受限（字符串/数字/布尔/标识符键），手写递归下降解析器即可，禁引入解析依赖（红线：禁项目外新组件）。
   - **预算帽（r1：先验定值，废除「实施后实测 +5%」——该口径实施前不可机械执行）**：换算常数 3.6 chars/tok 显式化（§0），**char 帽 = token 帽 × 3.6 + 取整余量**，实施前即可写死——每常量上限 = 基线实测 + 增量帽（BROWSE_HEADLESS ≤ 11,623+650 → **12,300 chars**，其余按 §0 基线同法逐常量定值）；fleet Σ19 常量 ≤ 55,236+3,600 → **58,900 chars**；L2 schema describe 合计 ≤ **2,160 chars**。chars 为法定单位、超帽即红。
2. **动态派生即防漂移**：unknown_action hint 从 actionDispatch keys 运行时 join——Map 增删 action，hint 自动同步，无需测试追。truth spec 只需一条单测：构造 unknown action 断言 hint 含全部合法值。
3. **错误路径行为测**：C 表每项升级配 channel 层单测（unknown_action / url_required / no-session 三族断言 hint 含片段）；实施时核对 INV-95/bug09 族既有断言（多为 toContain，additive suffix 兼容；遇 byte-exact 同 commit 更新）。
4. **schema 一致（r1 扩展：action 单点 → 全部 option-scope describe）**：`action`/`steps[].action` 的 `.describe()` 文本由 BROWSE_ACTIONS 拼出（非手写字符串）；`budget_ms`/`js`/`freshProfile`/`no_reload`/`screenshot.filePath`/`selectors`/`expect` 的 `.describe()` 中**枚举作用域的部分由 CONSUMED_OPTIONS / ENTRY_CONSUMED_OPTION_KEYS / NAV_ONLY_OPTION_KEYS 拼出**。至少三条硬断言：(a) budget_ms describe 必含「evaluate」与「steps」双语义词（从 CONSUMED_OPTIONS 派生的 per-action 消费集 + 入口链预算规则拼出——初稿「仅 steps 链」类事实错误在此构造下不可再现）；(b) js describe 必含三形态关键词（function expression / IIFE / statement body）且与 L1 描述同 claim 双层一致（tool-descriptions-no-leak 三方一致模式）；(c) 派生源变异可见——如从 CONSUMED_OPTIONS.evaluate 摘除 budget_ms，describe 文本随之变化，测试必红（真锚非摆设）。
