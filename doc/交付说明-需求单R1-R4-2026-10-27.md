## 二、R1 使用说明（采集主机操作清单）

### 2.1 升级

```bash
# 采集主机（jd-cloud-linux）上，MCP 配置的 lasso 启动命令升级到钉版：
npx -y lasso-mcp@1.32.0
# 验证：lasso doctor 报告 ready:true，且 download_engines / login_bridge 检查在列
```

### 2.2 配置（一次性，~/.lasso/config.json）

```json
{
  "LASSO_LAUNCH_LOCALE": "zh-CN",
  "LASSO_LAUNCH_EXTRA_ARGS": "--window-size=1920,1080"
}
```

要点：
- `LASSO_LAUNCH_EXTRA_ARGS` **用空白符分隔多个参数**（参数自身含逗号如 `window-size=1920,1080` 不受影响——这是刻意设计，与 CLI `--extra-args` 的逗号语义不同）
- 两键**双档生效**（日常档 launch-chrome + 登录档 login_bridge）
- locale 写入的是 lasso 托管 profile 的 `Preferences`（Chrome 155+ 优先级高于一切命令行开关——正是你们三条命令行路径全灭的根因）
- 配错形态（如 `zh_CN` 下划线）会在日志打 `invalid_tag` 后放行，不阻断启动

### 2.3 采集主机的正确回归路径（重要——避开两个坑）

**坑一：不要用 login_bridge 档做采集**。登录档硬编码 `--headless=new`（为远端登录接力设计），会静默报废你们的 Xvfb 真窗口环境信任层，extraArgs 救不回来。登录档只用于初始登录接力。

**正确路径 = 日常档**（同 profile 同端口，Xvfb DISPLAY 下有头运行）：

```bash
lasso launch-chrome --port 9225 \
  --profile ~/.cache/lasso/login-chrome-profile/default \
  --mode visible
```

**坑二：idle 收割**。你们的 Playwright 附着不产生 lasso 的活动信号，>30min 无 lasso 侧调用，Chrome 会被台账自动收割（采集中断）。二选一：
- (a) 采集脚本周期性 `touch ~/.cache/lasso/chrome-touch-9225`（文档化的外部活动信号）；
- (b) 启动加 `--idle-ms 0 --no-hard-cap`（双旗=真·不收割；单 `--idle-ms 0` 仍受 24h 硬顶）。

**冷启语义**：locale 在 Chrome 存活期间不生效（复用路径有 `chrome_locale_prefs_skipped_reused` 日志诚实打点）——**首次启用/验收前先 `lasso chrome-stop --port 9225` 再启动**。

### 2.4 验收（你们自己的脚本即可）

1. `lasso chrome-stop --port 9225`（清旧实例）
2. 按 §2.3 启动
3. 探针：请求侧 `Accept-Language: zh-CN,zh;q=0.9` + 页内 `navigator.language === 'zh-CN'`
4. 重启（chrome-stop → 再启动）后参数保真：分辨率 1920x1080 保持、QUIC 保持开启（两档默认 flags 均不含 QUIC 开关，天然合规）

### 2.5 一次性迁移

你们现 wrapper 直启的登录态资产在 lasso 托管 profile 之外——回归托管需一次性迁移（profile 目录对拷或重新登录）。

## 三、R2/R3/R4 裁定与你们的行动路径

### R2（rebrowser 化）——维持否决，重启条件如下

项目既有裁定（doc/bugs/09 A.6 #2）的重启条件原文：**「若未来出现『CDP patch 后通过 tm 类站点』的可复现 L3 实证（非厂商自述），重开裁决」**。

- 你们需求单里的五份参考（rebrowser 官方/博客、svebaa、DataDome 厂研、「真机+完美住宅 IP 也秒出验证码」）全部是**机制存在性与泄露严重性**证据，不是 **patch 后通过性**实证——条件未满足。
- 注意：三检测页（brotector/rebrowser/sannysoft）全绿是**必要非充分**——重启实证须含 tm 类等价的**服务端评分站**通过。
- **对你们更重要的杠杆事实**：你们的采集栈是 Playwright `connectOverCDP` 直连 9225，不经 lasso 的 browse 通道——**你们栈内的 Runtime.enable 泄露主源在你们自己的 Playwright 里**。rebrowser-patches 同样提供 rebrowser-playwright，可自行评估取舍（你们的栈，你们的决定；lasso 侧不做欺骗原语）。

### R3（humanize 行为）——维持否决

双重既有裁定：doc/bugs/09 A.6 #4（行为模拟/鼠标轨迹伪造：军备竞赛无底洞 + 简单架构否决）+ doc/bugs/11 决议 A.2（键入节奏随机化/人类拟态——伦理红线，「任何人未来提需求也拒绝，除非用户显式推翻本节」）。意图伞论证在档（防窄化重提）。

lasso 的正式答案是 **browse_headed L2 档**（真实有头环境天然带真实行为基线）+ 你们在自己 Playwright 栈内的行为层修复（你们白盒取证的 Top1「输入事件真空」结论本就该在采集脚本侧修）。

### R4（doctor 指纹五项）——暂缓

需求单自标低优/可选；指纹值真源在采集主机（doctor 本就跑在宿主上）。**重启路径**：下批实施时经 tailscale 在采集主机远程验证（CDP 9225 可远程），或由你们跑 `lasso doctor` 回传 JSON 对照。R1 验收已覆盖五项中最关键的 language 双口径。

## 四、本批顺带修复中与你们相关的部分

1. **config.json 全键位 parity 修复**（死键类五次复发根治）：`LASSO_YTDLP_PATH`（yt-dlp 二进制覆盖）、`LASSO_PROXY` 等下载链键、`LASSO_SEARCH_FREE_ONLY`、`LASSO_ALLOW_CLOUD_BROWSER`、`LASSO_VLM_ENDPOINT`、`LASSO_COOKIE_PASSPHRASE` 现在从 config.json 读取真实生效（此前静默无效）。
2. **doctor 提速**：引擎版本探针异步化+缓存——无网络路径从 ~5.2s 降到 ~1.7s（快二进制机更快）。
3. **MCP server 事件循环健康**：请求路径同步子进程冻结点清除（doctor/下载/login_bridge/search_local 全部异步化）——采集中并发调用不再互相卡死。
4. **两条执法 INV**（INV-109/110）上车：sync 子进程冻结名单 + `process.env.LASSO_` 直读白名单，CI 级防回潮。
