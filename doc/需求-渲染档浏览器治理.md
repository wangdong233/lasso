# 需求报告:lasso 渲染档浏览器治理(确定性 headless 档,服务 media-gen-mcp 等消费方)

> 提出方:media-gen-mcp(wangdong233)· 日期:2026-09-01 · 性质:**功能增强需求**(用户已拍板方向:lasso 增强以满足 media-gen-mcp,消费方全量托付浏览器生命周期)
> 背景:P0 事故《media-gen-mcp/doc/2026-09-01-Chrome泄漏致整机冻结-P0根因报告.md》——render 管线自管 puppeteer Chrome(每次 launch+30s 空闲定时器),spawner 被 SIGKILL → 清理随宿主消亡 → 两天 83 孤儿舰队 → 整机 Load 680 冻结。**根因的本质是"浏览器生命周期归属了会死的消费方进程"** —— lasso 的治理面(ledger/idle reaper/stop/mode 过滤)正是解药,但现有档位(visible/hidden 日常档)不满足确定性渲染需求,故提本需求。

## 一、为什么 media-gen-mcp 当初自管(增强必须补齐的缺口)

| 缺口 | 说明 |
|---|---|
| **确定性旗标** | render 承诺"同输入同输出",依赖**启动期旗标**(CDP 无法对已运行 Chrome 补设)。🔴【2026-09-01 勘误】本行原列清单混入了 puppeteer 注入的默认旗标,与消费方真源不符。**真源 = media-gen-mcp `src/browser-pool.ts` 的 `DETERMINISTIC_FLAGS`(HEAD 2311f33 起,P0 根治时已自 render-svg.ts 迁入),逐字同序如下**:`--no-sandbox`、`--disable-gpu`(Mac 上确定性关键)、`--font-render-hinting=full`、`--force-color-profile=srgb`、`--run-all-compositor-stages-before-draw`、`--disable-background-timer-throttling`、`--disable-backgrounding-occluded-windows`、`--disable-renderer-backgrounding`;另须 headless 新模式(命令行 `--headless=new`)。注意消费方经 puppeteer-core launch,实际命令行还含 puppeteer 注入的默认旗标(`--mute-audio`/`--hide-scrollbars`/`--disable-dev-shm-usage`(Linux)等,随 puppeteer 版本变化)——**lasso 要复刻的是"puppeteer 同款有效命令行"而非仅上述 8 条**,精确对照面见《对接实施说明》§一.4 旗标导出法;最终裁决 = 消费方 golden byte-identical(本文 §三.2) |
| **干净环境** | 渲染需空白 profile(临时 user-data-dir),与日常浏览 profile 隔离;日常档带登录态/扩展/历史,会引入不可控变量 |
| **程序化消费接口** | media-gen-mcp 是 node 进程,需要程序化"确保实例在+拿 ws endpoint",而非人工 CLI |

## 二、需求清单

### P0(满足即可迁移)

**R1 渲染档 launch profile**
- `lasso launch-chrome --render`(或独立子命令 `render-chrome`)拉起**渲染档**实例:`--headless=new` + 上述确定性旗标全集 + 空白临时 user-data-dir(固定可识别前缀,如 `~/.cache/lasso/render-chrome-profile-*`)
- **独立端口约定**(建议 9224;【2026-09-01 勘误】launch-chrome 默认端口实为 9222,9223 是 media-gen Flow provider 惯例——9224 与两者均不冲突),ledger 登记 `launchMode: "render"`
- idle 回收:空闲 N 分钟自动 stop(N 可配,默认 10min);chrome-stop 按 mode 过滤时**渲染档与 hidden 同等待遇**(可被收割)

【2026-09-01 补充】R1 落地细节(基于 lasso 现码,避免实现走偏):
- **建议独立子命令 `lasso render-chrome`,不复用 `launch-chrome --render` 路径**:现码 launch-chrome 深度耦合日常档机制(hidden 粘滞账 desired-hide / hide-enforcer 执守进程 / 登录墙状态机 / mac 隐藏保险丝,见 `src/launcher/launch-chrome.ts`)——渲染档一个都不需要,复用会拖进整条日常档链路。最终命名由 lasso 裁决,但**消费方与错误文案的唯一入口是 `render-chrome --ensure`**(见 R3)
- **端口事实核对**:lasso 现用 9222(launch-chrome 默认,doctor #6 对齐)/ 9223(media-gen Flow provider 惯例)→ **9224 空闲,建议成立**
- **touch 文件复用既有跨仓库约定 `~/.cache/lasso/chrome-touch-<port>`**(bug02 契约,`src/launcher/chrome-touch.ts`;idle reaper 每 tick 已 stat 该文件,活动判定三源取 max)——🔴 **不要新造 `render-chrome-*.touch` 之类命名**:既破坏既有外部消费者契约,又需要新收割管道。渲染档 port=9224 → touch 文件即 `~/.cache/lasso/chrome-touch-9224`
- **渲染档 idle 默认 10min,与日常档 CLI 默认(`--idle-ms 0` 不回收)刻意不同**——渲染档是无人值守的确定性资源,默认必须能自动退场;env `LASSO_RENDER_IDLE_MS` 覆盖
- **stop/reap 收割渲染档时必须连带 `rmSync` 该实例 profile 目录**:现 chrome-stop 只杀进程+删台账不删 profile(日常档持久 profile 是设计);渲染档是每实例临时 profile,不删即积垃圾(与 R4 doctor"陈年 profile 清理"互为兜底)
- 「与 hidden 同等待遇」澄清 := idle reaper 可收割 + 无过滤 `chrome-stop --all` 可收;显式 `--modes hidden` 因 `launchMode:"render"` 精确匹配不命中,**不动渲染档**(验收 4)。另注意:**现 chrome-stop CLI 只有 `--port N / --all`,modes 仅是 API 选项**——R1 验收依赖 `--modes <m1,m2>` CLI 旗标,需补(见 §五验收 4)


**R2 生命周期归属高于消费方会话(本事故的根治点)**
- 渲染档 Chrome 的持有者**不得是 CC 会话内的 MCP server 进程**(它随会话被 SIGKILL —— 正是事故机制)
- 建议形态二选一(lasso 侧裁决):
  - a)**launchd LaunchAgent 直管**:lasso 提供 `render-chrome install-agent`(生成 plist+加载,KeepAlive;Chrome 独立于一切会话存活,`stop` 即 unload)
  - b)lasso 常驻 daemon(`lasso render-daemon`,launchd托管):持有浏览器,消费方只 attach
- 无论哪种:**消费方(含其会话宿主)死亡后浏览器照常存活/照常被 idle 回收** —— SIGKILL 免疫是验收硬标准

【2026-09-01 补充】R2 与用户裁决的边界对齐:用户已裁决**废弃 media-gen-mcp 侧 LaunchAgent 过渡方案**(其自管看门狗的"SIGKILL 外置兜底体系"整体废弃,不做阶段移交——时序见《对接实施说明》§二)。本条 R2 的 (a)/(b) 是 **lasso 侧持有者**的选择,不受该裁决影响,仍由 lasso 裁决。仅一条硬约束:无论何种形态,`render-chrome --ensure` 必须是普通 CLI 可直接调用且不依赖 lasso MCP server 存活(消费方与用户文案都以 `--ensure` 为唯一入口;`install-agent` 仅形态 (a) 下存在,**不进消费方错误文案的硬依赖**)。


**R3 程序化 ensure/attach 接口**
- `lasso render-chrome --ensure`(幂等):实例在 → 输出 webSocketDebuggerUrl;不在 → 拉起后输出。stdout 单行 JSON(`{wsEndpoint, port, startedAt}`),供 node spawn 解析
- `lasso render-chrome --status`:自省(存活/空闲时长/累计渲染会话数);`--stop`
- 退出码语义:ensure 成功 0 / 拉起失败非 0(消费方据此降级)

【2026-09-01 补充】R3 精确契约(消费方 `JSON.parse(stdout)` 强依赖,lasso 必须逐条满足):
- **ensure 输出逐字段语义**:`wsEndpoint`(string,`ws://127.0.0.1:<port>/devtools/browser/<uuid>`,取自 `http://127.0.0.1:<port>/json/version`)/ `port`(number)/ `startedAt`(number,epoch ms,与台账 `launchedAt` 同源)/ `reused`(boolean,true=复用既有健康实例)/ **`touchPath`(string,消费方 heartbeat 目标文件绝对路径——由 ensure 下发,消费方不硬编码)**
- **stdout 纯净性**:stdout 只允许这一行 JSON(任何日志/进度/警告走 stderr);消费方必须忽略 stdout JSON 中的未知字段(前向兼容)
- **退出码全集**:`0` 成功;`2` Chrome 二进制不存在;`3` 端口/实例状态不可用(被非渲染档占用,或既有渲染档不健康且自动重生失败);`4` 拉起超时(>20s);`5` 内部错误;**未列举非零 = 未知失败**,消费方按通用失败降级(stderr 原样透传)。台账写失败不改变退出码(best-effort,与现 chrome-ledger 容错一致)
- **`--status` 输出**(恒 exit 0,查询语义):`{"running":bool,"port","pid"?,"wsEndpoint"?,"startedAt"?,"idleMs","lastUseAt"?,"renderSessions","touchPath"}`;**`--stop` 幂等**(不在运行也 exit 0),输出 `{"stopped":[{port,pid,action}]}`,`action ∈ killed|already_dead|pid_reused_skipped`(与现 chrome-stop 结果形状一致)
- **并发单飞**:两个消费方同时 `--ensure` 不得 double-launch(台账"一 port 至多一条"+ 拉起前探活/占位;与消费方现单飞锁语义对齐)
- **`install-agent`/`uninstall-agent`**(仅形态 (a)):幂等;卸载先于升级(plist 版本管理是《对接实施说明》§五.3 未定项)

## 五、验收标准(可直接抄进 lasso 测试)

```
1. lasso render-chrome --ensure → JSON wsEndpoint;Chrome 命令行含 8 旗标指纹 + headless=new
2. 消费方 attach 后渲染同一 SVG 两次 → byte-identical(golden)
3. kill -9 <消费方进程> → 渲染档 Chrome 存活;空闲 N 分钟后被 lasso 回收 ✓ 孤儿数 0
4. chrome-stop --modes hidden 不动渲染档;--modes render 可收
5. render-chrome doctor 在"手工伪造孤儿"场景检出并(确认后)清理;真身 Chrome 零误伤
6. 全程不影响日常档 9223(登录态/visible/hidden 语义零回归)
```

【2026-09-01 补充】验收命令脚本(可直接粘贴;`lasso-mcp` 可按需换成 `npx -y lasso-mcp`;上条 6 中"日常档 9223"按勘误口径含 9222 默认档)

```bash
# 0) 清场:无遗留渲染档(指纹旗标扫描,零误伤日常 Chrome/真身)
npx -y lasso-mcp render-chrome --stop
ps -Axo command= | grep -c "[r]un-all-compositor-stages-before-draw"          # 期望 0

# 1) ensure:exit 0 + stdout 单行 JSON 字段齐 + 命令行含确定性旗标对指纹
npx -y lasso-mcp render-chrome --ensure > /tmp/ensure.out 2>/tmp/ensure.err; echo "exit=$?"
node -e 'const j=JSON.parse(require("fs").readFileSync("/tmp/ensure.out","utf8"));process.exit(j.wsEndpoint&&j.port===9224&&j.touchPath?0:1)'
ps -Axo command= | grep "[r]un-all-compositor-stages-before-draw" | grep -c -- "--font-render-hinting=full"   # ≥1

# 2) 幂等:二次 ensure → reused:true(stdout 单行可解析)
npx -y lasso-mcp render-chrome --ensure | node -e 'let s="";process.stdin.on("data",d=>s+=d).on("end",()=>process.exit(JSON.parse(s).reused===true?0:1))'

# 3) SIGKILL 免疫 + idle 回收(LASSO_RENDER_IDLE_MS=30000 压缩试验窗口):
LASSO_RENDER_IDLE_MS=30000 npx -y lasso-mcp render-chrome --ensure
#   另起一个 attach 消费方(如消费方渲染调用)后:
kill -9 <消费方pid>; sleep 5
ps -Axo command= | grep -c "[r]un-all-compositor-stages-before-draw"          # 期望 1(渲染档存活=SIGKILL 免疫)
sleep 45
ps -Axo command= | grep -c "[r]un-all-compositor-stages-before-draw"          # 期望 0(idle 30s+宽限后回收)
ls ~/.cache/lasso/ | grep -c "render-chrome-profile"                          # 期望 0(profile 随收割删除)

# 4) mode 过滤(需 lasso 补 chrome-stop --modes CLI 旗标,见 R1 补充):
npx -y lasso-mcp render-chrome --ensure
npx -y lasso-mcp chrome-stop --modes hidden && ps -Axo command= | grep -c "[r]un-all-compositor-stages-before-draw"   # 期望 1(未动)
npx -y lasso-mcp chrome-stop --modes render  && ps -Axo command= | grep -c "[r]un-all-compositor-stages-before-draw"   # 期望 0(可收)

# 5) 消费方 golden 硬门槛(在 media-gen-mcp 仓内跑,attach 钉死):
cd <media-gen-mcp 仓库根> && MEDIA_GEN_RENDER_MODE=attach npm test
#   核心断言套件:test/render-video-determinism.test.mjs(mp4 byte-identical)+
#   test/golden.test.ts + scripts/check-render-output.mjs strict(npm test 第 6 段已含)
```
